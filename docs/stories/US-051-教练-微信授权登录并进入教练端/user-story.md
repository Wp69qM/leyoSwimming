## 4. 业务流程

### 4.1 主路径

1. 教练在教练端小程序入口点击「微信一键登录」按钮
2. 小程序调用 `wx.login()` 获取临时登录凭证 `code`
3. 小程序将 `code` 与 `app_type=coach` 提交到后端 `POST /api/v1/auth/wechat-login`
4. 后端调用微信 `code2session` 接口，用 `code` 换取 `openid`、`union_id`、`session_key`
5. 后端按 `union_id` 查询 `user` 表：
   - 命中已有用户 → 复用账号
   - 未命中 → 新建用户记录，`identity_status = 注册用户`，`profile_completed = false`
6. 后端按同一 `union_id` 查询 `coach` 表，获取教练入驻状态
7. 后端签发 JWT `access_token` + `refresh_token`，将 `session_key` 写入 Redis（TTL 7200s）
8. 后端返回登录结果（含 token、`is_new_user` 标志、`profile_completed` 标志、`coach_status` 枚举值、`redirect_page` 建议跳转页）
9. 前端校验隐私协议同意状态：
   - 未同意当前生效版本 → 跳转隐私协议页（US-009）
   - 已同意 → 继续步骤 10
10. 前端按 `redirect_page` 决定跳转：
    - `coach_onboarding` → 跳转「入驻资料页」（US-010）
    - `coach_pending` → 跳转「等待审核页」
    - `coach_rejected` → 跳转「重新提交入驻页」（US-040）
    - `coach_resigned` → 跳转「重新入驻页」（US-040）
    - `coach_resigning` → 跳转「离职处理中页」
    - `coach_home` → 跳转「教练首页」（US-012 起）

### 4.2 异常分支

- **分支 1**：用户拒绝授权 → 提示"需要微信授权才能登录"，停留在登录页
- **分支 2**：微信 `code2session` 接口调用失败 → 提示"微信服务暂时不可用，请稍后重试"
- **分支 3**：`code` 已被使用或已过期（5 分钟内有效） → 提示"登录凭证已失效，请重新点击登录"
> **隐私协议分支**：教练未同意隐私协议 → 跳转隐私协议页（US-009），同意后再按 `redirect_page` 跳转

- **分支 4**：网络超时 → 提示"网络异常，请重试"
- **分支 5**：同一微信账号在用户端已注册但从未申请教练 → 复用 `user` 记录，按无 `coach` 记录处理，跳转入驻资料页（若未同意隐私协议则先跳转隐私协议页）

## 8. 边界场景

### 8.1 边界场景 1：登录态有效期内切换回教练端

- **触发条件**：教练之前在教练端登录过，token 未过期，重新打开小程序
- **预期行为**：前端检测本地 token 有效，直接调用 `/api/v1/coach/me/status` 获取状态并跳转对应页面
- **用户可见反馈**：无感进入对应页面（首页 / 等待审核 / 入驻资料等）

### 8.2 边界场景 2：微信 `union_id` 已绑定其他已注销账号

- **触发条件**：教练的 `union_id` 对应 user 记录 status = 1（软删除）
- **预期行为**：按业务规则 [§5.2.1 第 4 条](../../prd/prd.md) 处理：重新注册生成新账号，不绑定原账号数据；新用户 `identity_status='注册用户'`，按无 coach 记录处理
- **用户可见反馈**：跳转入驻资料页

### 8.3 边界场景 3：教练快速重复点击登录按钮

- **触发条件**：教练快速点击两次「微信一键登录」
- **预期行为**：前端按钮点击后立即 disable + loading；后端以 `code` 为幂等键，相同 code 5 分钟内重复提交只返回首次结果
- **用户可见反馈**：正常跳转，不创建重复记录

### 8.4 边界场景 4：教练端与用户端使用不同微信小程序

- **触发条件**：教练端和用户端分别绑定两个小程序 AppID，但共享同一微信开放平台账号
- **预期行为**：后端通过 `union_id` 关联同一自然人，复用 `user` 记录
- **用户可见反馈**：教练端登录后可直接看到用户端同一微信账号下的基础信息

### 8.5 边界场景 5：教练处于离职中状态（status = 4）

- **触发条件**：教练已提交离职申请，coach.status = 4（离职中）
- **预期行为**：登录成功，但 `redirect_page = coach_resigning`，前端跳转"离职处理中页"，不可进行排班、预约等操作
- **用户可见反馈**：页面提示"离职流程处理中，部分功能受限"

## 12. 备注

- **幂等键**：以微信 `code` 作为幂等键（5 分钟内有效，且只能使用一次），重复提交返回首次结果
- **事务边界**：查询用户 + 创建用户 + 签发 token + 写 session 必须在同一事务内，任一失败全部回滚
- **性能要求**：登录接口 P99 < 1500ms（含微信 code2session 调用时间）
> **隐私协议**：教练端首次登录成功后，进入目标页面前必须先完成 US-009 隐私协议授权；未同意则跳转隐私协议页，同意后再按 `redirect_page` 跳转。用户端已同意的隐私协议版本对教练端同样有效。

- **安全要求**：
  - `session_key` 不可返回给前端
  - `access_token` JWT 有效期 2h，`refresh_token` 有效期 7d
  - `app_type` 字段需校验，仅允许 `user` 或 `coach`
- **设计相关**：见 §13-15 Figma 相关章节
- **技术相关**：见 [./tech-design.md](./tech-design.md)
- **测试相关**：见 [./test-plan.md](./test-plan.md)

## 14. 页面级设计决策

### 14.1 教练端登录页样式与位置

- **背景**：教练端登录页是教练进入小程序的第一个交互点，需要明确的视觉引导
- **选项**：
  - A. 顶部居中大按钮
  - B. 底部固定按钮（fixed bottom）
  - C. 全屏授权引导卡片 + 底部按钮
- **结论**：选 B（底部固定按钮），与用户端登录页保持一致，按钮样式使用微信品牌绿（#07C160），高度 48px，全宽
- **影响范围**：教练端微信授权登录页

### 14.2 登录后的状态分流策略

- **背景**：教练登录后可能处于多种入驻状态，需要自动跳转到正确页面
- **选项**：
  - A. 登录成功后统一跳到教练首页，首页再根据 coach_status 二次弹窗/跳转
  - B. 登录接口直接返回 `redirect_page`，前端一次跳转到目标页
- **结论**：选 B，减少中间态和二次请求，体验更直接
- **影响范围**：登录接口响应字段 + 前端路由逻辑

### 14.3 用户端与教练端账号互通策略

- **背景**：同一自然人可能既是学员又是教练，需要明确账号关系
- **选项**：
  - A. 教练端和用户端完全独立账号体系
  - B. 共用 `user` 基础账号，教练资质放在独立 `coach` 表
- **结论**：选 B，与 PRD §3.1 一致：教练是独立角色，不与用户身份重叠；`user` 表记录基础身份，`coach` 表记录教练资质状态
- **影响范围**：登录接口查询逻辑、数据模型

### 14.4 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 点击「微信一键登录」按钮 | tap | 按钮 loading + 调用 wx.login() | 防重复点击：点击后立即 disable |
| wx.login 成功 | 微信回调 | 提交 code + app_type=coach 到后端 | — |
| wx.login 失败/拒绝 | 微信回调 | 展示错误文案 + 恢复按钮可点击 | 文案见 §6.4 |
| 后端返回成功 | HTTP 200 | 按 redirect_page 跳转 | 见 §14.2 |
| 后端返回错误 | HTTP 4xx/5xx | 展示对应错误文案 + 恢复按钮 | 文案见 US-004 §6.4-6.5 |
| 点击「重新授权」按钮 | tap | 调用 wx.openSetting() | 见 US-004 §14.2 |

## 4. 业务流程

### 4.1 主路径

1. 用户在小程序入口点击「微信一键登录」按钮
2. 小程序调用 `wx.login()` 获取临时登录凭证 `code`
3. 小程序将 `code` 提交到后端 `POST /api/v1/auth/wechat-login`
4. 后端调用微信 `code2session` 接口，用 `code` 换取 `openid`、`union_id`、`session_key`
5. 后端按 `union_id` 查询 `user` 表：
   - 命中已有用户 → 复用账号
   - 未命中 → 新建用户记录，`identity_status = 注册用户`，`profile_completed = false`
6. 后端签发 JWT `access_token` + `refresh_token`，将 `session_key` 写入 Redis（TTL 7200s）
7. 返回登录结果（含 token、`is_new_user` 标志、`profile_completed` 标志）
8. 前端按 `profile_completed` 决定跳转：
   - `false` → 跳转「补充资料页」（US-005）
   - `true` → 跳转小程序首页

### 4.2 异常分支

- **分支 1**：用户拒绝授权 → 提示"需要微信授权才能登录"，停留在登录页
- **分支 2**：微信 `code2session` 接口调用失败 → 提示"微信服务暂时不可用，请稍后重试"
- **分支 3**：`code` 已被使用或已过期（5 分钟内有效） → 提示"登录凭证已失效，请重新点击登录"
- **分支 4**：网络超时 → 提示"网络异常，请重试"

## 6. 验收标准（业务级 Gherkin）

> 业务级 Gherkin：聚焦"用户能观察到的结果"，不绑死实现细节。
> 字段级断言、API 设计、状态机影响 → 见配套**技术设计文档**。
> TDD 任务清单、扩展测试用例 → 见配套**测试计划**。
>
> US 等级：L2（1 人天，含 1 个状态转换）

### 6.1 场景 1：首次微信授权登录成功，跳转补充资料页（正常路径）

```gherkin
Given 用户首次使用微信授权登录，user 表中不存在其 union_id
When  用户点击"微信一键登录"按钮并同意授权
Then  系统创建新用户记录，identity_status = "注册用户"
And   profile_completed = false
And   返回 access_token 和 refresh_token
And   前端跳转到"补充资料"页（US-005）
And   user.union_id 等于微信返回的 union_id
And   user.identity_status 由 "游客" 转换为 "注册用户"
```

### 6.2 场景 2：已注册用户微信授权登录成功，跳转首页（正常路径）

```gherkin
Given 用户已注册且 profile_completed = true，user 表中存在其 union_id
When  用户点击"微信一键登录"按钮并同意授权
Then  系统复用已有用户记录，不新建账号
And   返回 access_token 和 refresh_token
And   is_new_user = false
And   前端跳转到小程序首页
And   user.identity_status 保持为 "注册用户"（或更高：学员）
```

### 6.3 场景 3：用户拒绝授权（异常路径）

```gherkin
Given 用户在微信授权弹窗中点击"拒绝"
When  系统尝试调用 wx.login() 或获取用户信息
Then  登录流程终止
And   停留在登录页并展示文案"需要微信授权才能登录"
And   不创建任何用户记录
And   不签发 token
```

### 6.4 场景 4：微信接口调用失败（异常路径）

```gherkin
Given 后端调用微信 code2session 接口时返回错误码或超时
When  后端处理登录请求
Then  返回 HTTP 502 + 错误码 "WECHAT_API_ERROR"
And   前端展示文案"微信服务暂时不可用，请稍后重试"
And   不创建任何用户记录
And   不签发 token
```

### 6.5 场景 5：登录凭证已失效（异常路径）

```gherkin
Given 用户提交的 code 已被使用或已超过 5 分钟有效期
When  后端调用 code2session 接口
Then  微信返回 errcode = 40029（invalid code）
And   后端返回 HTTP 401 + 错误码 "WECHAT_CODE_INVALID"
And   前端展示文案"登录凭证已失效，请重新点击登录"
And   不创建任何用户记录
```

## 7. 数据/API/状态机影响

> 本节为摘要级概述，完整技术设计见 [./tech-design.md](./tech-design.md)。

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `user` | 新增 | 首次登录时插入新记录：`openid`、`union_id`、`identity_status='注册用户'`、`profile_completed=false`、`status=0`（TINYINT，0=正常/1=软删除/2=封禁，与 PRD §9.2.1 一致） |
| 2 | `user_session` | 新增 | 写入会话记录：`user_id`、`session_key`（加密）、`expires_at`、`refresh_token_hash` |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/v1/auth/wechat-login` | POST | 新增 | 接收微信 `code`，调用 `code2session`，查询/创建用户，签发 JWT |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `user.identity_status` | 游客 → 注册用户 | 首次微信授权登录成功且新建用户记录 | **本 US 触发的核心状态转换**；后续 注册用户→学员 由 US-020 触发 |
| 2 | `user.profile_completed` | false → true | 用户在 US-005 中补充资料完成 | 本 US 仅置为 `false`，转换由 US-005 完成 |

## 8. 边界场景

| # | 场景 | 处理方式 |
|---|------|---------|
| 1 | 微信 `union_id` 已绑定其他已注销账号（软删除账号） | 按业务规则 [§5.2.1 第 4 条](../../prd/prd.md) 处理：重新注册生成新账号，不绑定原账号数据；新用户 `identity_status='注册用户'`，与原账号数据完全隔离 |
| 2 | 网络超时（code2session 调用 > 3s） | 后端设置 3s 超时，超时返回 HTTP 504 + `WECHAT_API_TIMEOUT`；前端提示"网络异常，请重试" |
| 3 | 微信 `session_key` 过期（TTL 7200s 到期） | 后续需要 `session_key` 解密手机号等数据时若已过期，前端重新调用 `wx.login()` 获取新 code 并走刷新流程 |
| 4 | 用户快速重复点击登录按钮 | 前端按钮点击后立即 disable + loading；后端以 `code` 为幂等键，相同 code 5 分钟内重复提交只返回首次结果 |
| 5 | 同一 `openid` 但 `union_id` 缺失（用户未绑定微信开放平台） | 以 `openid` 作为兜底唯一键，记录告警日志；不阻断登录流程 |
| 6 | JWT `access_token` 过期 | 前端用 `refresh_token` 调用刷新接口换发新 `access_token`，对用户无感 |

## 12. 备注

- **幂等键**：以微信 `code` 作为幂等键（5 分钟内有效，且只能使用一次），重复提交返回首次结果
- **事务边界**：查询用户 + 创建用户 + 签发 token + 写 session 必须在同一事务内，任一失败全部回滚
- **性能要求**：登录接口 P99 < 1500ms（含微信 code2session 调用时间）
- **安全要求**：
  - `session_key` 不可返回给前端
  - `access_token` JWT 有效期 2h，`refresh_token` 有效期 7d
  - 密码相关字段（即使本 US 不创建）未来需使用 bcrypt 存储
- **设计相关**：见 §13-15 Figma 相关章节
- **技术相关**：见 [./tech-design.md](./tech-design.md)
- **测试相关**：见 [./test-plan.md](./test-plan.md)

## 14. 页面级设计决策

> 本节是**本故事特殊**的设计选择，**全局规范**中没有定义的设计决策记录在这里。

### 14.1 登录按钮样式与位置

- **背景**：登录页是用户进入小程序的第一个交互点，需要明确的视觉引导
- **选项**：
  - A. 顶部居中大按钮
  - B. 底部固定按钮（fixed bottom）
  - C. 全屏授权引导卡片 + 底部按钮
- **结论**：选 B（底部固定按钮），符合微信小程序常见登录页习惯，按钮样式使用微信品牌绿（#07C160），高度 48px，全宽
- **影响范围**：微信授权登录页

### 14.2 拒绝授权后的二次引导

- **背景**：用户首次拒绝授权后，再次调用 `wx.login` 不会弹窗，需要引导用户主动开启权限
- **选项**：
  - A. 直接展示错误文案，要求用户重启小程序
  - B. 展示「重新授权」按钮 + 引导文案「点击右上角...→设置→开启权限」
- **结论**：选 B，提供二次引导按钮，点击后调用 `wx.openSetting()` 引导用户开启权限
- **影响范围**：微信授权登录页错误态

### 14.3 新用户 vs 老用户的跳转差异

- **背景**：首次登录用户需要补充资料（US-005），老用户应直接进入首页
- **结论**：后端返回 `is_new_user` 和 `profile_completed` 两个标志，前端按以下逻辑跳转：
  - `is_new_user=true` 或 `profile_completed=false` → 跳「补充资料页」
  - `profile_completed=true` → 跳「小程序首页」
- **影响范围**：登录成功后的路由逻辑

### 14.4 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 点击「微信一键登录」按钮 | tap | 按钮 loading + 调用 wx.login() | 防重复点击：点击后立即 disable |
| wx.login 成功 | 微信回调 | 提交 code 到后端，按钮保持 loading | — |
| wx.login 失败/拒绝 | 微信回调 | 展示错误文案 + 恢复按钮可点击 | 文案见 §6.3 |
| 后端返回成功 | HTTP 200 | 按 is_new_user 跳转 | 见 §14.3 |
| 后端返回错误 | HTTP 4xx/5xx | 展示对应错误文案 + 恢复按钮 | 文案见 §6.4-6.5 |
| 点击「重新授权」按钮 | tap | 调用 wx.openSetting() | 见 §14.2 |

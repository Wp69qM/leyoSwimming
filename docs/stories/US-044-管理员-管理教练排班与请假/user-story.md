## 2. 触发条件

- **触发方**：管理员
- **触发动作**：在管理后台「排班管理」查看/修改排班，或在「请假审批」处理教练请假申请

## 3. 前置条件

- [x] 管理员已登录且具有 `MANAGE_SCHEDULE` 权限
- [x] 目标教练已入驻并通过审核（`coach.status = 1`）
- [x] 请假申请已由教练提交且状态为 pending（依赖 US-036）

---

## 4. 业务流程

### 4.1 主路径（查看与修改排班）

1. 管理员进入「排班管理」
2. 系统展示所有教练的排班表，默认本周
3. 管理员选择教练与日期范围
4. 管理员点击某个时段进行编辑：修改时间、删除、新增
5. 系统校验时间冲突
6. 系统保存排班变更
7. 返回成功提示

### 4.2 主路径（审批请假）

1. 管理员进入「请假审批」队列
2. 系统列出 pending 状态的请假申请
3. 管理员查看请假原因、请假时间、教练、受影响课程及系统推荐的改约时段
4. 管理员确认或补充改约建议后点击「通过」
5. 系统将 leave_request.status 更新为 approved
6. 系统将请假日期内未来已释放的 schedule_slot 标记为 disabled（不物理删除，便于复用）
7. 系统自动取消请假时段内已预约的课程并释放课时
8. 系统向相关学员发送课程取消通知，通知中包含教练请假原因与改约建议
9. 返回审批成功提示

### 4.3 异常分支

- **分支 1**：管理员无权限 → 返回 `ADMIN_PERMISSION_DENIED`
- **分支 2**：请假申请非 pending 状态 → 返回 `LEAVE_ALREADY_PROCESSED`
- **分支 3**：修改排班时间冲突 → 返回 `SCHEDULE_TIME_CONFLICT`

## 6. 验收标准（业务级 Gherkin）

> 本 US 为 L2（1.5 人天），包含 2 个正常场景 + 3 个异常场景 = 5 个场景。

### 6.1 场景 1：管理员通过教练请假申请

```gherkin
Given 管理员 M 已登录且具有排班管理权限
And   教练 C 提交了 2026-08-01 全天的请假申请，状态为 pending，请假原因="身体不适"
And   该时段内有 2 个已预约的 booking
And   系统推荐改约时段为 2026-08-03 09:00-10:00
When  管理员 M 点击「通过」
Then  leave_request.status 更新为 approved
And   2026-08-01 教练 C 的 schedule_slot 被标记为 disabled（不物理删除，便于复用）
And   2 个 booking 状态更新为「已取消」，cancel_reason = 5（教练请假）
And   对应 package 的 reserved_count 减少，available_count 增加
And   系统向学员发送课程取消通知，内容包含请假原因"身体不适"与改约建议"2026-08-03 09:00-10:00"
And   返回 HTTP 200 与提示"请假已通过"
```

### 6.2 场景 2：管理员修改教练排班

```gherkin
Given 管理员 M 已登录且具有排班管理权限
And   教练 C 在 2026-08-02 09:00-10:00 有一个可约时段
And   该时段无预约
When  管理员 M 将其修改为 2026-08-02 10:00-11:00
Then  schedule_slot 记录更新时间成功
And   无时间冲突
And   返回 HTTP 200 与提示"排班已更新"
```

### 6.3 场景 3：管理员拒绝教练请假申请

```gherkin
Given 管理员 M 已登录且具有排班管理权限
And   教练 C 的请假申请状态为 pending
When  管理员 M 点击「拒绝」并填写原因="场馆活动需要"
Then  leave_request.status 更新为 rejected
And   教练 C 的原有排班保持不变
And   已预约课程不受影响
And   返回 HTTP 200 与提示"请假已拒绝"
```

### 6.4 场景 4：请假申请已处理时不可重复审批

```gherkin
Given 管理员 M 已登录且具有排班管理权限
And   教练 C 的请假申请状态为 approved
When  管理员 M 再次调用通过接口
Then  返回错误码 LEAVE_ALREADY_PROCESSED
And   HTTP 状态码 409
And   leave_request 状态保持 approved 不变
```

### 6.5 场景 5：修改排班时间冲突

```gherkin
Given 管理员 M 已登录且具有排班管理权限
And   教练 C 在 2026-08-02 09:00-10:00 和 10:30-11:30 各有一个可约时段
When  管理员 M 将第一个时段修改为 10:00-11:00
Then  返回错误码 SCHEDULE_TIME_CONFLICT
And   HTTP 状态码 409
And   schedule_slot 不发生变更
```

## 8. 边界场景

### 8.1 边界场景 1：删除已有预约的排班时段

- **触发条件**：管理员删除一个已有 booking 的 schedule_slot
- **预期行为**：系统提示「该时段已有预约，删除将取消课程并通知学员」，管理员确认后继续
- **用户可见反馈**：课程取消，学员收到通知

### 8.2 边界场景 2：跨天批量添加排班

- **触发条件**：管理员一次性为教练添加未来 30 天排班
- **预期行为**：系统校验所有时段无冲突后批量插入
- **用户可见反馈**：排班表一次性更新，冲突项高亮提示

### 8.3 边界场景 3：请假时段与已上课课程重叠

- **触发条件**：请假开始时间早于当前时间，部分课程已完成
- **预期行为**：仅取消未上课（状态为已预约/待上课）的 booking，已完成课程不受影响
- **用户可见反馈**：审批结果提示「已跳过 X 节已完成课程」

## 12. 备注

- **幂等键**：请假审批使用 `leave:{leave_id}:version:{updated_at}` 乐观锁
- **事务边界**：请假通过时，leave_request + booking + package 更新在同一事务

## 14. 页面级设计决策

### 14.1 排班展示形式

- **背景**：需要同时查看多个教练、多天的排班
- **选项**：A. 列表；B. 周视图日历
- **结论**：选择 B（周视图），更接近教练端习惯
- **影响范围**：排班管理页

### 14.2 请假审批与课程取消联动

- **背景**：请假通过后需要自动取消课程
- **选项**：A. 同步等待取消完成；B. 异步任务
- **结论**：选择 A（MVP），package/booking 数量可控
- **影响范围**：请假审批接口

### 14.3 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |

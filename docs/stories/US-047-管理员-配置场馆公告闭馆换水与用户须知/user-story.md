## 4. 业务流程

### 4.1 主路径（配置场馆信息）

1. 管理员进入「场馆运营」模块，选择「场馆信息」Tab
2. 系统展示当前场馆信息（名称、地址、导航、开业年限、泳池状态等）
3. 管理员编辑场馆信息字段并提交
4. 系统校验字段合法性后更新 `venue` 表
5. 返回保存成功提示，前端展示更新后场馆信息

### 4.2 主路径（发布公告）

1. 管理员切换至「公告」Tab
2. 系统展示公告列表与发布表单
3. 管理员填写公告标题、内容、展示目标身份、有效期并提交
4. 系统校验后向 `notice` 表新增一条 `status='published'` 的记录
5. 系统按目标身份（全部/学员/游客等）即时推送或展示公告
6. 返回发布成功提示

### 4.3 主路径（设置闭馆/换水）

1. 管理员切换至「闭馆换水」Tab
2. 系统展示闭馆日历与已设置闭馆日期
3. 管理员选择日期、填写原因（换水/场馆活动/其他）并提交
4. 系统校验该日期是否已存在闭馆记录
5. 系统写入 `venue_closure` 记录，并异步检测该日期内未上课的 booking
6. 系统自动取消受影响 booking（cancel_reason=4 场馆闭馆），释放 package.reserved → available
7. 系统向受影响学员与教练发送闭馆通知
8. 返回 HTTP 202 Accepted 与异步任务 task_id

### 4.4 主路径（更新《用户须知》）

1. 管理员切换至「用户须知」Tab
2. 系统展示当前生效版本与历史版本列表
3. 管理员编辑新版《用户须知》内容并提交
4. 系统校验内容非空后，将新版本写入 `terms_of_service` 表并置 `is_active=true`
5. 系统将旧版本 `is_active` 置为 false
6. 系统将所有已签署旧版本的用户 `user_terms_sign.status` 更新为「待重新签署」
7. 系统向所有注册用户推送用户须知更新提醒
8. 返回发布成功提示

### 4.5 异常分支

- **分支 1**：闭馆日期冲突 → 返回 `CLOSURE_DATE_CONFLICT`
- **分支 2**：《用户须知》内容为空 → 返回 `TERMS_CONTENT_EMPTY`
- **分支 3**：管理员无权限 → 返回 HTTP 403

## 6. 验收标准（业务级 Gherkin）

> 本 US 为 L2（1.5 人天），场景数 = 4 正常 + 2 异常 = 6。

### 6.1 场景 1：管理员更新场馆信息

```gherkin
Given 管理员已登录且具有场馆运营权限
And   当前场馆名称为"乐游健身中心"
When  管理员提交场馆信息：名称="乐游游泳馆", 地址="XX路XX号", 泳池状态="开放"
Then  系统返回 HTTP 200
And   venue 表 name 更新为"乐游游泳馆"
And   游客端/学员端场馆展示页同步显示最新场馆信息
```

### 6.2 场景 2：管理员发布公告

```gherkin
Given 管理员已登录且具有场馆运营权限
When  管理员发布公告：标题="暑期课程安排", 内容="7月起增加晚间时段", 展示身份="全部"
Then  系统返回 HTTP 200
And   notice 表新增 1 条记录，title="暑期课程安排"，status='published'
And   游客端/学员端首页通知栏展示"暑期课程安排"
```

### 6.3 场景 3：管理员设置闭馆并异步取消受影响预约

```gherkin
Given 场馆正常开放
And   存在 2026-08-01 09:00 的已预约课程 5 节
When  管理员设置 2026-08-01 全天闭馆（原因：换水）
Then  系统返回 HTTP 202 Accepted
And   响应体含 { task_id, affected_bookings: 5, status: "processing" }
And   closure 表新增记录
And   系统异步执行取消任务（与 §12 性能要求一致）
When  异步任务完成（数秒内）
Then  5 节预约状态变更为"已取消"，cancel_reason=4（场馆闭馆）
And   释放 package.reserved → available
And   向学员与教练发送闭馆通知
And   管理员后台可查询 task_id 的最终状态为 "completed"
```

### 6.4 场景 4：管理员更新《用户须知》并触发重新签署

```gherkin
Given 当前《用户须知》版本为 v1.0
And   学员 U-001 已签署 v1.0
When  管理员发布 v2.0《用户须知》
Then  系统返回 HTTP 200
And   terms 表新增 v2.0 记录，is_active=true，v1.0 is_active=false
And   学员 U-001 的签署状态变为"待重新签署"
And   系统向所有注册用户推送更新提醒
```

### 6.5 场景 5：闭馆日期冲突

```gherkin
Given 已存在 2026-08-01 的闭馆记录
When  管理员再次设置 2026-08-01 闭馆
Then  系统返回 HTTP 409
And   返回错误码 CLOSURE_DATE_CONFLICT
And   不新增重复闭馆记录
```

### 6.6 场景 6：《用户须知》内容为空

```gherkin
Given 管理员已登录
When  管理员提交空内容的《用户须知》
Then  系统返回 HTTP 400
And   返回错误码 TERMS_CONTENT_EMPTY
And   不创建新版本
```

## 8. 边界场景

### 8.1 边界场景 1：闭馆日期包含已上课记录

- **触发条件**：管理员设置的闭馆日期包含已完成课程
- **预期行为**：仅取消未上课预约，已完成课程不受影响
- **用户可见反馈**：后台提示"已跳过已完成课程"

### 8.2 边界场景 2：公告超过有效期

- **触发条件**：公告到达下线时间
- **预期行为**：系统自动将 notice.status 更新为 offline
- **用户可见反馈**：前端不再展示

### 8.3 边界场景 3：用户签署记录导出

- **触发条件**：管理员需要导出某版本《用户须知》签署记录
- **预期行为**：系统支持按版本号导出 CSV
- **用户可见反馈**：下载 CSV 文件

## 4. 业务流程

### 4.1 主路径

1. 管理员进入「场馆运营」模块
2. 选择子功能：场馆信息 / 公告 / 闭馆换水 / 用户须知
3. 管理员编辑并提交
4. 系统校验并保存
5. 若涉及闭馆/换水或用户须知更新，系统触发后续通知/签署流程

### 4.2 异常分支

- **分支 1**：闭馆日期冲突 → 返回 `CLOSURE_DATE_CONFLICT`
- **分支 2**：《用户须知》内容为空 → 返回 `TERMS_CONTENT_EMPTY`
- **分支 3**：管理员无权限 → 返回 HTTP 403

## 6. 验收标准（业务级 Gherkin）

> 本 US 为 L2（1.5 人天），场景数 = 2 正常 + 3 异常 = 5。

### 6.1 场景 1：管理员配置场馆信息并发布公告

```gherkin
Given 管理员已登录且具有场馆运营权限
When  管理员更新场馆信息：名称="乐游游泳馆", 地址="XX路XX号", 泳池状态="开放"
And   管理员发布公告：标题="暑期课程安排", 内容="7月起增加晚间时段", 展示身份="全部"
Then  系统返回 HTTP 200
And   venue 表更新为名称="乐游游泳馆"
And   notice 表新增 1 条记录，status='published'
And   游客端/学员端首页通知栏展示"暑期课程安排"
```

### 6.2 场景 2：管理员设置闭馆并自动取消受影响预约

```gherkin
Given 场馆正常开放
And   存在 2026-08-01 09:00 的已预约课程 5 节
When  管理员设置 2026-08-01 全天闭馆（原因：换水）
Then  系统返回 HTTP 200
And   closure 表新增记录
And   5 节预约状态变更为"已取消"，cancel_reason='venue_closure'
And   释放 package.reserved → available
And   向学员与教练发送闭馆通知
```

### 6.3 场景 3：管理员更新《用户须知》并触发重新签署

```gherkin
Given 当前《用户须知》版本为 v1.0
And   学员 U-001 已签署 v1.0
When  管理员发布 v2.0《用户须知》
Then  系统返回 HTTP 200
And   terms 表新增 v2.0 记录，is_active=true，v1.0 is_active=false
And   学员 U-001 的签署状态变为"待重新签署"
And   系统向所有注册用户推送更新提醒
```

### 6.4 场景 4：闭馆日期冲突

```gherkin
Given 已存在 2026-08-01 的闭馆记录
When  管理员再次设置 2026-08-01 闭馆
Then  系统返回 HTTP 409
And   返回错误码 CLOSURE_DATE_CONFLICT
And   不新增重复闭馆记录
```

### 6.5 场景 5：《用户须知》内容为空

```gherkin
Given 管理员已登录
When  管理员提交空内容的《用户须知》
Then  系统返回 HTTP 400
And   返回错误码 TERMS_CONTENT_EMPTY
And   不创建新版本
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `venue` | 新增/修改 | 场馆信息 |
| 2 | `notice` | 新增/修改 | 公告 |
| 3 | `venue_closure` | 新增 | 闭馆/换水记录 |
| 4 | `terms_of_service` | 新增/修改 | 《用户须知》版本 |
| 5 | `user_terms_sign` | 新增/修改 | 用户签署记录 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/admin/venue` | GET/PUT | 新增/修改 | 场馆信息 |
| 2 | `/api/admin/notices` | GET/POST/PUT | 新增 | 公告管理 |
| 3 | `/api/admin/venue-closures` | GET/POST | 新增 | 闭馆换水设置 |
| 4 | `/api/admin/terms` | GET/POST | 新增 | 用户须知版本管理 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|

| 3 | `user_terms_sign.status` | 已签署 → 待重新签署 | 用户须知版本更新 | — |

## 8. 边界场景

### 8.1 边界场景 1：闭馆日期包含已上课记录

- **触发条件**：管理员设置的闭馆日期包含已完成课程
- **预期行为**：仅取消未上课预约，已完成课程不受影响
- **用户可见反馈**：后台提示"已跳过已完成课程"

### 8.2 边界场景 2：公告超过有效期

- **触发条件**：公告到达下线时间
- **预期行为**：系统自动将 notice.status 更新为 offline
- **用户可见反馈**：前端不再展示

### 8.3 边界场景 3：用户签署记录导出

- **触发条件**：管理员需要导出某版本《用户须知》签署记录
- **预期行为**：系统支持按版本号导出 CSV
- **用户可见反馈**：下载 CSV 文件

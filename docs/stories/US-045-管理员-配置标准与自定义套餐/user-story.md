## 4. 业务流程

### 4.1 主路径

1. 管理员进入「套餐配置」页面
2. 系统展示标准套餐列表（含状态：上架/下架）
3. 管理员点击「新增标准套餐」
4. 系统弹出表单：名称、适用教练、课时数、有效期（天）、售价、上下架状态
5. 管理员填写并提交
6. 系统校验字段合法后写入 `package_template` 表，`status='active'`
7. 返回列表并刷新

### 4.2 异常分支

- **分支 1**：课时数 ≤ 0 或售价 < 0 → 前端/后端返回 `INVALID_PACKAGE_PARAM`
- **分支 2**：套餐名称重复 → 返回 `DUPLICATE_PACKAGE_NAME`
- **分支 3**：管理员无权限 → 返回 HTTP 403

## 6. 验收标准（业务级 Gherkin）

> 本 US 为 L2（1 人天），场景数 = 2 正常 + 3 异常 = 5。

### 6.1 场景 1：管理员新增标准套餐成功

```gherkin
Given 管理员已登录且具有套餐配置权限
And   系统中不存在名称为"暑期 10 节课"的标准套餐
When  管理员提交标准套餐：名称="暑期 10 节课", 课时数=10, 有效期=180 天, 售价=3000.00, 状态=上架
Then  系统返回 HTTP 200 且 package_template 表新增 1 条记录
And   该记录 status='active'，total_hours=10，price=3000.00
And   前端列表展示"暑期 10 节课"且状态为"上架"
```

### 6.2 场景 2：管理员编辑标准套餐并下架

```gherkin
Given 系统中已存在标准套餐 A，status='active'，price=2000.00
When  管理员将套餐 A 价格改为 1800.00 并设置为下架
Then  系统返回 HTTP 200
And   package_template.price 更新为 1800.00
And   package_template.status 更新为 'inactive'
And   游客端/学员端不再展示该套餐
```

### 6.3 场景 3：新增标准套餐时名称重复

```gherkin
Given 系统中已存在名称为"暑期 10 节课"的标准套餐
When  管理员再次提交名称为"暑期 10 节课"的标准套餐
Then  系统返回错误码 DUPLICATE_PACKAGE_NAME
And   HTTP 状态码 409
And   package_template 表不新增记录
```

### 6.4 场景 4：新增标准套餐参数非法

```gherkin
Given 管理员已登录
When  管理员提交标准套餐：课时数=0，售价=-100
Then  系统返回错误码 INVALID_PACKAGE_PARAM
And   HTTP 状态码 400
And   提示"课时数必须大于 0，售价不能为负数"
```

### 6.5 场景 5：无权限管理员访问配置接口

```gherkin
Given 管理员已登录但角色无"套餐配置"权限
When  管理员调用 POST /api/admin/package-templates
Then  系统返回 HTTP 403
And   返回错误码 FORBIDDEN
And   package_template 表不新增记录
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `package_template` | 新增/修改 | 标准套餐模板表，字段：id, name, coach_id, total_hours, valid_days, price, status, created_at, updated_at |
| 2 | `package_template` | 读取 | 列表查询、详情查询 |
| 3 | `coach` | 读取 | 关联教练与参考单价 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/admin/package-templates` | GET | 新增 | 管理员获取标准套餐列表 |
| 2 | `/api/admin/package-templates` | POST | 新增 | 管理员新增标准套餐 |
| 3 | `/api/admin/package-templates/:id` | PUT | 新增 | 管理员编辑标准套餐 |
| 4 | `/api/admin/package-templates/:id/toggle-status` | POST | 新增 | 上下架切换 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `package_template.status` | active ↔ inactive | 管理员上下架操作 | 仅影响新购，不影响已购 package |

## 8. 边界场景

### 8.1 边界场景 1：管理员并发编辑同一套餐

- **触发条件**：两名管理员同时编辑同一标准套餐
- **预期行为**：后提交者收到乐观锁冲突提示，需刷新后重试
- **用户可见反馈**：提示"该套餐信息已被他人修改，请刷新页面重试"

### 8.2 边界场景 2：删除已关联订单的标准套餐模板

- **触发条件**：模板已被历史订单引用，管理员尝试删除
- **预期行为**：系统拒绝物理删除，标记为 inactive 并保留历史数据
- **用户可见反馈**：提示"该套餐已产生订单，仅可下架不可删除"

### 8.3 边界场景 3：自定义套餐课时数超出范围

- **触发条件**：学员购买自定义套餐时课时数不在后台配置范围内
- **预期行为**：购买接口拒绝并提示允许范围
- **用户可见反馈**：提示"自定义课时数需在 1~50 节之间"

## 14. 页面级设计决策

### 14.1 标准套餐与自定义套餐分 Tab 展示

- 标准套餐以表格形式展示
- 自定义套餐配置区展示「允许课时范围」和「有效期默认值」

### 14.2 上下架操作即时生效

- 上架/下架按钮点击后二次确认
- 生效后立即影响游客端/学员端套餐列表

### 14.3 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 点击新增 | 按钮 | 弹出表单弹窗 | 字段含校验规则 |
| 提交表单 | 点击确定 | 成功：关闭弹窗并刷新列表；失败：显示错误 | — |
| 切换上下架 | 点击开关 | 二次确认后状态变更 | 仅影响新购 |

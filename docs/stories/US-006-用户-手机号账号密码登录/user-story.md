## 2. 触发条件

- **触发方**：用户
- **触发动作**：在登录页选择「手机号登录」或「账号密码登录」并提交
- **触发时机**：用户主动操作，退出登录后或切换账号时

---

## 3. 前置条件

- [x] 用户已完成资料补充（依赖 US-005），`profile_completed = true` 且 `status = 0`
- [x] 账号状态正常（未软删除、未封禁）
- [x] 登录设备网络可用

---

## 4. 业务流程

### 4.1 主路径

1. 用户进入登录页，选择登录方式
2. 手机号登录：输入手机号 → 获取验证码 → 输入验证码 → 登录
3. 账号密码登录：输入用户名/手机号 + 密码 → 登录
4. 系统校验凭证
5. 校验通过，生成登录态
6. 跳转首页

### 4.2 异常分支

- **分支 1**：手机号未注册 → 提示「该手机号未注册，请先注册」
- **分支 2**：验证码错误/过期 → 提示「验证码错误或已过期」
- **分支 3**：密码错误 → 提示「密码错误，还可尝试 N 次」
- **分支 4**：账号已注销 → 提示「账号已注销，请重新注册」

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：手机号验证码登录成功

```gherkin
Given 用户已注册且手机号 13800138000 状态正常
When  用户输入手机号 13800138000 和正确验证码 123456
And   用户点击「登录」
Then  系统返回登录态 token
And   页面跳转至首页
And   user.last_login_at 更新为当前时间
```

### 6.2 场景 2：账号密码登录成功

```gherkin
Given 用户 swimmer01 的密码为 Abcd1234
When  用户输入用户名 swimmer01 和密码 Abcd1234
And   用户点击「登录」
Then  系统返回登录态 token
And   页面跳转至首页
```

### 6.3 场景 3：密码错误

```gherkin
Given 用户 swimmer01 的密码为 Abcd1234
When  用户输入用户名 swimmer01 和密码 WrongPass
And   用户点击「登录」
Then  返回错误码 INVALID_CREDENTIALS
And   前端提示"手机号/用户名或密码错误"
```

### 6.4 场景 4：连续密码错误触发账号锁定

```gherkin
Given 用户 swimmer01 的密码为 Abcd1234
And   用户已连续 4 次输入错误密码
When  用户第 5 次输入错误密码并点击「登录」
Then  返回错误码 ACCOUNT_LOCKED
And   前端提示"密码错误次数过多，请 30 分钟后重试或找回密码"
And   账号锁定 30 分钟，期间禁止密码登录
```

### 6.5 场景 5：网络异常导致登录失败

```gherkin
Given 用户已登录小程序
And   用户输入正确的手机号 13800138000 和验证码 123456
When  用户点击「登录」时网络断开或后端超时
Then  前端提示"网络异常，请检查网络后重试"
And   登录态未被创建
And   user.last_login_at 不更新
```

### 6.6 场景 6：账号已注销后尝试登录

```gherkin
Given 用户 swimmer01 的账号已注销（user.status = 1）
When  用户输入用户名 swimmer01 和任意密码并点击「登录」
Then  返回错误码 ACCOUNT_DELETED
And   前端提示"账号已注销，请重新注册"
And   不签发任何 token
```

## 8. 边界场景

### 8.1 边界场景 1：验证码 60 秒内重复获取

- **触发条件**：用户 60 秒内重复点击获取验证码
- **预期行为**：后端限流拒绝，前端倒计时保持
- **用户可见反馈**："请 60 秒后再试"

### 8.2 边界场景 2：连续 5 次密码错误

- **触发条件**：用户连续 5 次输入错误密码
- **预期行为**：账号锁定 30 分钟或触发验证码
- **用户可见反馈**："密码错误次数过多，请 30 分钟后重试或找回密码"

### 8.3 边界场景 3：登录设备异地

- **触发条件**：用户在非常用设备/地点登录
- **预期行为**：发送登录提醒通知，必要时二次验证
- **用户可见反馈**："检测到新设备登录，请确认"

## 14. 页面级设计决策

### 14.1 登录方式 Tab 设计

- **背景**：需要同时支持手机号验证码和账号密码登录
- **选项**：A. 两个 Tab 切换；B. 一个表单，提供切换入口
- **结论**：选择 A，顶部 Tab「手机号登录」「密码登录」
- **影响范围**：登录页 UI、路由参数

### 14.2 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 切换登录方式 | 点击 Tab | 表单内容切换 | 保留已填手机号 |
| 获取验证码 | 点击按钮 | 60 秒倒计时 | 失败显示错误提示 |

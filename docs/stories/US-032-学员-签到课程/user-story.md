## 2. 触发条件

- **触发方**：学员
- **触发动作**：在「我的预约」点击「一键签到」；在「上课记录」页点击「填写课后总结」
- **触发时机**：签到在课程开始前 15 分钟至课程结束期间；课后总结在课程开始后即可填写

---

## 3. 前置条件

- [x] 学员已登录（依赖 US-004 / US-005）
- [x] 存在 booking.status ∈ {已预约, 待上课, 上课中}（依赖 US-029）；课后总结场景允许 status = 已完成
- [x] 签到：当前时间在课程开始时间前 15 分钟至课程结束时间之间
- [x] 课后总结：当前时间 ≥ 课程开始时间（无需 booking 必须 已完成，但若教练未确认则 course_record 尚不存在，系统应支持学员预填总结，待教练确认时合并）

---

## 4. 业务流程

### 4.1 主路径

1. 学员进入「我的预约」，点击目标课程卡片
2. 若在签到窗口内，展示「一键签到」按钮
3. 学员点击签到，系统记录 `booking.checked_in_at = NOW()`，不扣除课时
4. 系统通知教练「学员已到场」
5. 课程结束后，学员进入「上课记录」页
6. 系统展示教练填写的课程记录（如有）：时间、内容、重点、作业、照片/视频；若教练尚未通过 US-033 创建 course_record，显示空记录占位
7. 学员点击「填写课后总结」，填写身体感受、学习效果、问题反馈
8. 系统保存总结：若 course_record 已存在，写入 `course_record.student_summary_json`；若不存在，创建临时 `student_summary` 记录（绑定 booking_id），待 US-033 教练确认时合并
9. 返回保存成功，更新记录页展示学员总结

### 4.2 异常分支

- **分支 1**：不在签到窗口内 → 返回 `CHECKIN_WINDOW_NOT_OPEN`
- **分支 2**：booking 已取消 / 旷课 → 返回 `BOOKING_NOT_CHECKINABLE`
- **分支 3**：重复签到 → 幂等返回已签到状态
- **分支 4**：非本人操作 → 返回 403

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常签到

```gherkin
Given 学员已登录
And   存在 booking.status = 待上课，开课时间为今日 10:00，结束时间为 11:00
And   当前时间为今日 9:50
When  学员点击「一键签到」
Then  booking.checked_in_at 写入当前时间戳
And   booking.status 保持 待上课
And   教练收到「学员已到场」通知
And   返回 HTTP 200
```

### 6.2 场景 2：正常提交课后总结（course_record 已由教练创建）

```gherkin
Given 学员已登录
And   存在 booking.status = 已完成
And   教练已通过 US-033 确认上课并创建 course_record
When  学员填写课后总结：身体感受"稍有疲劳"、学习效果"蛙泳划手有进步"、问题反馈"换气节奏不稳"
Then  course_record.student_summary_json 保存上述内容
And   返回 HTTP 200
```

### 6.2.1 场景 2b：教练尚未确认时学员预填课后总结

```gherkin
Given 学员已登录
And   存在 booking.status ∈ {待上课, 上课中}（教练尚未通过 US-033 确认）
And   course_record 尚不存在
When  学员填写课后总结
Then  系统创建临时 student_summary 记录（绑定 booking_id）
And   返回 HTTP 200，提示"总结已保存，待教练确认后合并"
And   教练通过 US-033 确认创建 course_record 时，系统将临时 student_summary 合并写入 course_record.student_summary_json
```

### 6.3 场景 3：不在签到窗口内

```gherkin
Given 学员已登录
And   存在 booking.status = 已预约，开课时间为明日 10:00
And   当前时间为今日 12:00
When  学员尝试签到
Then  系统返回 HTTP 400，错误码 CHECKIN_WINDOW_NOT_OPEN
And   不更新 booking.checked_in_at
```

### 6.4 场景 4：重复签到

```gherkin
Given 学员已登录
And   存在 booking.checked_in_at 已设置
When  学员再次点击「一键签到」
Then  系统返回 HTTP 200
And   booking.checked_in_at 保持不变
And   不重复发送通知
```

### 6.5 场景 5：查看教练尚未填写的上课记录

```gherkin
Given 学员已登录
And   存在 booking.status = 已完成（或仍在 待上课/上课中 但已过开课时间）
And   教练尚未通过 US-033 创建 course_record
When  学员进入「上课记录」页
Then  系统返回空记录占位
And   提示"教练还未填写本节课记录"
And   仍允许学员预填课后总结（见场景 2b）
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `booking` | 修改 | 记录 checked_in_at |
| 2 | `course_record` | 读/修改 | 读取教练记录，保存学员总结 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/bookings/{booking_id}/check-in` | POST | 新增 | 学员签到 |
| 2 | `/api/bookings/{booking_id}/record` | GET | 新增 | 查看上课记录 |
| 3 | `/api/bookings/{booking_id}/summary` | POST | 新增 | 提交课后总结 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `booking` | 无状态转换 | 签到 | 仅更新 checked_in_at，不影响状态机 |
| 2 | `course_record` | 修改 | 提交课后总结 | 保存学员反馈 |

## 8. 边界场景

### 8.1 边界场景 1：网络抖动导致重复签到

- **触发条件**：前端重试导致同一请求多次到达
- **预期行为**：幂等键去重，返回已签到结果
- **用户可见反馈**：签到成功页

### 8.2 边界场景 2：课程取消后尝试签到

- **触发条件**：booking.status = 已取消，学员仍点击签到
- **预期行为**：返回 BOOKING_NOT_CHECKINABLE
- **用户可见反馈**：提示"课程已取消，无需签到"

### 8.3 边界场景 3：上课中才签到

- **触发条件**：学员上课开始后才点击签到
- **预期行为**：允许签到（只要在课程结束时间内）
- **用户可见反馈**：签到成功，教练收到迟到到场通知

## 14. 页面级设计决策

### 14.1 签到按钮状态

- 签到窗口外：隐藏按钮
- 签到窗口内且未签到：显示「一键签到」
- 已签到：按钮变为「已签到」并禁用

### 14.2 课后总结字段

- 身体感受：单选（轻松 / 正常 / 疲劳）
- 学习效果：单选（进步明显 / 有进步 / 一般 / 困难）
- 问题反馈：多行文本，最多 200 字

### 14.3 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |

## 4. 业务流程

### 4.1 主路径（加入候补）

1. 学员进入预约页面，看到某时段已约满
2. 学员点击「加入候补」
3. 系统校验：用户已登录、有 active 套餐、时段已满、未重复候补
4. 系统创建 waitlist 记录（status=waiting）
5. 学员可在「我的候补」查看排队位置

### 4.2 主路径（关注时段）

1. 学员看到心仪时段（无论是否已满）
2. 学员点击「关注」
3. 系统创建 slot_follow 记录
4. 该时段释放前或有人取消时，系统发送提醒（US-024 及通知）

### 4.3 异常分支

- **分支 1**：时段未满 → 加入候补按钮不可用，引导直接预约
- **分支 2**：用户无 active 套餐 → 返回错误码 `NO_ACTIVE_PACKAGE`
- **分支 3**：已加入同一时段候补 → 返回错误码 `ALREADY_IN_WAITLIST`

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：成功加入候补

```gherkin
Given 学员已登录且持有 active 套餐
And   教练 A 明日 9:00 时段已约满
When  学员点击「加入候补」
Then  系统创建 waitlist.status = waiting
And   学员在「我的候补」看到该记录
And   接口返回 HTTP 201
```

### 6.2 场景 2：成功关注时段

```gherkin
Given 用户已登录
And   教练 A 明日 10:00 时段已释放
When  用户点击「关注」
Then  系统创建 slot_follow 记录
And   用户在「我的关注」看到该记录
And   接口返回 HTTP 201
```

### 6.3 场景 3：时段未满不能候补

```gherkin
Given 学员已登录且持有 active 套餐
And   教练 A 明日 11:00 时段仍有余位
When  学员查看该时段
Then  「加入候补」按钮置灰
And   文案提示"该时段可直接预约"
```

### 6.4 场景 4：无 active 套餐不能候补

```gherkin
Given 注册用户已登录但无 active 套餐
And   教练 A 明日 9:00 时段已约满
When  学员点击「加入候补」
Then  系统返回 HTTP 400，错误码 NO_ACTIVE_PACKAGE
And   不创建 waitlist 记录
```

### 6.5 场景 5：重复加入同一时段候补

```gherkin
Given 学员已登录且已加入教练 A 明日 9:00 的候补
When  学员再次点击「加入候补」
Then  系统返回 HTTP 400，错误码 ALREADY_IN_WAITLIST
And   不重复创建记录
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `waitlist` | 新增 | 候补记录 |
| 2 | `slot_follow` | 新增 | 关注记录 |
| 3 | `schedule_slot` | 读取 | 校验时段状态 |
| 4 | `package` | 读取 | 校验 active 套餐 |
| 5 | `user` | 读取 | 登录态 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/schedule-slots/{id}/waitlist` | POST | 新增 | 加入候补 |
| 2 | `/api/waitlist/{id}` | DELETE | 新增 | 取消候补 |
| 3 | `/api/schedule-slots/{id}/follow` | POST | 新增 | 关注时段 |
| 4 | `/api/follows/{id}` | DELETE | 新增 | 取消关注 |
| 5 | `/api/users/me/waitlist-and-follows` | GET | 新增 | 我的候补与关注 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `waitlist` | 无 → waiting | 加入候补 | 由 US-024 触发转正 |
| 2 | `waitlist` | waiting → cancelled | 用户取消或他处转正 | — |
| 3 | `waitlist` | waiting → converted | 有人取消且轮到该用户 | US-024 |

## 8. 边界场景

### 8.1 边界场景 1：同时加入多个时段候补

- **触发条件**：学员加入 3 个不同时段候补
- **预期行为**：均创建 waiting 记录
- **用户可见反馈**：「我的候补」展示 3 条记录

### 8.2 边界场景 2：取消候补

- **触发条件**：学员在「我的候补」点击取消
- **预期行为**：waitlist.status = cancelled
- **用户可见反馈**：记录移至已取消

### 8.3 边界场景 3：候补有效期内时段被删除

- **触发条件**：管理员删除或隐藏该 schedule_slot
- **预期行为**：相关 waitlist 自动 cancelled，slot_follow 自动删除或标记失效
- **用户可见反馈**：提示"该时段已失效"

## 4. 业务流程

### 4.1 主路径

1. 游客进入教练详情页，点击「购买体验课」
2. 系统展示《用户须知》并校验用户已勾选「我已阅读并同意《用户须知》」
3. 系统校验用户身份、教练状态、体验课购买资格、协议勾选状态
4. 系统生成待支付订单（order.status = 待支付）
5. 游客选择微信支付/支付宝支付并完成付款
6. 系统接收支付回调，更新订单为已支付
7. **支付成功后**系统创建 active 体验套餐（package.status = active，available=1，expire_at=30 天后）
8. 系统触发身份重算，用户变为学员
9. 系统返回购买成功，游客可预约该教练体验课

> **顺序修正说明**（P0 修复）：原版本在「订单创建」时就预创建 active 套餐，违反订单状态机（未支付不应有 active 套餐）。现按 PRD §6.2 订单状态机：订单待支付 → 支付回调成功 → 才创建/激活套餐。套餐创建与支付回调在同一事务。

### 4.2 异常分支

- **分支 1**：用户未勾选《用户须知》 → 返回错误 `AGREEMENT_REQUIRED`
- **分支 2**：用户已有 active/exhausted 体验套餐 → 返回错误 `TRIAL_PACKAGE_EXISTS`
- **分支 3**：教练 status ≠ 1 → 返回错误 `COACH_UNAVAILABLE`
- **分支 4**：支付超时 24h → 订单自动取消，套餐回滚

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常购买体验课

```gherkin
Given 游客已登录且名下无体验套餐
And   教练 A 状态为已通过（status=1）
When  游客提交体验课订单
Then  订单状态 = 待支付
And   不创建 package（套餐在支付成功后才激活）
And   接口返回 HTTP 201 与支付参数
When  游客完成支付，支付回调到达
Then  订单状态 = 已支付
And   package.status = active，package_type = 0，available = 1，total_hours = 1，expire_at = 30 天后
And   用户身份变为学员
And   接口返回 HTTP 200
```

### 6.2 场景 2：游客未勾选《用户须知》

```gherkin
Given 游客已登录且名下无体验套餐
And   教练 A 状态为已通过（status=1）
And   用户未勾选《用户须知》
When  游客提交体验课订单
Then  系统返回 HTTP 400，错误码 AGREEMENT_REQUIRED
And   不创建订单
And   前端提示"请先阅读并同意《用户须知》"
```

### 6.3 场景 3：游客未登录触发登录

```gherkin
Given 游客未登录
When  游客点击"购买体验课"
Then  系统引导游客先完成微信授权登录
And   登录后回到购买确认页
```

### 6.4 场景 4：已有体验套餐再次购买

```gherkin
Given 用户名下已有 status=active 的体验套餐
When  用户再次购买体验课
Then  系统返回 HTTP 400，错误码 TRIAL_PACKAGE_EXISTS
And   不创建新订单和套餐
```

### 6.5 场景 5：教练不可约

```gherkin
Given 教练 B 状态为待审核（status=0）
When  游客购买教练 B 的体验课
Then  系统返回 HTTP 400，错误码 COACH_UNAVAILABLE
And   不创建订单
```

### 6.6 场景 6：支付超时取消

```gherkin
Given 游客已提交体验课订单但未支付
And   订单创建时间为 24 小时前
When  系统定时任务扫描超时订单
Then  订单状态变为已取消
And   不创建 package（因支付未成功，套餐从未激活）
And   用户身份保持游客/注册用户不变
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `order` | 新增 | 体验课订单，course_type=0，初始 status=待支付 |
| 2 | `package` | 新增（支付成功后） | 体验套餐，支付回调成功时创建，status=active，expire_at=30 天后 |
| 3 | `payment` | 新增 | 支付流水 |
| 4 | `agreement_sign` | 新增 | 记录《用户须知》签署版本与时间 |
| 5 | `user` | 修改 | 支付成功后 identity 字段更新为学员 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/orders/trial` | POST | 新增 | 创建体验课订单（校验协议勾选，仅创建待支付订单，不创建套餐） |
| 2 | `/api/orders/{id}/pay` | POST | 新增 | 发起支付 |
| 3 | `/api/payments/callback` | POST | 新增 | 支付回调（事务内：更新订单+创建套餐+记录协议签署+更新身份） |
| 4 | `/api/agreements/status` | GET | 新增 | 查询用户协议签署状态 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `order` | 无 → 待支付 → 已支付 | 提交订单 / 支付回调 | 订单状态机驱动套餐激活 |
| 2 | `package` | 无 → active | **支付回调成功**（非订单创建） | 修正：原"订单创建时预创建"违反状态机 |
| 3 | `user` | 注册用户 → 学员 | 支付成功 | 与套餐创建同一事务 |

## 8. 边界场景

### 8.1 边界场景 1：支付回调幂等

- **触发条件**：同一笔支付回调被推送两次
- **预期行为**：第二次幂等，订单状态不变，不重复增加套餐
- **用户可见反馈**：购买成功页正常展示

### 8.2 边界场景 2：支付成功但 package 创建失败

- **触发条件**：支付回调处理中 DB 异常
- **预期行为**：事务回滚或补偿重试，确保用户已支付必有套餐
- **用户可见反馈**：客服介入或自动重试后成功

### 8.3 边界场景 3：体验课套餐过期后再次购买

- **触发条件**：用户之前体验套餐 status=expired 且 available > 0
- **预期行为**：允许再次购买（§4.5）
- **用户可见反馈**：购买流程正常进行

## 12. 备注

- **幂等键**：支付回调以 `out_trade_no` 幂等
- **事务边界**：订单创建独立事务；支付回调（更新订单 + 创建套餐 + 记录协议签署 + 身份更新）在同一事务
- **性能要求**：下单接口 P99 < 300ms
- **协议签署**：下单前必须校验用户已同意最新版《用户须知》，并在支付回调成功时写入 `agreement_sign`

## 2. 触发条件

- **触发方**：用户
- **触发动作**：在登录页选择「手机号登录」，输入手机号并获取验证码，提交登录
- **触发时机**：用户主动操作，退出登录后或切换账号时；或受登录态保护的功能被访问时由系统引导跳转

---

## 3. 前置条件

- [x] 用户已安装微信并打开小程序
- [x] 用户已同意隐私协议（依赖 US-009）
- [x] 用户已阅读并勾选《用户须知》（首次登录时需在登录页勾选；已注册用户需确认当前版本已同意）
- [x] 登录设备网络可用
- [x] 系统短信服务正常

## 4. 业务流程

### 4.1 主路径（已注册手机号登录）

1. 用户进入登录页，选择「手机号登录」
2. 用户输入手机号
3. 用户点击「获取验证码」，系统校验手机号格式并发送短信验证码
4. 用户输入收到的短信验证码
5. 用户勾选「我已阅读并同意《用户须知》和《隐私协议》」
6. 用户点击「登录」
7. 系统校验手机号、验证码，以及是否勾选《用户须知》和《隐私协议》
8. 校验通过，生成登录态
9. 系统按 `profile_completed` 决定跳转：
   - `false` → 跳转「完善个人资料页」（US-005）
   - `true` → 跳转小程序首页

### 4.2 主路径（未注册手机号首次登录即注册）

1. 用户输入未注册的手机号
2. 用户点击「获取验证码」
3. 用户输入验证码
4. 用户勾选「我已阅读并同意《用户须知》和《隐私协议》」
5. 用户点击「登录」
6. 系统校验手机号、验证码，以及是否勾选《用户须知》和《隐私协议》
7. 系统发现该手机号未注册，自动创建用户记录：
   - `identity_status = '注册用户'`
   - `profile_completed = false`
   - `phone = 输入的手机号`
8. 系统生成登录态
9. 系统跳转「完善个人资料页」（US-005）

### 4.3 异常分支

- **分支 1**：手机号格式错误 → 提示「请输入正确的手机号」
- **分支 2**：手机号未注册但验证码错误 → 提示「验证码错误或已过期」
- **分支 3**：验证码过期 → 提示「验证码错误或已过期」
- **分支 4**：60 秒内重复获取验证码 → 提示「请 60 秒后再试」
- **分支 5**：账号已注销（status=1）→ 提示「账号已注销，请重新注册」
- **分支 6**：短信服务失败 → 提示"验证码发送失败，请稍后重试"
- **分支 7**：未勾选《用户须知》或《隐私协议》→ 提示「请阅读并同意《用户须知》和《隐私协议》」，不执行登录

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：已注册手机号验证码登录成功

```gherkin
Given 用户已注册且手机号 13800138000 状态正常
And   用户已同意隐私协议 v2.0
And   用户已勾选《用户须知》和《隐私协议》
When  用户输入手机号 13800138000 和正确验证码 123456
And   用户点击「登录」
Then  系统返回登录态 token
And   若 profile_completed = true，页面跳转至首页
And   若 profile_completed = false，页面跳转至「完善个人资料页」（US-005）
And   user.last_login_at 更新为当前时间
```

### 6.2 场景 2：未注册手机号首次验证码登录并自动注册

```gherkin
Given user 表中不存在手机号 13800138000
And   用户已同意隐私协议 v2.0
And   用户已勾选《用户须知》和《隐私协议》
When  用户输入手机号 13800138000 和正确验证码 123456
And   用户点击「登录」
Then  系统自动创建新用户记录
And   identity_status = "注册用户"
And   profile_completed = false
And   phone = 13800138000
And   系统返回登录态 token
And   页面跳转至「完善个人资料页」（US-005）
```

### 6.3 场景 3：未勾选《用户须知》或《隐私协议》

```gherkin
Given 用户已输入手机号 13800138000 和正确验证码 123456
When  用户未勾选《用户须知》或《隐私协议》
And   用户点击「登录」
Then  系统阻止登录
And   返回错误码 TERMS_NOT_ACCEPTED
And   前端提示「请阅读并同意《用户须知》和《隐私协议》」
And   不签发任何 token
And   不创建或修改 user 记录
```

### 6.4 场景 4：验证码错误

```gherkin
Given 用户输入手机号 13800138000
When  用户输入错误验证码 000000
And   用户点击「登录」
Then  返回错误码 INVALID_SMS_CODE
And   前端提示"验证码错误或已过期"
And   不签发任何 token
```

### 6.4 场景 4：60 秒内重复获取验证码

```gherkin
Given 用户刚刚获取过验证码
When  用户在 60 秒内再次点击「获取验证码」
Then  系统拒绝发送
And   前端提示"请 60 秒后再试"
```

### 6.5 场景 5：账号已注销后尝试登录

```gherkin
Given 手机号 13800138000 的账号已注销（user.status = 1）
When  用户输入该手机号和正确验证码并点击「登录」
Then  返回错误码 ACCOUNT_DELETED
And   前端提示"账号已注销，请重新注册"
And   不签发任何 token
```

### 6.6 场景 6：网络异常导致登录失败

```gherkin
Given 用户输入正确的手机号 13800138000 和验证码 123456
When  用户点击「登录」时网络断开或后端超时
Then  前端提示"网络异常，请检查网络后重试"
And   登录态未被创建
And   user.last_login_at 不更新
```

## 8. 边界场景

### 8.1 边界场景 1：验证码 60 秒内重复获取

- **触发条件**：用户 60 秒内重复点击获取验证码
- **预期行为**：后端限流拒绝，前端倒计时保持
- **用户可见反馈**："请 60 秒后再试"

### 8.2 边界场景 2：登录设备异地

- **触发条件**：用户在非常用设备/地点登录
- **预期行为**：发送登录提醒通知，必要时二次验证
- **用户可见反馈**："检测到新设备登录，请确认"

### 8.3 边界场景 3：短信服务不可用

- **触发条件**：短信服务商接口异常
- **预期行为**：前端提示发送失败，可重试
- **用户可见反馈**："验证码发送失败，请稍后重试"

## 14. 页面级设计决策

### 14.1 登录页设计

- **背景**：仅保留手机号验证码登录
- **结论**：登录页包含手机号输入框、验证码输入框、获取验证码按钮、登录按钮；底部增加协议勾选区「我已阅读并同意《用户须知》和《隐私协议》」
- **影响范围**：登录页 UI，无需 Tab 切换

### 14.2 协议勾选校验

- **背景**：登录时必须校验用户已勾选《用户须知》和《隐私协议》
- **选项**：A. 前端校验即可；B. 前端 + 后端双重校验
- **结论**：选 B，前端点击登录时立即提示，后端 `POST /api/auth/login/phone` 同时校验 `terms_accepted=true` 且 `privacy_accepted=true`
- **影响范围**：登录页交互、后端登录接口

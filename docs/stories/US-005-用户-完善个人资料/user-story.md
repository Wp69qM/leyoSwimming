## 2. 触发条件

> 什么事件/操作触发该故事

- **触发方**：用户
- **触发动作 1**：首次使用微信授权登录（US-004）或手机号验证码登录（US-006）后，系统检测到资料缺失，进入资料完善页
- **触发动作 2**：用户主动进入「我的 → 个人资料」点击「编辑资料」
- **触发时机**：登录成功后立即触发，或用户主动操作时

## 3. 前置条件

> 故事执行前必须满足的状态

- [x] 用户已完成登录（微信授权登录依赖 US-004，手机号验证码登录依赖 US-006）
- [x] 用户已勾选《用户须知》和《隐私协议》（依赖 US-009）
- [x] 当前用户资料状态为不完整（`profileCompleted = false`）或用户主动编辑资料（`profileCompleted = true`）
- [x] 系统已存在当前登录用户的 `user` 记录

## 4. 业务流程

> 步骤列表（带异常分支），用户视角描述

### 4.1 主路径（首次完善）

1. 用户登录成功，系统判断 `profileCompleted = false`
2. 系统展示个人资料完善页，默认带入已获取的头像、手机号（微信登录带入微信头像与授权手机号；手机号登录带入手机号）
3. 用户填写/确认必填项：头像、姓名、手机号、年龄、性别
4. 若用户填写的年龄 < 18 周岁，系统动态展示监护人信息填写区，用户必须填写监护人姓名、监护人手机号
5. 用户选填：有无游泳基础、会什么泳姿（有基础时显示）、游泳年限（有基础时显示）、个人描述
6. 用户点击「保存」
7. 系统校验必填项、字段格式、手机号唯一性、姓名敏感词、监护人手机号格式（未成年人时）
8. 系统保存资料，设置 `user.profileCompleted = true`
9. 系统返回首页或「我的」页面（首次完善跳转首页，编辑资料返回「我的」）

### 4.2 主路径（从「我的」编辑资料）

1. 用户在「我的」页面点击头像/昵称区域或「编辑资料」按钮
2. 系统展示个人资料页，回显当前已填写内容
3. 用户修改任意字段
4. 用户点击「保存」
5. 系统校验并保存，`profileCompleted` 保持 `true`
6. 系统返回「我的」页面

### 4.3 异常分支

- **分支 1**：手机号已被其他账号绑定 → 提示「该手机号已绑定其他账号，请更换」
- **分支 2**：必填项缺失 → 前端阻止提交，对应字段下方提示「不能为空」
- **分支 3**：姓名含敏感词 → 提示「姓名包含敏感内容，请重新输入」
- **分支 4**：头像上传失败 → 提示「头像上传失败，请重试」
- **分支 5**：未成年人未填写监护人姓名/手机号 → 前端阻止提交，提示「请填写监护人信息」
- **分支 6**：监护人手机号格式错误 → 提示「请输入正确的监护人手机号」

## 8. 边界场景

> 至少 3 个异常边界场景

### 8.1 边界场景 1：快速重复提交

- **触发条件**：用户连续点击「保存」按钮两次
- **预期行为**：幂等处理，第二次请求返回与第一次一致的结果，不重复更新
- **用户可见反馈**：页面正常跳转/返回，无重复提示

### 8.2 边界场景 2：网络中断

- **触发条件**：提交过程中网络断开
- **预期行为**：前端展示重试机制，失败后提示用户重新提交
- **用户可见反馈**："网络异常，请检查网络后重试"

### 8.3 边界场景 3：头像上传失败

- **触发条件**：用户选择头像后上传失败（网络/格式/大小超限）
- **预期行为**：前端提示上传失败，保留其他字段已填写内容
- **用户可见反馈**："头像上传失败，请重试"

### 8.4 边界场景 4：从「我的」编辑时不慎清空必填项

- **触发条件**：用户在编辑资料页清空必填项后点击保存
- **预期行为**：前端校验阻止提交，提示必填项缺失
- **用户可见反馈**：对应字段下方显示红色错误提示

### 8.5 边界场景 5：用户将年龄从成年人修改为未成年人

- **触发条件**：用户在编辑资料页将年龄从 25 修改为 12
- **预期行为**：系统动态展示监护人信息填写区并要求填写后才能保存
- **用户可见反馈**：页面出现监护人姓名/手机号输入框，未填写时提示必填

### 8.6 边界场景 6：用户将年龄从未成年人修改为成年人

- **触发条件**：用户在编辑资料页将年龄从 12 修改为 25
- **预期行为**：系统隐藏监护人信息填写区，已保存的 guardianName/guardianPhone 保留但不再展示和校验必填
- **用户可见反馈**：监护人信息区折叠或消失

## 14. 页面级设计决策

> 本节是**本故事特殊**的设计选择，**全局规范**中没有定义的设计决策记录在这里。

### 14.1 资料完善的入口策略

- **背景**：首次登录后必须完善资料才能使用核心功能
- **选项**：A. 强制跳转资料完善页；B. 首页顶部提示条引导
- **结论**：选择 A，登录后直接跳转资料完善页，未完善必填项无法进入首页
- **影响范围**：登录回调页、资料完善页、首页路由守卫

### 14.2 手机号字段定位

- **背景**：微信登录或手机号登录已获取手机号
- **选项**：A. 仅展示不可改；B. 展示并允许修改；C. 不展示
- **结论**：选择 B，展示已绑定手机号并允许修改，修改时需校验唯一性
- **影响范围**：表单设计、手机号唯一性校验

### 14.3 游泳基础相关字段联动

- **背景**：「有无游泳基础」决定「会什么泳姿」「游泳年限」是否展示
- **选项**：A. 始终展示；B. 选择「有基础」后动态显示
- **结论**：选择 B，选择「无基础」时隐藏泳姿和年限字段
- **影响范围**：表单交互、数据模型字段可为空

### 14.4 编辑资料入口

- **背景**：用户需要随时修改个人资料
- **选项**：A. 新增独立 US；B. 扩展 US-005 覆盖「我的 → 编辑资料」
- **结论**：选择 B，扩展 US-005，两个入口共用同一页面与 API
- **影响范围**：「我的」页面需增加「编辑资料」入口

### 14.5 未成年人监护人信息联动

- **背景**：未成年人（< 18 周岁）需额外维护监护人姓名与手机号，满足合规要求
- **选项**：A. 所有用户都展示监护人字段；B. 仅当年龄 < 18 时动态展示并校验必填
- **结论**：选择 B，根据用户填写的年龄实时判断，未成年人时监护人姓名/手机号为必填，成年人时隐藏
- **影响范围**：表单交互、数据模型增加 guardianName / guardianPhone、前端校验逻辑、后端必填校验

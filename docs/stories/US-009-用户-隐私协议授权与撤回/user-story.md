## 2. 触发条件

- **触发方**：用户
- **触发动作**：首次注册时系统展示隐私协议，或用户主动进入「我的 → 设置 → 隐私协议」
- **触发时机**：注册完成时、协议版本更新时、用户主动操作时

## 3. 前置条件

- [x] 用户已完成微信授权登录（依赖 US-004）

## 4. 业务流程

### 4.1 主路径

1. 系统展示隐私协议内容（首次注册或版本更新时）
2. 用户阅读后勾选「我已阅读并同意《隐私协议》」
3. 用户点击「同意」
4. 系统记录用户同意的协议版本号和同意时间
5. 用户进入后续流程

### 4.2 异常分支

- **分支 1**：用户不同意隐私协议 → 无法完成注册/继续使用需授权的功能
- **分支 2**：用户撤回授权 → 系统限制数据收集相关功能，提示影响
- **分支 3**：协议版本更新 → 用户下次使用时需重新同意新版本

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常同意隐私协议

```gherkin
Given 用户已完成微信授权登录（首次注册）
And   当前隐私协议版本为 v2.0
When  用户阅读并勾选「我已阅读并同意《隐私协议》」
And   用户点击「同意」
Then  系统记录 user_privacy_consent.version = 'v2.0'
And   user_privacy_consent.agreed_at 为当前时间
And   用户可继续进入首页
```

### 6.2 场景 2：不同意隐私协议

```gherkin
Given 用户首次注册进入隐私协议页
When  用户点击「不同意」
Then  前端提示"需同意隐私协议后方可继续使用"
And   用户无法进入首页
And   user_privacy_consent 无记录
```

### 6.3 场景 3：撤回隐私授权

```gherkin
Given 用户已同意隐私协议 v2.0
When  用户在隐私设置页点击「撤回授权」
And   用户确认撤回
Then  user_privacy_consent.status = 'revoked'
And   user_privacy_consent.revoked_at 为当前时间
And   系统停止非必要的数据收集
And   前端提示"已撤回授权，部分功能可能受限"
```

## 8. 边界场景

### 8.1 边界场景 1：协议版本更新后未重新同意

- **触发条件**：系统更新隐私协议至 v3.0，用户仍只同意过 v2.0
- **预期行为**：用户下次进入需授权场景时强制重新同意
- **用户可见反馈**：弹窗提示"隐私协议已更新，请重新阅读并同意"

### 8.2 边界场景 2：撤回授权后访问需授权功能

- **触发条件**：用户已撤回授权，尝试购买套餐
- **预期行为**：阻止购买流程，提示需重新授权
- **用户可见反馈**："您已撤回隐私授权，无法使用购买功能，请重新同意"

### 8.3 边界场景 3：重复同意同一版本

- **触发条件**：用户已同意 v2.0，再次点击同意
- **预期行为**：幂等处理，不新增重复记录
- **用户可见反馈**：正常进入流程

## 14. 页面级设计决策

### 14.1 隐私协议弹窗 vs 全页

- **背景**：首次注册时如何展示隐私协议
- **选项**：A. 全屏页面；B. 底部弹窗
- **结论**：选择 A，首次注册使用全屏页面，确保用户充分阅读
- **影响范围**：注册流程路由

### 14.2 撤回授权的影响提示

- **背景**：用户可能不理解撤回授权的后果
- **结论**：撤回前展示二次确认弹窗，明确列出受影响功能
- **影响范围**：隐私设置页交互

### 14.3 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 点击同意 | 勾选并点击按钮 | 记录同意并进入首页 | 未勾选时按钮禁用 |
| 点击撤回 | 点击按钮 | 二次确认弹窗 | 确认后更新状态 |

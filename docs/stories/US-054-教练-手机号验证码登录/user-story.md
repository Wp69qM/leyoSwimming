## 2. 触发条件

- **触发方**：教练
- **触发动作**：在教练端登录页选择「手机号登录」，输入手机号并获取验证码，提交登录
- **触发时机**：教练主动操作，退出登录后或切换账号时；或受登录态保护的功能被访问时由系统引导跳转

- [x] 教练已安装微信并打开教练端小程序
- [x] 教练已勾选《用户须知》和《隐私协议》（依赖 US-009）
- [x] 教练每次登录时均已阅读并勾选《用户须知》和《隐私协议》（与首次/非首次无关）
- [x] 登录设备网络可用
- [x] 系统短信服务正常
- [x] 教练未处于已登录态（或登录态已过期）

## 4. 业务流程

### 4.1 主路径（已注册手机号登录）

1. 教练进入教练端登录页，选择「手机号登录」
2. 教练输入手机号
3. 教练点击「获取验证码」，系统校验手机号格式并发送短信验证码
4. 教练输入收到的短信验证码
5. 教练勾选「我已阅读并同意《用户须知》和《隐私协议》」
6. 教练点击「登录」
7. 系统校验手机号、验证码，以及是否勾选《用户须知》和《隐私协议》
8. 校验通过，后端按手机号查询 `coach` 表：
   - 手机号存在 → 复用账号（含 status=3 已离职账号，登录后走重新入驻分流）
9. 后端签发 JWT `access_token` + `refresh_token`，返回 `expires_in`、`is_new_coach`、`coach_status`
10. 前端将 `access_token` 与 `refresh_token` 存储到本地（如 `Taro.setStorageSync`），并记录 `expires_in`（登录态管理规则与 US-051 一致）
11. 前端按 `coach_status` 决定跳转（跳转目标与 US-051 一致）：
    - `-1`（未提交入驻资料） → 跳转「入驻资料填写页」（US-010）
    - `0`（待审核） → 跳转「等待审核页」
    - `1`（已通过） → 跳转「教练首页」（US-012 起）
    - `2`（已驳回） → 跳转「入驻资料填写页」（US-010，顶部展示驳回原因条）
    - `3`（已离职） → 跳转「入驻资料填写页」（US-010，顶部展示重新入驻说明条）
    - `4`（申请离职中） → 跳转「教练首页」；「我的」页面提供「查看离职申请」入口，教练可主动进入「离职处理中页」（US-039），不强制跳转
12. 后续访问受登录态保护的接口时，前端在 HTTP Header `Authorization: Bearer {access_token}` 中携带 token；后端校验 token 有效后方可访问
13. 前端在 app 启动或依赖登录态的页面 `onShow` 时检查本地 token：若不存在或已过期，引导教练重新登录；`access_token` 过期但 `refresh_token` 有效时，前端调用刷新接口换发新的 `access_token`

### 4.2 主路径（未注册手机号首次登录即注册）

1. 教练输入未注册的手机号
2. 教练点击「获取验证码」
3. 教练输入验证码
4. 教练勾选「我已阅读并同意《用户须知》和《隐私协议》」
5. 教练点击「登录」
6. 系统校验手机号、验证码，以及是否勾选《用户须知》和《隐私协议》
7. 系统按手机号查询 `coach` 表：
   - 手机号不存在 → 自动创建新教练记录，`coach.status = -1`（未提交入驻资料）
   - 手机号存在 → 复用账号（含 status=3 已离职账号，登录后走重新入驻分流）
8. 后端签发 JWT `access_token` + `refresh_token`，返回 `expires_in`、`is_new_coach = true`、`coach_status = -1`
9. 前端将 `access_token` 与 `refresh_token` 存储到本地，并记录 `expires_in`
10. 前端跳转「入驻资料页」（US-010）

### 4.3 异常分支

- **分支 1**：手机号格式错误 → 提示「请输入正确的手机号」
- **分支 2**：手机号已注册但验证码错误 → 提示「验证码错误或已过期」
- **分支 3**：验证码过期 → 提示「验证码错误或已过期」
- **分支 4**：60 秒内重复获取验证码 → 提示「请 60 秒后再试」
- **分支 5**：短信服务失败 → 提示「验证码发送失败，请稍后重试」
- **分支 6**：未勾选《用户须知》或《隐私协议》→ 提示「请阅读并同意《用户须知》和《隐私协议》」，不执行登录

> **注**：手机号存在且 `status = 3`（已离职）时，系统复用原 coach 记录并登录，登录后按 `coach_status=3` 跳转 US-010 重新入驻资料填写页，原账号历史数据保留。

## 8. 边界场景

### 8.1 边界场景 1：验证码 60 秒内重复获取

- **触发条件**：教练 60 秒内重复点击获取验证码
- **预期行为**：后端限流拒绝，前端倒计时保持
- **用户可见反馈**："请 60 秒后再试"

### 8.2 边界场景 2：登录设备异地

- **触发条件**：教练在非常用设备/地点登录
- **预期行为**：发送登录提醒通知，必要时二次验证
- **用户可见反馈**："检测到新设备登录，请确认"

### 8.3 边界场景 3：短信服务不可用

- **触发条件**：短信服务商接口异常
- **预期行为**：前端提示发送失败，可重试
- **用户可见反馈**："验证码发送失败，请稍后重试"

### 8.4 边界场景 4：已离职手机号登录后重新入驻

- **触发条件**：教练使用已离职（status=3）的手机号登录
- **预期行为**：系统复用原 coach 记录并登录，返回 coach_status=3，登录后按 US-040 跳转 US-010 重新入驻资料填写页，原账号历史数据保留
- **用户可见反馈**：登录成功后跳转「入驻资料填写页」，顶部展示重新入驻说明条，表单自动回显历史内容

## 12. 备注

- **验证码 TTL**：5 分钟
- **登录限流**：同一手机号 60 秒内只能发送 1 条验证码
- **会话有效期**：小程序登录态 30 天
- **自动注册**：未注册手机号首次验证码登录即视为注册，需后续在 US-010 中提交入驻资料
- **已离职账号处理**：`status=3` 的教练手机号登录时，系统复用原 `coach` 记录并登录，返回 `coach_status=3`，登录后按 US-040 跳转 US-010 重新入驻资料填写页，原账号历史数据保留
- **手机号加密**：`coach.phone` 字段需加密存储，日志中脱敏展示

| **登录页-手机号/微信切换入口** | 🔲 | 🔲 | 🔲 | 🔲 | 参考 US-006 用户端登录页入口 |

## 14. 页面级设计决策

### 14.1 登录入口位置

- **背景**：教练端登录页（US-051 C-微信授权页）默认展示「微信一键登录」，需要增加手机号登录入口
- **选项**：
  - A. 登录页底部增加「手机号登录」文字按钮，点击后跳转独立手机号登录页
  - B. 登录页内直接提供「微信登录 / 手机号登录」Tab 切换
  - C. 底部登录区下方增加「其他登录方式：手机号登录」入口
- **结论**：选 A，保持微信一键登录作为主 CTA，底部增加「手机号登录」入口；点击后进入独立手机号登录页，减少单页信息过载
- **影响范围**：教练端微信授权登录页、教练端手机号登录页

### 14.2 手机号登录页设计

- **背景**：仅保留手机号验证码登录
- **结论**：登录页包含手机号输入框、验证码输入框、获取验证码按钮、登录按钮；顶部保留品牌 Logo 与 Slogan；底部增加协议勾选区「我已阅读并同意《用户须知》和《隐私协议》」
- **影响范围**：教练端手机号登录页 UI

### 14.3 协议勾选校验

- **背景**：登录时必须校验教练已勾选《用户须知》和《隐私协议》
- **选项**：A. 前端校验即可；B. 前端 + 后端双重校验
- **结论**：选 B，前端点击登录时立即提示，后端 `POST /api/coach/auth/phone-login` 同时校验 `terms_accepted=true` 且 `privacy_accepted=true`
- **影响范围**：手机号登录页交互、后端登录接口

### 14.4 登录成功后分流策略

- **背景**：教练登录后可能处于多种入驻状态，需要自动跳转到正确页面
- **结论**：登录接口返回 `coach_status`，前端按 `coach_status` 一次跳转到目标页，与 US-051 保持一致
- **影响范围**：登录接口响应字段 + 前端路由逻辑

### 14.5 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 点击「手机号登录」入口 | tap | 跳转教练端手机号登录页 | 见 §14.1 |
| 输入手机号 | input | 实时校验格式，格式错误时输入框边框变红并提示"请输入正确的手机号" | — |
| 点击「获取验证码」 | tap | 按钮进入 60s 倒计时，禁用并显示"已发送（60s）" | 60s 内重复点击提示"请 60 秒后再试" |
| 输入验证码 | input | 6 位数字验证码自动聚焦下一个输入框或整体高亮 | — |
| 未勾选协议时点击「登录」 | tap | 前端提示「请阅读并同意《用户须知》和《隐私协议》」，不发起请求 | 见 §6.3 |
| 已勾选协议后点击「登录」 | tap | 按钮 loading，发起登录请求 | 防重复点击：点击后立即 disable |
| 后端返回成功 | HTTP 200 | 按 coach_status 跳转 | 见 §14.4 |
| 后端返回错误 | HTTP 4xx/5xx | 展示对应错误文案 + 恢复按钮 | 见 §6.4-6.7 |

### 14.6 与用户端 US-006 的区分

| 对比项 | 用户端（US-006） | 教练端（US-054） |
|--------|------------------|------------------|
| 登录查询/写入表 | `user` 表 | `coach` 表 |
| 会话表 | `user_session` | `coach_session` |
| 首次登录默认状态 | `identity_status='注册用户'`，`profile_completed=false` | `coach.status=-1`（未提交入驻资料） |
| 登录后跳转依据 | `profile_completed` | `coach.status`（-1/0/1/2/3/4） |
| 完善资料/入驻步骤 | 完善个人资料（US-005） | 提交入驻资料（US-010） |
| 已注销/离职账号处理 | status=1 重新创建 user 账号 | status=3 重新创建 coach 账号 |

## 4. 业务流程

### 4.1 主路径

1. 教练进入教练端「我的」TabBar 页面
2. 系统展示页面底部「退出登录」按钮
3. 教练点击「退出登录」按钮
4. 系统弹出二次确认弹窗，提示「确定要退出登录吗？」
5. 教练点击弹窗「确定」
6. 系统调用后端退出登录接口，使当前会话 token 失效
7. 系统清除前端本地存储的 access_token、refresh_token 及过期时间
8. 系统跳转回教练登录页（pages/login/index）

### 4.2 异常分支

- **分支 1**：教练点击弹窗「取消」→ 关闭弹窗，保持当前登录态，不执行退出
- **分支 2**：网络异常导致后端退出接口失败 → 前端仍清除本地 token，跳转回教练登录页（pages/login/index）；后端 token 按自身 TTL 自然过期失效
- **分支 3**：本地 token 已不存在或已过期 → 前端直接清除残留 token，跳转回教练登录页（pages/login/index）

## 6. 验收标准（业务级 Gherkin）

> US 等级：L1（0.2d，单一接口 + 前端清除逻辑）

### 6.1 场景 1：教练正常退出登录

```gherkin
Given 教练已登录且本地存在有效的 access_token 和 refresh_token
And   教练位于教练端「我的」页面
When  教练点击底部「退出登录」按钮
And   教练在弹窗中点击「确定」
Then  系统调用后端退出登录接口
And   后端将当前 coach_session/refresh_token 标记为失效
And   前端清除本地 access_token、refresh_token 及 expires_in
And   系统跳转回教练登录页（pages/login/index）
And   教练再次访问受登录态保护的接口时返回 401
```

### 6.2 场景 2：教练取消退出

```gherkin
Given 教练已登录且位于教练端「我的」页面
When  教练点击「退出登录」按钮
And   教练在弹窗中点击「取消」
Then  弹窗关闭
And   前端不调用后端退出登录接口
And   本地 token 保持不变
And   教练仍停留在「我的」页面且保持登录态
```

### 6.3 场景 3：本地 token 已过期或不存在

```gherkin
Given 教练位于教练端「我的」页面
And   本地 access_token 不存在或已过期
When  教练点击「退出登录」按钮并确认
Then  前端直接清除本地残留的 token
And   系统跳转回教练登录页（pages/login/index）
And   后端不执行任何 token 失效操作（无可失效 token）
```

## 8. 边界场景

### 8.1 边界场景 1：网络异常导致后端退出接口失败

- **触发条件**：教练确认退出时网络断开或后端超时
- **预期行为**：前端仍清除本地 token，跳转回教练登录页（pages/login/index）；服务端 token 按 TTL 自然过期
- **用户可见反馈**：页面从「我的」页面跳转回教练登录页，底部"退出登录"按钮不再显示

### 8.2 边界场景 2：教练快速重复点击退出登录

- **触发条件**：教练连续多次点击「退出登录」按钮
- **预期行为**：前端按钮点击后立即 disable + loading；后端接口幂等，仅执行一次 token 失效
- **用户可见反馈**：按钮显示"退出中..."，避免重复弹窗

### 8.3 边界场景 3：多设备登录场景

- **触发条件**：同一教练账号在多个设备登录
- **预期行为**：仅使当前设备/session 的 token 失效，不影响其他设备登录态
- **用户可见反馈**：当前设备退出登录，其他设备仍可正常使用

## 12. 备注

- **幂等键**：以当前 `access_token` / `refresh_token` hash 为幂等键，避免重复调用导致异常
- **事务边界**：后端标记 coach_session 失效 + 记录 logout 日志应在同一事务内
- **性能要求**：退出登录接口 P99 < 500ms
- **安全要求**：
  - 必须校验请求中的 token 属于当前登录教练
  - 退出后旧 access_token 和 refresh_token 均不可再用于访问受保护接口
  - 清除前端存储时需同时清除内存与持久化 storage
- **设计相关**：见 §13-15 Figma 相关章节

## 14. 页面级设计决策

> 本节是**本故事特殊**的设计选择，**全局规范**中没有定义的设计决策记录在这里。**禁止重复全局规范已定义的内容**。

### 14.1 退出登录入口位置

- **背景**：需要在教练端「我的」页面提供账号退出入口
- **选项**：A. 放在页面顶部个人资料区；B. 放在页面底部设置区；C. 放在页面最底部作为独立按钮
- **结论**：选择 C，将「退出登录」作为教练端「我的」页面最底部的独立按钮，视觉层级弱于主要功能入口，避免误触
- **影响范围**：教练端「我的」页面底部区域

### 14.2 二次确认方式

- **背景**：退出登录是破坏性操作，需防止误触
- **选项**：A. 点击后直接退出；B. 弹出确认弹窗
- **结论**：选择 B，弹出原生/自定义确认弹窗，含「确定」和「取消」两个按钮
- **影响范围**：退出登录交互流程

### 14.3 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 点击「退出登录」 | tap | 弹出二次确认弹窗 | 弹窗文案："确定要退出登录吗？" |
| 点击弹窗「确定」 | tap | 按钮 loading，调用后端接口，成功后清除 token 并跳转回教练登录页（pages/login/index） | 防重复点击 |
| 点击弹窗「取消」 | tap | 关闭弹窗，保持当前页面和登录态 | — |

## 2. 触发条件

- **触发方**：教练
- **触发动作**：在教练端填写请假时间段、原因并提交
- **触发时机**：用户主动操作，课程开始前可提交请假申请，已开始的课程不可请假

## 3. 前置条件

- [x] 教练已登录且 `coach.status = 1`（已通过）
- [x] 请假对应的课程尚未开始

---

## 4. 业务流程

### 4.1 主路径

1. 教练进入教练端「请假申请」页面
2. 选择请假开始时间与结束时间（最小粒度 1 小时）
3. 选填请假原因（如事假 / 病假）
4. 点击「提交申请」
5. 系统校验：教练状态合法、请假开始时间不早于当前时间、结束时间晚于开始时间、无冲突
6. 系统创建 `coach_leave` 记录，`status = 0`（待审批）
7. 系统返回「提交成功，等待管理员审批」

### 4.2 异常分支

- **请假时间冲突**：所选时间段与已有已批准请假重叠 → 返回错误码 `LEAVE_TIME_CONFLICT`
- **请假开始时间已过**：开始时间早于当前时间 → 返回错误码 `LEAVE_START_PAST`
- **结束时间早于开始时间**：结束时间 < 开始时间 → 返回错误码 `INVALID_TIME_RANGE`
- **教练状态不允许**：`coach.status ≠ 1` → 返回错误码 `COACH_STATUS_INVALID`

## 8. 边界场景

> 至少 3 个异常边界场景（如并发、权限越界、数据缺失、超时、空数据、极值等）

### 8.1 边界场景 1：教练快速重复提交

- **触发条件**：教练 3 秒内连续点击「提交申请」
- **预期行为**：幂等键去重，第二次请求返回已有请假单，不重复创建记录
- **用户可见反馈**：提示「请勿重复提交」

### 8.2 边界场景 2：结束时间早于开始时间

- **触发条件**：教练选择的结束时间 < 开始时间
- **预期行为**：前端/后端校验，返回错误码 `INVALID_TIME_RANGE`
- **用户可见反馈**：提示「结束时间不能早于开始时间」

### 8.3 边界场景 3：超长时间请假

- **触发条件**：请假跨度 > 30 天
- **预期行为**：允许提交，但标记为「管理员重点关注」
- **用户可见反馈**：提示「已提交，管理员将尽快处理」

### 8.4 边界场景 4：教练状态非已通过

- **触发条件**：`coach.status` 为待审核（0）、已驳回（2）、已离职（3）或申请离职中（4）
- **预期行为**：拒绝提交，返回错误码 `COACH_STATUS_INVALID`
- **用户可见反馈**：提示「当前状态不可提交请假申请」

## 14. 页面级设计决策

> 本节是**本故事特殊**的设计选择，**全局规范**中没有定义的设计决策记录在这里。**禁止重复全局规范已定义的内容**（如状态徽标颜色、字体、4 态模板）。

### 14.1 请假时间最小粒度

- **背景**：避免过短请假，与排班时段对齐
- **选项**：30 分钟 / 1 小时
- **结论**：最小粒度 1 小时，与 `schedule_slot` 时段粒度一致
- **影响范围**：教练端请假页时间选择器

### 14.2 请假原因输入

- **背景**：管理员审批时需要了解请假事由
- **选项**：必填 / 选填
- **结论**：选填，降低教练提交门槛；不填时默认显示「未填写」
- **影响范围**：教练端请假申请表单

### 14.3 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 选择时间 | 点击时间选择器 | 时间段高亮 | 最小粒度 1 小时 |
| 提交请假 | 点击「提交申请」 | loading → 成功页/错误提示 | 3 秒内防重复点击 |
| 时间冲突 | 提交冲突时段 | 弹窗提示「请假时间冲突，请重新选择」 | 不关闭已填内容 |

## 4. 业务流程

### 4.1 主路径

1. 管理员进入「用户管理 → 教练管理」
2. 系统展示教练列表，默认按创建时间（`coach.approved_at`）降序，支持按教练状态、实时状态、关键词筛选
3. 管理员搜索/筛选目标教练
4. 管理员执行以下任一操作：
   - **查看详情**：点击「查看」进入教练详情页，展示 coach 表生效资料（基础信息、实名与资质、教学履历、服务设置、证书列表）及该教练的审核/操作历史
   - **编辑资料**：点击「编辑资料」打开编辑弹窗，管理员可修改教练在入驻时填写的基础信息、教学履历、服务设置，以及实名与资质信息（如身份证、教练资格证、健康证、个人形象照等）；保存后更新 `coach` 表并记录审计日志
   - **新建教练**：点击「新建教练」，填写与教练端入驻资料一致的字段（基础信息 / 实名与资质 / 教学履历 / 服务设置），提交后 `coach.status = 1`（直接已通过），`approved_at` 为当前时间，并写入审计日志
   - **取消入驻**：对已通过的教练点击「取消入驻」，填写原因，系统更新 `coach.status = 3`（已离职），记录审计日志，并触发 US-041 中教练离职后的后续处理（如清空可约时段、解绑学员等，依赖 US-041）
5. 系统记录操作审计日志
6. 返回操作成功提示

### 4.2 异常分支

- **分支 1**：管理员无权限 → 返回错误码 `ADMIN_PERMISSION_DENIED`
- **分支 2**：查看详情 / 编辑资料 / 取消入驻时指定的 `coach_id` 不存在 → 返回错误码 `COACH_NOT_FOUND`（列表查询为空时正常返回空数组，不触发本错误）
- **分支 3**：新建教练时手机号已被占用，或编辑教练时手机号被其他教练占用 → 返回错误码 `PHONE_ALREADY_EXISTS`
- **分支 4**：新建教练时身份证已被占用，或编辑教练时身份证被其他教练占用 → 返回错误码 `ID_CARD_ALREADY_EXISTS`
- **分支 5**：取消入驻时教练不处于已通过状态 → 返回错误码 `COACH_STATUS_NOT_APPROVED`

## 6. 验收标准（业务级 Gherkin）

> 本 US 为 L2（1 人天），包含 4 个正常场景 + 3 个异常场景 = 7 个场景。

### 6.1 场景 1：管理员查看教练列表

```gherkin
Given 管理员 M 已登录且具有教练管理读权限
And   系统中存在 3 位已通过教练
When  管理员 M 进入「用户管理 → 教练管理」
Then  系统返回教练列表
And   列表每行展示教练 ID、姓名、性别、年龄、教学年限、擅长泳姿、创建时间、在职状态、实时状态
And   默认按创建时间降序排列
And   返回 HTTP 200
```

### 6.2 场景 2：管理员查看教练详情

```gherkin
Given 管理员 M 已登录且具有教练管理读权限
And   教练 C 已通过审核，coach_id=2001
When  管理员 M 在教练列表点击「查看」
Then  系统返回教练 C 的完整生效资料
And   页面展示基础信息（姓名、手机号、性别、年龄、邮箱、微信二维码）
And   页面展示实名与资质（身份证号、身份证正反面、教练资格证、健康证、个人形象照）
And   页面展示教学履历（任教年限、总学员数、总课时数、擅长泳姿、个人简介）
And   页面展示服务设置（参考单价）
And   页面展示该教练的审核/操作历史
And   返回 HTTP 200
```

### 6.3 场景 3：管理员编辑教练资料

```gherkin
Given 管理员 M 已登录且具有教练管理写权限
And   教练 C 已通过审核，coach_id=2001，当前简介为"专注成人游泳教学"
When  管理员 M 点击「编辑资料」
And   将简介修改为"专注成人与儿童游泳教学"
And   上传新的个人形象照
And   点击「保存」
Then  coach.bio 更新为"专注成人与儿童游泳教学"
And   coach_certificate 新增/更新个人形象照记录
And   coach.updated_at 更新
And   audit_log 新增 1 条 action='ADMIN_UPDATE_COACH_PROFILE' 记录
And   返回 HTTP 200 与提示"教练资料已更新"
```

### 6.4 场景 4：管理员新建教练

```gherkin
Given 管理员 M 已登录且具有教练管理写权限
And   手机号"13800138000"未被教练占用
When  管理员 M 点击「新建教练」
And   填写姓名"李教练"、性别"女"、年龄 28、手机号"13800138000"、邮箱"li@example.com"
And   上传身份证正反面、教练资格证、健康证、个人形象照
And   填写任教年限 5 年、擅长泳姿"自由泳、仰泳"、参考单价 300 元
And   点击「保存」
Then  coach 表新增 1 条记录，status=1，approved_at 为当前时间
And   coach_certificate 表新增该教练的资质证书记录
And   audit_log 新增 1 条 action='ADMIN_CREATE_COACH' 记录
And   返回 HTTP 200 与提示"教练已创建"
```

### 6.5 场景 5：管理员取消教练入驻

```gherkin
Given 管理员 M 已登录且具有教练管理取消入驻权限
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `coach` | 读取/修改/新增 | 查询列表与详情；编辑时更新基础信息、教学履历、服务设置；新建时直接写入已通过状态；取消入驻时更新 status=3 |
| 2 | `coach_certificate` | 读取/新增/修改 | 编辑/新建时维护教练资质证书 |
| 3 | `coach_audit_log` | 新增 | 记录新建、编辑、取消入驻等敏感操作 |
| 4 | `coach_application` | 读取 | 详情页展示该教练历史申请记录 |

### 7.2 API 影响

> 本 US 接口遵循 [API 接口规范](../../../tech/api-convention.md)：统一使用 `POST`，URL 按 `/list`、`/detail`、`/add`、`/update`、业务动作命名，参数通过 JSON body 传递。

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/admin/coach/list` | POST | 新增 | 教练管理列表；请求体 `{ page, pageSize, keyword, status, realtimeStatus }`；按创建时间降序 |
| 2 | `/api/admin/coach/detail` | POST | 新增 | 教练详情；请求体 `{ coachId }`；返回 coach 生效资料、证书列表、历史申请/操作记录 |
| 3 | `/api/admin/coach/add` | POST | 新增 | 新建教练；请求体包含完整入驻字段；直接 status=1 |
| 4 | `/api/admin/coach/update` | POST | 新增 | 编辑教练资料；请求体 `{ coachId, profile, certificates }` |
| 5 | `/api/admin/coach/cancelEntry` | POST | 新增 | 取消入驻；请求体 `{ coachId, reason }`； coach.status 更新为 3 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | coach.status | — → 1 | 管理员新建教练 | 直接已通过 |
| 2 | coach.status | 1 → 3 | 管理员取消入驻 | 教练离职 |
| 3 | coach.status | 1/2/3 → 1 | 管理员编辑资料 | 不改变 status，更新资料 |

## 8. 边界场景

### 8.1 边界场景 1：编辑手机号/身份证号重复

- **触发条件**：管理员将教练手机号或身份证号修改为已被其他教练占用的值
- **预期行为**：唯一性校验失败，返回 `PHONE_ALREADY_EXISTS` 或 `ID_CARD_ALREADY_EXISTS`
- **用户可见反馈**：字段级错误提示"该手机号/身份证号已被使用"

### 8.2 边界场景 2：取消入驻后教练仍有未完成的课程/订单

- **触发条件**：管理员取消一个仍有进行中学员套餐或未完成课程的教练入驻
- **预期行为**：允许取消入驻，但系统标记为"已离职"；后续学员约课、换教练流程由 US-022 / US-041 处理
- **用户可见反馈**：提示"教练已离职，请尽快为学员安排换教练"

### 8.3 边界场景 3：新建教练字段校验失败

- **触发条件**：管理员新建教练时必填项缺失或格式错误
- **预期行为**：返回字段级校验错误，不写入 coach 表
- **用户可见反馈**：表单对应字段显示错误信息

## 14. 页面级设计决策

### 14.1 列表页字段设计

- **背景**：教练管理与教练审核列表类似，但关注在职状态而非审核状态
- **结论**：列表展示教练 ID、姓名、性别、年龄、教学年限、擅长泳姿、创建时间、在职状态、实时状态；不展示头像，保持表格紧凑
- **影响范围**：A-coach-management-page.md 表格列

### 14.2 编辑资料范围

- **背景**：管理员编辑与教练端自行编辑的范围不同
- **结论**：管理员可编辑全部入驻字段（包括实名与资质），且无需重新走审核流程；教练端编辑实名与资质需重新审核（US-012 / US-010）
- **影响范围**：A-coach-edit-modal.md 字段可编辑性

### 14.3 取消入驻二次确认

- **背景**：取消入驻会影响学员约课与教练服务
- **结论**：点击「取消入驻」后弹出二次确认框，强制填写原因
- **影响范围**：教练管理列表页操作列

### 14.4 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 筛选教练 | 选择状态/实时状态/输入关键词 | 列表实时刷新 | 支持组合筛选 |
| 查看详情 | 点击「查看」或姓名 | 跳转 A-教练详情页 | 展示完整生效资料与历史 |
| 编辑资料 | 点击「编辑资料」 | 打开编辑弹窗 | 管理员可编辑全部字段 |
| 新建教练 | 点击「新建教练」 | 打开新建弹窗 | 字段与教练端入驻一致 |
| 取消入驻 | 点击「取消入驻」 | 二次确认弹窗 → 成功提示 | 仅已通过教练显示 |

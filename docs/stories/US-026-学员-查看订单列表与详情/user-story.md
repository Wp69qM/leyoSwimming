## 2. 触发条件

- **触发方**：学员
- **触发动作**：进入「我的订单」页面或点击某笔订单
- **触发时机**：用户主动查询时

## 3. 前置条件

- [x] 用户已登录（依赖 US-004 / US-005）
- [x] 用户存在至少一笔订单（依赖 US-020 / US-025）

---

## 4. 业务流程

### 4.1 主路径

1. 学员进入「我的订单」页面
2. 系统按时间倒序展示订单列表
3. 学员点击某笔订单进入详情
4. 系统展示订单金额、套餐信息、支付状态、创建时间、支付时间、退款入口

### 4.2 异常分支

- **分支 1**：用户无订单 → 展示空状态
- **分支 2**：订单被删除或不存在 → 返回 404

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常查看订单列表

```gherkin
Given 学员已登录且名下有 3 笔订单
When  学员进入「我的订单」页面
Then  列表按 created_at 倒序展示 3 笔订单
And   每笔订单展示订单号、金额、状态标签
And   状态标签支持 9 种：0-无 / 1-待支付(橙色) / 2-已支付(绿色) / 3-已取消(灰色) / 4-退款审批中(蓝色) / 5-争议退款处理中(紫色) / 6-已退款(深灰) / 7-退款被拒(红色) / 8-退款处理中(蓝色脉冲)
```

### 6.2 场景 2：无订单空状态

```gherkin
Given 学员已登录但名下无任何订单
When  学员进入「我的订单」页面
Then  页面展示空状态插画
And   展示文案"暂无订单"
```

### 6.3 场景 3：查看订单详情

```gherkin
Given 学员已登录且存在 order.status = 已支付的订单
When  学员点击该订单进入详情
Then  详情页展示订单号、套餐名称、教练姓名、金额、支付时间
And   展示「申请退款」入口
```

## 8. 边界场景

### 8.1 边界场景 1：越权访问他人订单

- **触发条件**：用户直接请求其他用户的 order_id
- **预期行为**：返回 403 FORBIDDEN
- **用户可见反馈**：提示"无权查看该订单"

### 8.2 边界场景 2：分页超出范围

- **触发条件**：用户请求页码超出实际数据页数
- **预期行为**：返回空数组 + HTTP 200
- **用户可见反馈**：列表底部显示"没有更多订单"

### 8.3 边界场景 3：订单详情中订单被退款

- **触发条件**：订单状态为已退款
- **预期行为**：详情页展示退款金额与退款时间
- **用户可见反馈**：状态标签显示"已退款"

## 14. 页面级设计决策

### 14.1 订单状态标签

> 对齐 PRD §6.2.1/§6.2.2 订单状态机（9 状态）。v3 评审 P0 修复：原仅 4 状态，现补全为 9 状态。

| 状态码 | 状态名 | 标签色 | 说明 |
|--------|--------|--------|------|
| 0 | 无 | — | 初始态，不展示 |
| 1 | 待支付 | 橙色 #FA8C16 | 等待用户支付 |
| 2 | 已支付 | 绿色 #52C41A | 支付成功 |
| 3 | 已取消 | 灰色 #BFBFBF | 用户/系统取消 |
| 4 | 退款审批中 | 蓝色 #1890FF | 管理员审核中 |
| 5 | 争议退款处理中 | 紫色 #722ED1 | 争议处理 |
| 6 | 已退款 | 深灰 #595959 | 终态 |
| 7 | 退款被拒 | 红色 #F5222D | 终态 |
| 8 | 退款处理中 | 蓝色脉冲 #1890FF | 中间态，等待渠道回调（PRD §6.2.2 新增） |

- 默认按创建时间倒序

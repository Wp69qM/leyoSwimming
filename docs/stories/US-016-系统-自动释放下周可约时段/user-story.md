## 4. 业务流程

### 4.1 主路径

1. 每周固定释放日（默认周三 10:00），定时任务触发
2. 系统读取 `status IN (1, 4)` 的教练列表（`status = 3` 已离职教练排除）
3. 系统为每位教练生成未来 7 天（下周整周）的 `schedule_slot` 记录
4. 每天生成 10:00、11:00、12:00、13:00、14:00、15:00、16:00、17:00、18:00、19:00、20:00 共 11 个时段，每个时段 1 小时
5. 系统将生成的 slot 状态设为 `available`
6. 系统记录释放日志

### 4.2 异常分支

- **分支 1**：某周释放任务漏执行 → 依赖兜底定时任务检测并补偿执行
- **分支 2**：重复释放 → 按 `(release_date, coach_id, start_time)` 幂等，跳过已存在的 slot
- **分支 3**：生成过程中某教练数据异常 → 跳过该教练并记录 warn 日志，不影响其他教练

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常释放未来一周时段

```gherkin
Given 当前为周三 10:00
And   系统配置为未来 7 天释放
And   教练 A 的 coach.status = 1
When  释放任务触发
Then  系统为教练 A 生成 77 条 schedule_slot 记录
And   每天 11 个 slot，时间分别为 10:00 至 20:00
And   每条 slot.status = "available"
And   系统记录 release_log 1 条，generated_slots = 77
```

### 6.2 场景 2：释放任务超时未执行

```gherkin
Given 上周释放任务因服务器宕机未执行
And   当前时间已超过上周释放时间 5 分钟
When  兜底定时任务每 5 分钟扫描一次
Then  任务检测到漏执行并立即补偿释放
And   生成对应 slot
```

### 6.3 场景 3：防止重复释放

```gherkin
Given 本周释放任务已执行成功
And   释放任务再次触发（如手动重跑）
When  系统检查 release_log 中本周已有 success 记录
Then  跳过本次释放
And   返回幂等响应 "本周已释放"
```

### 6.4 场景 4：已离职教练不生成 slot

```gherkin
Given 当前为周三 10:00
And   教练 C 的 coach.status = 3（已离职）
When  释放任务触发
Then  系统不为教练 C 生成任何 slot
And   release_log 中 generated_slots 不包含教练 C
```

### 6.5 场景 5：申请离职中教练继续释放

```gherkin
Given 当前为周三 10:00
And   教练 D 的 coach.status = 4（申请离职中）
When  释放任务触发
Then  系统为教练 D 生成 77 条 schedule_slot 记录
And   每条 slot.status = "available"
And   release_log 记录 generated_slots 包含教练 D 的 77 条 slot
```

## 8. 边界场景

### 8.1 边界场景 1：两名教练生成同一时间段

- **触发条件**：教练 A 与教练 B 的 slot 时间完全重合
- **预期行为**：分别生成，互不影响（按 coach_id 区分）
- **用户可见反馈**：学员可在预约页看到两位教练的可约时段

### 8.2 边界场景 2：大量教练并发释放

- **触发条件**：系统有 100+ 教练同时释放
- **预期行为**：任务分批处理，数据库连接池不耗尽
- **用户可见反馈**：释放延迟在 30 秒内

### 8.3 边界场景 3：部分教练生成异常

- **触发条件**：某教练数据异常导致生成 slot 失败
- **预期行为**：跳过该教练，不影响其他教练
- **用户可见反馈**：无（后台任务）

## 12. 备注

- **幂等键**：释放任务以 `(release_date)` 为幂等键，防止重复生成
- **事务边界**：单教练生成 slot 在同一事务内；跨教练不共享事务
- **性能要求**：100 名教练释放完成 P99 < 30s
- **兜底机制**：每 5 分钟扫描 `release_log`，检测漏执行并补偿
- **状态过滤**：仅对 `status IN (1, 4)` 教练生成 slot；`status = 3`（已离职）教练不生成，与 PRD §5.4.7 状态 4 行为表保持一致
- **本批次简化**：去除 `coach_availability_template` 与 `release_rule` 依赖，固定生成未来 7 天 10:00-20:00 时段

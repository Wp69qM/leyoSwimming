## 2. 触发条件

- **触发方**：系统
- **触发动作**：定时任务到达配置的释放时间
- **触发时机**：每周固定释放日（默认周三 10:00），或节假日提前释放日

---

## 3. 前置条件

- [x] 已存在 `release_rule` 配置（依赖 US-015）
- [x] 教练已维护可约时段模板（依赖 US-014）
- [x] 系统时钟与释放时间匹配
- [x] `status = 3`（已离职）教练不参与释放；`status = 4`（申请离职中）教练继续释放，以保障老学员约课

---

## 4. 业务流程

### 4.1 主路径

1. 定时任务扫描 `release_rule`，计算下一次释放时间
2. 到达释放时间后，任务触发
3. 系统读取 `status IN (1, 4)` 且未离职教练的可约时段模板（`status = 3` 已离职教练排除）
4. 系统按 `release_scope` 生成未来目标周期的 `schedule_slot` 记录
5. 系统将生成的 slot 状态设为 `available`
6. 系统记录释放日志，并发送释放完成通知给管理员
7. 首页倒计时重置为下一次释放时间

### 4.2 异常分支

- **分支 1**：某教练未设置模板 → 跳过该教练，记录 warn 日志
- **分支 2**：节假日闭馆 → 按 `holiday_release_offset_days` 提前/延后释放
- **分支 3**：释放时间服务器宕机 → 依赖兜底定时任务 5 分钟内补偿执行

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常释放下周整周时段

```gherkin
Given 当前为周三 10:00 且 release_rule 配置为释放下周整周
And   教练 A 已设置周一至周日 9:00-10:00 可约
When  释放任务触发
Then  系统生成 coach_id=A 的 7 条 schedule_slot 记录
And   每条 slot.status = "available"
And   slot.start_time 覆盖下周一到周日 9:00
And   系统记录 release_log 1 条，generated_slots = 7
```

### 6.2 场景 2：节假日提前释放

```gherkin
Given release_rule.holiday_release_enabled = true
And   holiday_release_offset_days = -1
And   下周一为法定节假日
When  系统计算释放时间
Then  释放任务于本周二 10:00 触发
And   生成下周一闭馆日之外的可用 slot
```

### 6.3 场景 3：教练未设置模板

```gherkin
Given 释放任务触发
And   教练 B 的可约时段模板为空
When  系统读取教练 B 的模板
Then  系统跳过教练 B 且不生成 slot
And   记录 warn 日志 "coach_id=B 无可用模板"
```

### 6.4 场景 4：释放任务超时未执行

```gherkin
Given 上次释放任务因服务器宕机未执行
And   当前时间已超过上次释放时间 5 分钟
When  兜底定时任务每 5 分钟扫描一次
Then  任务检测到漏执行并立即补偿释放
And   生成对应 slot
```

### 6.5 场景 5：防止重复释放

```gherkin
Given 本周释放任务已执行成功
And   释放任务再次触发（如手动重跑）
When  系统检查 release_log 中本周已有 success 记录
Then  跳过本次释放
And   返回幂等响应 "本周已释放"
```

### 6.6 场景 6：申请离职中教练继续释放

```gherkin
Given 当前为周三 10:00
And   教练 D 的 coach.status = 4（申请离职中）
And   教练 D 已设置周一至周日 10:00-11:00 可约
When  释放任务触发
Then  系统为教练 D 生成 7 条 schedule_slot 记录
And   每条 slot.status = "available"
And   release_log 记录 generated_slots 包含教练 D 的 7 条 slot
```

## 8. 边界场景

### 8.1 边界场景 1：部分教练模板冲突

- **触发条件**：两名教练模板生成同一时间段但不冲突（不同 coach_id）
- **预期行为**：分别生成，互不影响
- **用户可见反馈**：学员可在预约页看到两位教练的可约时段

### 8.2 边界场景 2：闭馆日处理

- **触发条件**：下周某日为闭馆日
- **预期行为**：该日不生成 slot
- **用户可见反馈**：学员端该日期不展示可约时段

### 8.3 边界场景 3：大量教练并发释放

- **触发条件**：系统有 100+ 教练同时释放
- **预期行为**：任务分批处理，数据库连接池不耗尽
- **用户可见反馈**：释放延迟在 30 秒内

## 12. 备注

- **幂等键**：释放任务以 `(release_date, release_scope)` 为幂等键，防止重复生成
- **事务边界**：单教练模板生成 slot 在同一事务内；跨教练不共享事务
- **性能要求**：100 名教练释放完成 P99 < 30s
- **兜底机制**：每 5 分钟扫描 `release_log`，检测漏执行并补偿
- **状态过滤**：仅对 `status IN (1, 4)` 教练生成 slot；`status = 3`（已离职）教练不生成，与 PRD §5.4.7 状态 4 行为表保持一致

## 4. 业务流程

### 4.1 主路径

1. 学员进入「预约」页面，系统默认展示已绑定教练未来 7 天的可约时段
2. 学员选择日期与时段
3. 系统校验：套餐 active、available_count > 0、时段有效且空闲、无冲突预约
4. 系统按 FIFO 选择最早 active 套餐，预占 1 课时：available_count -1，reserved_count +1
5. 系统创建 booking 记录，status = 已预约
6. 系统返回预约成功详情，并发送提醒

### 4.2 异常分支

- **分支 1**：时段已被他人预约 → 返回错误码 `SLOT_TAKEN`
- **分支 2**：套餐无可用课时 → 返回错误码 `NO_QUOTA`
- **分支 3**：未绑定教练 → 返回错误码 `NO_BOUND_COACH`
- **分支 4**：目标时段不在可约范围内（>7 天或已过期）→ 返回错误码 `SLOT_NOT_AVAILABLE`
- **分支 5**：套餐处于退款审批中 / 冻结 → 返回错误码 `PACKAGE_NOT_BOOKABLE`

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常预约已绑定教练时段

```gherkin
Given 学员已登录
And   存在 active 套餐，available_count = 5，coach_id = 100
And   已绑定教练 100 在明日 9:00 有可约时段
When  学员选择明日 9:00 并提交预约
Then  booking 创建成功，status = 已预约
And   package.reserved_count = 1，available_count = 4
And   返回预约详情
And   HTTP 状态码 = 201
```

### 6.2 场景 2：时段已被预约

```gherkin
Given 学员已登录
And   明日 9:00 时段已被其他学员预约
When  学员尝试预约明日 9:00
Then  系统返回 HTTP 400，错误码 SLOT_TAKEN
And   package 课时不变
```

### 6.3 场景 3：套餐可用课时不足

```gherkin
Given 学员已登录
And   active 套餐 available_count = 0
When  学员尝试预约
Then  系统返回 HTTP 400，错误码 NO_QUOTA
And   不创建 booking
```

### 6.4 场景 4：未绑定教练

```gherkin
Given 学员已登录
And   名下无 active 正价套餐或套餐 coach_id 为空
When  学员进入预约页
Then  系统返回 HTTP 400，错误码 NO_BOUND_COACH
And   提示"请先购买并绑定教练"
```

### 6.5 场景 5：重复提交预约

```gherkin
Given 学员已登录
And   已成功预约明日 9:00
When  学员再次提交同一时段预约（同 idempotency_key）
Then  系统返回 HTTP 409，错误码 DUPLICATE_BOOKING
And   不重复创建 booking
And   package 课时不变
And   响应体返回已存在的 booking_id
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `package` | 修改 | available_count -1，reserved_count +1 |
| 2 | `booking` | 新增 | status = 已预约 |
| 3 | `schedule_slot` | 读 | 校验时段有效 |
| 4 | `user` | 读 | 校验学员身份 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/bookings` | POST | 新增 | 提交正课预约 |
| 2 | `/api/coaches/{coach_id}/slots` | GET | 读取 | 获取可约时段（可复用 US-014）|
| 3 | `/api/packages/active` | GET | 读取 | 获取当前学员 active 套餐列表 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `booking` | 无 → 已预约 | 提交预约成功 | 预占课时 |
| 2 | `package` | available → reserved | 预约成功 | FIFO 扣减 |

## 8. 边界场景

### 8.1 边界场景 1：多人并发预约同一时段

- **触发条件**：两名学员同时提交同一时段预约
- **预期行为**：数据库唯一索引 / 分布式锁保证仅第一个成功，其余返回 SLOT_TAKEN
- **用户可见反馈**："该时段已被他人预约，请选择其他时段"

### 8.2 边界场景 2：教练请假导致时段关闭

- **触发条件**：提交瞬间教练请假审批通过，schedule_slot.status = closed
- **预期行为**：预约接口拒绝，返回 SLOT_NOT_AVAILABLE
- **用户可见反馈**："该时段已不可用"

### 8.3 边界场景 3：网络抖动导致重复提交

- **触发条件**：前端重试导致同一请求多次到达
- **预期行为**：幂等键去重，返回已有 booking
- **用户可见反馈**：预约成功页

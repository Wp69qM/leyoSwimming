## 2. 触发条件

- **触发方**：教练
- **触发动作**：在教练端点击「上课记录」入口；或在预约页点击某个学员的「查看记录」
- **触发时机**：教练主动查看学员历史记录

---

## 3. 前置条件

- [x] 教练已登录且账号状态正常（依赖 US-011 / US-012）
- [x] 存在由该教练确认过的 course_record（依赖 US-033）

---

## 4. 业务流程

### 4.1 主路径

1. 教练进入「上课记录」页面
2. 系统展示教练名下所有有上课记录的学员筛选列表
3. 教练选择某个学员，或默认展示全部学员记录
4. 系统按上课时间倒序展示该学员的历史上课记录
5. 每条记录展示：上课时间、学习泳姿、课程内容、掌握程度、学员课后总结
6. 教练点击某条记录可查看完整详情

### 4.2 异常分支

- **分支 1**：当前教练无任何上课记录 → 展示空状态
- **分支 2**：选择学员后无记录 → 展示该学员空状态
- **分支 3**：非本教练学员 → 返回 403 或不展示在筛选列表中

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：正常查看某学员上课记录

```gherkin
Given 教练已登录
And   学员 A 有 3 条由该教练确认的 course_record
When  教练在筛选器中选择学员 A
Then  系统按上课时间倒序展示 3 条上课记录
And   每条记录展示上课时间、学习泳姿、课程内容、掌握程度
And   HTTP 状态码 = 200
```

### 6.2 场景 2：默认展示全部学员记录

```gherkin
Given 教练已登录
And   教练名下有学员 A 的 2 条记录和学员 B 的 1 条记录
When  教练进入上课记录页且未选择学员
Then  系统按上课时间倒序展示 3 条记录
And   每条记录展示学员姓名
```

### 6.3 场景 3：无记录时展示空状态

```gherkin
Given 教练已登录
And   该教练尚未确认任何课程
When  教练进入上课记录页
Then  系统展示空状态插画与提示"暂无上课记录"
```

### 6.4 场景 4：查看学员课后总结

```gherkin
Given 教练已登录
And   存在一条已确认的 course_record
And   学员已填写课后总结
When  教练查看该条记录详情
Then  系统展示学员的身体感受、学习效果、问题反馈
```

### 6.5 场景 5：非本教练学员不可见

```gherkin
Given 教练 A 已登录
And   学员 C 只与教练 B 有过课程记录
When  教练 A 尝试查看学员 C 的上课记录
Then  系统返回 HTTP 403
And   学员 C 不出现在教练 A 的筛选列表中
```

## 8. 边界场景

### 8.1 边界场景 1：大量历史记录

- **触发条件**：某学员有几十条上课记录
- **预期行为**：分页加载，避免一次性返回过多数据
- **用户可见反馈**：列表底部展示加载更多提示

### 8.2 边界场景 2：学员改名或更换头像

- **触发条件**：学员在 US-005 中更新了资料
- **预期行为**：上课记录展示最新姓名与头像
- **用户可见反馈**：记录中显示最新资料

### 8.3 边界场景 3：课程记录被误标旷课后修正

- **触发条件**：管理员通过 US-035 返还课时并将 booking 状态修正
- **预期行为**：上课记录列表按最终状态展示
- **用户可见反馈**：记录状态与实际情况一致

## 14. 页面级设计决策

### 14.1 筛选器设计

- 顶部展示学员筛选器，默认「全部学员」
- 点击筛选器展开学员列表弹窗或下拉
- 学员列表仅包含与该教练有过上课记录的学员

### 14.2 记录列表信息结构

- 上课时间（日期 + 具体时段）
- 学员头像 + 姓名
- 学习泳姿
- 课程内容摘要
- 掌握程度标签
- 学员课后总结摘要（如有）

### 14.3 详情页内容

- 课程信息组：上课时间、学员、关联套餐
- 教练记录组：完整课程内容、重点、掌握程度、作业、媒体
- 学员总结组：身体感受、学习效果、问题反馈

### 14.4 页面级交互说明

| 交互 | 触发 | 反馈 | 备注 |
|------|------|------|------|
| 选择学员 | 点击筛选器 | 列表刷新为该学员记录 | |
| 点击记录 | 列表页 | 进入记录详情页 | |
| 返回列表 | 详情页 | 回到上课记录列表 | |

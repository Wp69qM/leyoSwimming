## 2. 触发条件

- **触发方**：教练
- **触发动作**：在教练端为已绑定学员选择可约时段并提交代约，或在预约详情页为学员改约其他时段
- **触发时机**：学员明确授权后，教练主动代为操作时

## 3. 前置条件

- [x] 教练已登录且资质已通过（依赖 US-011 / US-012）

## 4. 业务流程

### 4.1 主路径 — 教练代约

1. 教练在教练端进入「学员管理」或「预约管理」，选择目标学员
2. 系统校验学员身份、套餐状态、可用课时及教练与学员的绑定关系
3. 教练浏览该学员已绑定教练（即自己）的未来 7 天可约时段
4. 教练选择时段并提交代约
5. 系统判断代约时间窗：
   - 开课时间 ≥24h：直接按 FIFO 选择最早 active 套餐，预占 1 课时：available_count -1，reserved_count +1
   - 开课时间 <24h：向学员发送代约确认请求；学员在系统内明确确认后，再按 FIFO 预占课时并创建 booking；学员未确认则不预占课时、不创建 booking（项目约定：PRD §5.4.2 第4条仅规定"教练可帮学员代约，按正常预约规则从学员课时包预占 1 课时"，未明确 <24h 代约是否需学员确认；为防范教练越权代约与学员利益受损，本 US 约定 <24h 代约需学员明确确认，与 §4.2 改约规则保持一致）
6. 系统创建 booking 记录（确认完成后），status = 已预约，记录操作来源为 coach
7. 系统写入/更新 `coach_authorization` 记录，记录授权学员、被授权教练、授权动作（book/reschedule）、授权时间，确保可审计
8. 系统通知学员「教练已为您预约 X 月 X 日 XX:XX 课程」
9. 返回预约成功详情

### 4.2 主路径 — 教练改约

1. 教练在教练端打开学员已有的待上课预约
2. 系统校验 booking.status ∈ {已预约, 待上课}
3. 系统判断改约时间窗：
   - 开课时间 ≥24h：教练可直接改约
   - 开课时间 <24h：系统向学员发送改约确认请求，学员在系统内明确同意后方可继续；若学员未在有效期内确认或拒绝，则改约请求失效，原 booking 保持原状
4. 教练点击「改约」，选择新的可约时段
5. 系统先取消原预约（释放预占课时），再按新时段创建新预约
6. 系统通知学员原预约已取消、新预约已创建
7. 返回改约后的 booking 详情

### 4.3 异常分支

- **分支 1**：时段已被他人预约 → 返回错误码 `SLOT_TAKEN`
- **分支 2**：套餐无可用课时 → 返回错误码 `NO_QUOTA`
- **分支 3**：学员未绑定当前教练 → 返回错误码 `NO_BOUND_COACH`
- **分支 4**：目标时段不在可约范围内 → 返回错误码 `SLOT_NOT_AVAILABLE`
- **分支 5**：改约时 booking 已取消 / 已完成 / 旷课 → 返回 `BOOKING_NOT_RESCHEDULABLE`
- **分支 6**：非授权教练操作 → 返回 403

## 6. 验收标准（业务级 Gherkin）

### 6.1 场景 1：教练成功代约正价课程

```gherkin
Given 教练已登录且 coach_id = 100
And   学员 A 已绑定教练 100，存在 active 套餐 available_count = 5
And   教练 100 在明日 9:00 有可约时段
When  教练为学员 A 提交明日 9:00 代约
Then  booking 创建成功，status = 已预约，operator = coach
And   package.reserved_count = 1，available_count = 4
And   学员 A 收到代约成功通知
And   HTTP 状态码 = 201
```

### 6.2 场景 2：教练成功改约正价课程

```gherkin
Given 教练已登录
And   学员 A 已存在 booking.status = 已预约，开课时间为明日 9:00
And   明日 14:00 有可约时段
When  教练为学员 A 提交改约到明日 14:00
Then  原 booking.status = 已取消，package 原课时释放
And   新 booking 创建成功，status = 已预约，operator = coach
And   package.reserved_count 保持 1，available_count = 4
And   学员 A 收到改约通知
And   HTTP 状态码 = 200
```

### 6.3 场景 3：时段已被他人预约

```gherkin
Given 教练已登录
And   明日 9:00 时段已被其他学员预约
When  教练尝试为学员 A 代约明日 9:00
Then  系统返回 HTTP 400，错误码 SLOT_TAKEN
And   package 课时不变
```

### 6.4 场景 4：学员未绑定当前教练

```gherkin
Given 教练已登录且 coach_id = 100
And   学员 B 的套餐绑定 coach_id = 200
When  教练 100 尝试为学员 B 代约
Then  系统返回 HTTP 400，错误码 NO_BOUND_COACH
And   不创建 booking
```

### 6.5 场景 5：改约时 booking 已取消

```gherkin
Given 教练已登录
And   学员 A 的 booking.status = 已取消
When  教练尝试为该 booking 改约
Then  系统返回 HTTP 400，错误码 BOOKING_NOT_RESCHEDULABLE
And   不创建新 booking
```

### 6.6 场景 6：距开课不足 24 小时改约且学员未确认

```gherkin
Given 教练已登录
And   学员 A 已存在 booking.status = 已预约，开课时间为明日 10:00
And   当前时间为明日 2:00（距开课 8 小时，<24h）
And   明日 14:00 有可约时段
When  教练为学员 A 提交改约到明日 14:00
Then  系统返回 HTTP 202，改约进入待确认状态
And   原 booking.status 保持 已预约
And   系统向学员 A 发送改约确认通知

When  学员 A 未在有效期内确认改约
Then  改约请求自动失效
And   原 booking.status 仍保持 已预约
And   不创建新 booking
And   系统通知教练「学员未确认改约，预约保持原状」
```

## 7. 数据/API/状态机影响

### 7.1 数据表影响

| # | 表名 | 操作 | 说明 |
|---|------|------|------|
| 1 | `package` | 修改 | 代约时 available_count -1，reserved_count +1；改约时先释放再预占 |
| 2 | `booking` | 新增/修改 | 代约新增 status = 已预约；改约更新原 booking 为已取消并新增 booking |
| 3 | `schedule_slot` | 读 | 校验时段有效 |
| 4 | `user` | 读 | 校验学员身份 |
| 5 | `coach_student` | 读 | 校验教练与学员绑定关系 |
| 6 | `coach_authorization` | 新增 | 记录学员对教练的代约/改约授权，确保可审计 |

### 7.2 API 影响

| # | API | 方法 | 操作 | 说明 |
|---|-----|------|------|------|
| 1 | `/api/coach/bookings` | POST | 新增 | 教练代约正价课程 |
| 2 | `/api/coach/bookings/{booking_id}/reschedule` | POST | 新增 | 教练为学员改约 |
| 3 | `/api/coaches/{coach_id}/slots` | GET | 读取 | 获取可约时段（复用 US-014）|
| 4 | `/api/coach/students/{student_id}/packages` | GET | 读取 | 获取学员 active 套餐 |

### 7.3 状态机影响

| # | 实体 | 转换 | 触发条件 | 说明 |
|---|------|------|---------|------|
| 1 | `booking` | 无 → 已预约 | 教练代约成功 | 预占课时，来源为 coach |
| 2 | `booking` | 已预约 → 已取消 | 教练改约释放原预约 | 课时回滚 |
| 3 | `package` | available → reserved | 代约成功 | FIFO 扣减 |

## 8. 边界场景

### 8.1 边界场景 1：多人并发预约同一时段

- **触发条件**：教练与学员同时提交同一时段预约
- **预期行为**：数据库唯一索引 / 分布式锁保证仅第一个成功，其余返回 SLOT_TAKEN
- **用户可见反馈**：教练端提示"该时段已被预约，请选择其他时段"

### 8.2 边界场景 2：改约时学员套餐课时刚好用完

- **触发条件**：改约释放原课时后，套餐 available_count 临时增加，新时段预约成功
- **预期行为**：整个改约操作在事务内完成，package 始终满足 reserved + consumed + available = total_hours
- **用户可见反馈**：改约成功页展示新预约详情

### 8.3 边界场景 3：教练代约后学员自行取消

- **触发条件**：教练代约成功，学员在课前 24 小时外自行取消
- **预期行为**：按 US-030 取消规则释放课时，booking.status → 已取消
- **用户可见反馈**：学员端显示"已取消"

### 8.4 边界场景 4：改约确认超时

- **触发条件**：教练在距开课 <24h 时提交改约，学员未在有效期内确认
- **预期行为**：改约请求失效，原 booking 保持原状，不创建新 booking
- **用户可见反馈**：教练端提示"学员未确认改约，预约保持原状"；学员端显示原预约未变更

## 14. 页面级设计决策

### 14.1 代约入口

- 教练端「学员管理」展示每个学员的「代约」按钮
- 进入代约页默认展示该学员已绑定教练的可约时段

### 14.2 改约入口

- 教练端预约卡片详情中，对已预约/待上课状态展示「改约」按钮
- 改约流程：选择新时段 → 二次确认「原预约将取消」→ 提交

### 14.3 学员通知

- 代约/改约成功后，通过小程序订阅消息通知学员
- 通知内容包含课程时间、教练姓名、操作人

# 需求池

description: 记录所有产品需求，包括功能需求、非功能需求、业务需求等。
将过程中的好的想法，但不是mvp必须实现的需求，记录在需求池。

1. 学员改约
description: 学员在预约时间内，因个人原因需要变更预约时间。
必要性：有其他可替代的方案：学员先取消预约，然后重新预约其他时间段的

2. 视频广场的概念
description: 提供一个视频平台，教练可以上传教学视频，学员可以查看和学习。
其他的注册用户也可以上传游泳视频，就类似短视频的平台一样，大家都可以上传自己的游泳视频，大家也可以刷到别人的游泳视频。可以点赞，收藏，评论，关注用户。可以显示视频的点击量。

3. 埋点
description: 为了分析用户行为，需要在关键操作点埋点。查看点击量，分析数据
必要性：分析用户行为，优化产品功能。

4. 提供一个意见反馈的渠道
description: 学员和教练可以在产品中提供意见和建议，需要有一个渠道来收集和处理这些反馈。
必要性：收集用户反馈，改进产品功能和用户体验。

5. 后台管理系统-用户管理详情查看
description: 后台管理系统中，用户查看详情还是需要查看用户的最近训练记录的。还有关联的套餐卡，每个套餐卡用了几次，什么时候用的。有效期是什么时候，等等

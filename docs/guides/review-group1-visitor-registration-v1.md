## 5. 本组 MVP 逻辑通顺性总结

### 5.1 主线流程

本组覆盖 MVP 能力「1 游客浏览」与「2 注册登录」：

```
游客浏览教练/套餐/场馆/倒计时（US-001~003）
    ↓ 触发登录/注册
微信授权登录（US-004）→ 隐私协议同意（US-009）→ 补充注册资料（US-005）
    ↓
账号安全设置（US-008）← 手机号/密码登录（US-006）
    ↓
账号注销（US-007）
```

### 5.2 依赖关系检查

- INDEX 中 US-005 前置依赖 `US-004, US-009`，US-008 前置依赖 `US-005`，US-009 前置依赖 `US-004`，无循环依赖。
- US-003 仅依赖 US-015（release_rule 配置），与 INDEX 一致，倒计时展示可与 US-016 释放执行解耦。
- US-006 在 INDEX 中标记为无前置 US，但实现上依赖 US-005 产生的手机号/用户名/密码数据；建议在实现计划中明确数据预置条件，无需修改 INDEX。

### 5.3 状态机覆盖

- **用户身份状态机**：US-004 触发 `游客 → 注册用户`；US-005 触发 `profile_completed false → true`；US-007 触发 `正常(0) → 软删除(1)`；US-020 后续触发 `注册用户 → 学员`。
- **隐私授权状态机**：US-009 触发 `未同意 → 已同意 → 已撤回`。
- **会话状态机**：US-004/US-006 触发 `未登录 → 已登录`；US-008 触发 `有效 → 失效`（设备下线）。

### 5.4 关键风险点

1. **数据模型冲突**：US-005/US-006 的 `user.status` 与 `identity` 字段定义若不及时修正，将直接污染后续购课、预约、退款等 30+ US 的实现。
2. **登录态一致性**：US-008 修改密码后的会话失效策略未明确，可能导致 US-004/US-006 的 `user_session` 表实现不一致。
3. **隐私协议前置**：US-005 依赖 US-009 的同意状态，但 US-009 的技术设计尚未细化版本比对与功能受限清单。

## 1. 设计文件顶层划分

按「端」拆分为 **3 个顶级 Figma 文件**（建议），每个文件内部按「流程 → 页面 → 状态」三级组织。

| 文件 | 端 | PRD 页面编号 | 页面数量 | Figma 文件名 |
|------|----|-------------|---------|-------------|
| `leyoSwimming-user-miniapp` | 用户端小程序 | 1 ~ 21 | 21 | `leyoSwimming-用户端小程序` |
| `leyoSwimming-coach-miniapp` | 教练端小程序 | 22 ~ 35 | 14 | `leyoSwimming-教练端小程序` |
| `leyoSwimming-admin-web` | 管理端 Web | 36 ~ 55 | 20 | `leyoSwimming-管理端Web` |

> 如果设计师倾向于单文件多 Page，也可在单一文件内按「端」建 Page，但 Frame 命名规则不变。

## 2. Frame 层级：端 → 流程 → 页面 → 状态

每个 Figma 文件 / Page 内部结构如下：

```
📁 端（文件/Page）
  └── 🗂️ 流程 Section
        ├── 📄 页面 Frame
        │     ├── empty      空状态子 Frame
        │     ├── loading    加载状态子 Frame
        │     ├── error      错误状态子 Frame
        │     └── success    成功状态子 Frame
        └── 📄 页面 Frame
              └── ...
```

### 2.1 Section 命名规范

Section 对应「流程」，命名规则：

```
<两位序号>-<流程名>
```

示例：
- `01-游客浏览`
- `02-注册登录`
- `03-购买与支付`

### 2.2 页面 Frame 命名规范

页面 Frame 命名规则：

```
<端缩写>-<页面名>
```

| 端 | 缩写 | 示例 |
|----|------|------|
| 用户端小程序 | `U` | `U-首页` |
| 教练端小程序 | `C` | `C-教练主页` |
| 管理端 Web | `A` | `A-教练审核列表` |

### 2.3 状态子 Frame 命名规范

每个页面下必须包含 4 个状态子 Frame，命名规则：

```
<US编号>-<页面名>-<状态>
```

状态取值：`empty` / `loading` / `error` / `success`。

示例：
- `US-001-教练列表页-empty`
- `US-001-教练列表页-loading`
- `US-001-教练列表页-error`
- `US-001-教练列表页-success`

> 若一个页面由多个 US 共享，使用主要 US 编号；在 [us-batch-handoff.md](./us-batch-handoff.md) 的映射表中标注共享关系。

## 4. 四态模板规范

所有页面 Frame 必须包含 4 个状态子 Frame。四态定义继承自 [docs/figma/README.md](./README.md) §4，本节补充 Frame 布局与截图规范。

| 状态 | 触发条件 | 截图要点 | 命名后缀 |
|------|---------|---------|---------|
| **empty** | 数据为空 | 居中插画 + 提示文案 + 可选 CTA | `-empty` |
| **loading** | 数据请求中 | Skeleton 占位，禁止仅居中 Spinner | `-loading` |
| **error** | 网络/接口/业务错误 | 居中插画 + 错误文案 +「重试」按钮 | `-error` |
| **success** | 数据正常/操作成功 | 完整内容展示 | `-success` |

### 4.1 状态子 Frame 尺寸

| 端 | 基础尺寸 | 说明 |
|----|---------|------|
| 用户端小程序 | 375 × 812 | iPhone SE 为最小适配，设计稿按 375 宽度 |
| 教练端小程序 | 375 × 812 | 与用户端一致 |
| 管理端 Web | 1440 × 900 | 1280 / 1440 / 1920 三档断点，按 1440 设计 |

### 4.2 状态截图导出规范

导出命名：

```
<US编号>-<页面名>-<状态>.png
```

示例：
- `US-001-教练列表页-empty.png`
- `US-001-教练列表页-loading.png`

导出位置：建议 Figma 库内建立 `/screenshots/<US编号>/` 页面统一归档。

## 5. Token 与组件库引用

本节不重复定义 Token/组件/徽标，仅说明如何在 Figma 中引用 L1 规范。

### 5.1 Token 使用要求

- 所有颜色、字体、间距必须使用 [README.md](./README.md) §1 定义的 Token
- Figma 中建议建立 `leyoSwimming Design Tokens` 变量库，三个端文件均引用
- 禁止在 Frame 中写死色值

### 5.2 组件库引用要求

- 使用 [README.md](./README.md) §2 定义的组件库
- 组件实例命名保持默认，仅在 override 中修改文案/状态
- 自定义组件需经设计负责人评审后入库

### 5.3 状态徽标引用

- 教练实时状态徽标：5 种（空闲中/上课中/休息中/已下班/请假中）
- 套餐状态徽标：5 种（使用中/已耗尽/已过期/已退款/已冻结）
- 订单状态徽标：7 种
- 教练入职状态徽标：5 种

详见 [README.md](./README.md) §3。

## 6. 交付物 Checklist

每个页面设计完成后，设计师需自检以下项目：

- [ ] Frame 按「端 → 流程 → 页面 → 状态」四级组织
- [ ] 页面 Frame 命名符合 `<端缩写>-<页面名>` 规范
- [ ] 状态子 Frame 命名符合 `<US编号>-<页面名>-<状态>` 规范
- [ ] 空 / 加载 / 错误 / 成功 四态齐全
- [ ] 颜色/字体/间距使用 Token，未硬编码
- [ ] 组件来自统一组件库
- [ ] 状态徽标符合 [README.md](./README.md) §3 定义
- [ ] 截图已按命名规范导出并归档
- [ ] 对应 US 的 `user-story.md` §13 已回填 Figma 链接与 node-id
- [ ] 对应 US 的 `user-story.md` §15 已记录设计评审结论

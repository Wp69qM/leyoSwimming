## 2. 待办任务清单

### 任务 1：按 api-convention 修正 API 路径与技术设计

**目标**：让所有 US 的 API 命名统一符合 [docs/tech/api-convention.md](../tech/api-convention.md) 的 RPC over HTTP 规范。

**检查与修改范围**：
- 每个 US `user-story.md` 中 API 影响表
- 每个 US `tech-design.md` 中 API 设计
- 每个 US `test-plan.md` 中引用的接口路径（如有）

**规范要点**：
- 统一使用 `POST`
- URL 结构：`/api/{模块}/{资源单数}/{动作}`
- 禁止 URL 路径参数：`{id}` 改为 JSON body 中的 `{资源}Id`
- 常用动作：`list`、`detail`、`add`、`update`、`delete`、业务动词（`upload`/`toggle`/`ingest`/`rebuild` 等）
- ID 字段命名使用 lowerCamelCase，如 `documentId`、`knowledgeId`

**输出**：每个 US 的 API 表与 tech-design 中所有接口路径符合规范，无路径参数残留。

## 5. 核心规则摘要

1. **文档格式**：MVP 阶段仅支持 `.txt` / `.markdown` / `.md` 文件上传与手动输入。
2. **权限控制**：仅 ADMIN 角色可进入知识库管理页，进行上传、启用/禁用、删除操作。
3. **标题唯一**：知识库文档标题全局唯一，重复标题不允许上传。
4. **启用/禁用同步向量库**：禁用文档后，ai-service 向量库中对应 chunk 需被移除；启用时重新构建索引。
5. **删除清理向量库**：删除文档需同时清理 MySQL 元数据和 Chroma 向量库。
6. **检索规则**：仅检索 `status = 0` 的启用文档；相似度阈值 0.7，低于则视为无匹配。
7. **联网搜索兜底**：知识库无有效匹配时，自动调用 Tavily 搜索；回答需标注"以下内容来自网络，仅供参考"。
8. **推荐类问题不走知识库**：用户询问教练/课程/套餐推荐时，仍调用现有 `recommendation_tools`。
9. **错误降级**：向量库或 Tavily 失败时，返回友好提示，不阻塞对话。

# 页面规格：U-支付页

> **性质**：Figma 设计交付的唯一指令源。AI 生成 Figma 时**必须**按本规格严格执行。
> **核心约束**：本规格的每一条元素显隐规则必须可追溯到 [PRD](../../prd/prd.md) 或具体 US 的某条业务规则。
> **归属 US**：US-017 / US-020 / **US-025（支付与 Mock 回调）** / US-045
> **对应 PRD**：§3.3 身份转换、§4.2 套餐状态机、§5.3.4 购买与支付、§6.2 订单状态机、§12.2 支付链路、§13.3 MVP 页面清单第 12 项
> **版本**：v1.3 | **创建日期**：2026-08-13 | **更新日期**：2026-08-14
> **特别说明**：MVP 使用 Mock 支付渠道同时支持微信与支付宝；不真正调起微信/支付宝 SDK。支付页是支付流程关键页，必须清晰展示订单号、应付金额、支付倒计时，避免用户误操作。

## 2. 用户身份与业务状态维度

> **本节是 Page Spec 根基**。先定义"谁可能看到这个页面"以及"以什么业务状态看到"。
> 身份定义来源：[PRD §3.2](../../../docs/prd/prd.md) 与 [US-025](../../../docs/stories/US-025-学员-支付套餐订单/user-story.md)。

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| **游客** | 否 | 支付必须先登录；游客不会直接到达本页 |
| **注册用户** | 是 | 支付体验课/正价套餐订单 |
| **学员** | 是 | 为当前教练加课支付或首次购买支付 |
| **教练/管理员（以用户身份进入）** | 是 | 按其实际用户身份处理，不显示管理态 |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| `order.status = 1` 待支付 | 订单未支付 | 正常展示支付信息，按钮可点击 |
| `order.status = 3` 已取消 | 订单超时或用户主动取消 | 进入本页时检测到此状态，跳转订单详情并提示"订单已取消" |
| `order.status = 2` 已支付 | 订单已支付 | 进入本页时检测到此状态，直接跳转 `U-预约成功页` 或 `U-我的套餐页` |
| `payment_countdown > 0` | 订单仍在 24h 有效期内 | 顶部显示倒计时；倒计时结束自动触发订单取消 |
| `payment_countdown = 0` | 订单已过期 | 按钮禁用，提示"订单已过期，请重新下单" |
| `pay_channel = wechat` | 微信支付（channel = 0） | 支付方式区单选按钮可选项之一 |
| `pay_channel = alipay` | 支付宝支付（channel = 1） | 支付方式区单选按钮可选项之一 |
| `paying = true` | 前端已调用后端 Mock 支付 | 主按钮显示 loading，防止重复点击 |

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 无 order_id 传入或订单不存在 | 中央 Empty 组件：插画 + "暂无订单信息" + "返回首页" 按钮（→ `U-首页`） |
| **加载中** | 首次进入 / 查询订单状态 / 调起支付 SDK 前 | 金额区显示渐变占位；卡片区域显示骨架屏 |
| **错误状态** | 网络断开 / 接口 5xx / 订单不存在 / 支付渠道异常 | 中央错误插画 + "加载失败，点击重试" + Primary「重新加载」按钮；支付渠道异常时显示 "支付服务繁忙，请稍后重试" |
| **成功状态** | 订单待支付且倒计时 > 0 | 按 §4 显示规则矩阵完整展示；支付成功后显示成功 overlay 并自动跳转 |

# 页面规格：U-启动页

> **性质**：Figma 设计交付的唯一指令源。AI 生成 Figma 时**必须**按本规格严格执行。
> **核心约束**：本规格的每一条元素显隐规则必须可追溯到 [PRD](../../prd/prd.md) 或具体 US 的某条业务规则。
> **归属 US**：US-004（游客微信授权登录）/ US-005（用户补充注册资料）/ US-006（用户手机号/账号密码登录）
> **对应 PRD**：§3.2 身份状态机、§5.2.1 注册登录、§13.3 MVP 核心页面清单
> **版本**：v1.0 | **创建日期**：2026-08-02

## 2. 用户身份与业务状态维度

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| 游客 | ✅ | 启动页在身份判定前统一展示，所有身份看到的视觉元素一致 |
| 注册用户 | ✅ | 同上 |
| 学员 | ✅ | 同上 |
| 教练 | ✅ | 本页为用户端启动页，教练身份在启动阶段亦先进入此页（若从用户端入口启动） |
| 管理员 | ✅ | 同上（用户端视角） |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| **冷启动** | 小程序首次被打开或进程已被回收 | 完整展示品牌元素 + 加载指示器，需重新拉取启动配置与登录态 |
| **热启动** | 小程序从后台切回前台，进程仍在 | 可快速复用本地登录态，页面显示时间极短，但仍需展示品牌元素以保证视觉一致性 |
| **无登录态 / 登录态过期** | 本地未缓存有效 token 或 token 已失效 | 初始化结束后自动跳转登录引导页 |
| **已登录且资料完整** | 本地 token 有效且 `profile_completed = true` | 初始化结束后自动跳转首页 |
| **已登录但资料不完整** | 本地 token 有效但 `profile_completed = false`（首次微信登录后未补充资料） | 初始化结束后自动跳转补充资料页 |

## 3. 元素清单（自上而下）

> 1. 每个元素必须说明：名称、尺寸、位置、颜色、圆角、字体、显示条件、交互行为
> 2. 启动页所有元素必须居中对齐，使用 Auto Layout（禁止手动估算 x/y 坐标）
> 3. 页面不使用 TabBar 与 NavBar，保持全屏沉浸

## 5. 跳转动线矩阵

> 启动页无用户可点击的跳转元素，所有跳转由初始化结果自动触发。以下矩阵按“初始化完成后的会话状态”组织。

| 触发条件 | 无登录态 / 登录态过期 / 新用户 | 已登录且 `profile_completed = true` | 已登录但 `profile_completed = false` |
|---------|------------------------------|--------------------------------------|--------------------------------------|
| **初始化成功** | → `U-微信授权登录页`（US-004） | → `U-首页` | → `U-补充资料页`（US-005） |
| **初始化失败** | 停留本页，展示错误态 + 「重新加载」按钮 | 停留本页，展示错误态 + 「重新加载」按钮 | 停留本页，展示错误态 + 「重新加载」按钮 |

> **过渡动效**：初始化成功后，启动页以 300ms 淡出（opacity 1→0, ease-out）离开，随后进入目标页面。

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 首次安装且无任何本地缓存 | 与成功态视觉一致，展示品牌 Logo、名称、Slogan；加载指示器按最小 300ms 展示后进入加载态 |
| **加载中** | 正在检查本地 token、拉取启动配置或校验登录态 | 品牌元素完整显示 + 加载指示器旋转 + 「加载中…」文案 |
| **错误状态** | 网络断开、后端启动接口 5xx、或本地初始化异常 | 品牌元素保留但弱化（整体 opacity 0.6），中央展示 120×120 错误插画占位 + 文案「网络异常，请重试」+ 「重新加载」按钮 |
| **成功状态** | 初始化完成且已知下一步目标页面 | 品牌元素完整显示，触发淡出过渡并跳转目标页 |

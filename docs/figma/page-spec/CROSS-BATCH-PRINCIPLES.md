# 跨批次全局设计原则（用户侧小程序）

> **用途**：确保 US-001 ~ US-021 批次页面在身份、状态、组件、动线上保持全局一致。
> **适用范围**：小程序用户端全部 21 个 MVP 页面。
> **版本**：v1.0
> **最后更新**：2026-08-02

---

## 1. 身份与可见性全局规则

| 身份 | 判定标准 | 全局影响 |
|------|---------|---------|
| 游客 | 未登录 / 微信未授权 | 只能看公开信息；购买/预约/我的订单等入口点击后→微信授权页 |
| 注册用户 | 已授权 + 已补充手机号，无 active 套餐 | 可购买套餐；可预约体验课；看不到学员专属入口 |
| 学员 | 持有 ≥1 个 active 套餐 | 可正常预约；首页显示当前教练；不可购买其他教练套餐 |

### 1.1 游客可见内容（全局白名单）

以下页面/元素**游客可见**：
- 启动页
- 首页：通知栏、倒计时、搜索栏、热门教练横向卡片、场馆信息入口、公告摘要
- 教练列表页
- 教练详情页：基础资料、评价、套餐卡（但价格可模糊或提示登录后查看）
- 场馆公告页列表

### 1.2 游客必须被拦截的操作

以下操作游客点击后**统一跳转微信授权页**，不在当前页弹登录框：
- 购买套餐 / 体验课
- 预约时段
- 查看「我的预约」「我的订单」「上课记录」
- 点击需要身份信息的按钮（如「立即支付」「提交预约」）

> **统一原则**：身份拦截前置到授权页，不重复在每个页面内做登录弹窗。

## 2. 单教练约束全局规则

### 2.1 学员状态定义

- 持有任意 `status=active` 的套餐 = 学员。
- 可以同时持有**同一教练**的多个套餐（如主课 + 加课）。
- **不能**同时持有不同教练的 active 套餐。

### 2.2 对页面的影响矩阵

| 页面 | 无 active 套餐 | 已绑定教练 A |
|------|---------------|-------------|
| 首页 | 显示「新人体验课 Banner」+「查看全部套餐」 | 显示「继续上课（教练A）」+「为当前教练加课」 |
| 套餐列表页 | 全部套餐可见 | 仅教练 A 的套餐可见，其他教练套餐置灰并提示 |
| 套餐详情页（教练 B） | 正常购买 | 隐藏购买按钮，顶部显示「您已绑定教练 A，需先退订」 |
| 教练详情页（教练 B） | 正常显示购买入口 | 隐藏购买入口，显示当前教练 A 的快捷入口 |
| 教练排班页（教练 B） | 正常预约 | 显示跨教练警告条，禁用预约按钮 |
| 订单确认页 | 按选择套餐进入 | 若选择其他教练套餐，提交时提示并阻断 |

## 3. 体验课不变量

- 每个用户**仅可购买 1 份体验课**，且体验课必须在首份正价课**之前**或**同时**购买。
- 体验课有效期：**自购买起 30 天**。
- 体验课不可退款。
- 已持有体验课的用户，在任何页面都不再看到「新人体验课 Banner」。

### 3.1 页面显隐规则

- 首页 Banner：仅对「注册用户且无体验课」显示。
- 套餐列表页：已持有体验课时，体验课卡显示「已购买」状态，不可再点。
- 教练详情页：已持有体验课时，体验课卡显示「已购买」并禁用。
- 排班页：无体验课不可约体验课格。

## 4. 预约与取消规则

### 4.1 预约状态机

```
reserved → confirmed → completed
        → cancelled
        → no-show
```

### 4.2 取消规则（全局统一）

| 时间 | 操作 | 结果 |
|------|------|------|
| ≥24h  before start | 学员直接取消 | 释放课时，立即到账 |
| <24h and ≥2h before start | 学员申请取消 | 教练 24h 内审批，逾期自动拒绝 |
| <2h before start | 学员提交特殊原因申诉 | 需证明材料，争议退款 |
| 教练请假/场馆换水 | 系统自动取消 | 释放课时 + 通知改约 |

### 4.3 页面影响

- 预约详情页：根据时间区间显示不同取消按钮文案与二次确认内容。
- 我的预约页：卡片上显示「可取消」「需审批」「不可取消」状态徽标。
- 候补关注页：取消后课时释放，候补用户按队列顺序收到通知。

## 5. 订单与支付规则

### 5.1 订单状态机

```
pending → paid → active → expired/refunded
       → cancelled
```

### 5.2 退款规则（MVP）

- **无手续费**。
- 退款金额 = 套餐价 × (available + reserved) / total_hours。
- 退款申请提交时**立即释放 reserved** 课时。
- 已 consumed 课时不参与退款。

### 5.3 页面影响

- 订单详情页：pending 状态显示「去支付」；active 显示「申请退款」；refunded 显示退款金额与到账方式。
- 支付页：仅支持微信支付（MVP），展示订单号、应付金额、支付倒计时。

## 6. 导航与页面结构全局规则

### 6.1 TabBar（仅 Tab 首页显示）

| Tab | 图标 | 对应页面 |
|-----|------|---------|
| 首页 | home | U-首页 |
| 教练 | search/users | U-教练列表页 |
| 预约 | calendar | U-我的预约页 |
| 我的 | user | U-个人中心页（MVP 建议聚合账号安全/我的套餐/设置） |

### 6.2 NavBar 规则

- 所有二级页面显示 NavBar，左侧返回按钮，右侧可选操作（分享/更多）。
- 启动页、授权页、支付结果页等特殊流程页面**无 NavBar**。
- 标题 17px，白色，居中；背景 #0050B3（主色 700）。

### 6.3 页面返回行为

- 从「套餐详情页」点击购买 → 订单确认页 → 支付页 → 预约页 → 预约成功页。
- 支付结果页（成功/失败）**不显示返回按钮**，显示「完成」或「重新支付」。

## 7. 组件复用规范

### 7.1 必须全局复用的组件

| 组件 | 位置 | 规范来源 |
|------|------|---------|
| 教练卡片 | 首页/教练列表页/教练详情页相关推荐 | README.md §2.5.4 |
| 套餐卡 | 首页/套餐列表页/教练详情页/订单确认页 | README.md §2.5.5 |
| 时段格 | 教练排班页/预约页 | README.md §2.5.9 |
| 状态徽标 | 我的预约页/订单列表页/候补页 | README.md §2.5.6 |
| 空状态 | 所有列表页 | README.md §2.6.4 |
| 加载/错误/成功态 | 所有页面 | README.md §2.6 |

### 7.2 禁止行为

- 同一业务组件在不同页面出现尺寸、圆角、颜色不一致。
- 同一身份状态在不同页面出现显隐逻辑矛盾。
- 同一按钮文案在不同页面表达不同含义。

---

## 8. 四态设计强制要求

每个页面必须包含：

1. **空状态**：无数据时的引导（如「暂无公告」「暂无订单」）。
2. **加载状态**：骨架屏或 loading 指示器。
3. **错误状态**：网络错误/加载失败的刷新引导。
4. **成功状态**：操作完成后的确认（如支付成功、预约成功）。

对于结果页（预约成功/支付成功），成功态就是主状态。

## 9. 跳转动线全局图（用户侧）

```
启动页
  → 未登录 → 微信授权页 → 补充手机号页 → 首页
  → 已登录 → 首页

首页
  → 搜索/热门教练 → 教练列表页 / 教练详情页
  → 套餐入口 → 套餐列表页 → 套餐详情页
  → 场馆信息 → 场馆公告页

教练详情页
  → 购买套餐 → 订单确认页 → 支付页 → 预约页 → 预约成功页
  → 查看排班 → 教练排班页 → 预约页

我的预约页
  → 预约卡片 → 预约详情页（可取消/改约/申诉）

订单列表页
  → 订单卡片 → 订单详情页（支付/退款/查看）

候补/关注页
  → 候补卡片 → 教练排班页 / 预约页
```

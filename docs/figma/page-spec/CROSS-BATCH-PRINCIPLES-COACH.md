# 跨批次全局设计原则（教练侧小程序）

> **用途**：确保 US-010 ~ US-040 教练端相关页面在身份、状态、组件、动线上保持全局一致。
> **适用范围**：小程序教练端全部 MVP 页面。
> **版本**：v1.0
> **最后更新**：2026-08-02

---

## 1. 教练身份与状态全局规则

### 1.1 教练状态机

```
0（待审核） ← 首次提交 / 重新提交 / 重新入驻
1（已通过） ← 审核通过
2（已驳回） ← 审核拒绝（可重新提交，复用原记录）
3（已离职）  ← 离职审批通过
4（申请离职中） ← 教练提交离职申请
```

### 1.2 状态对页面可见性的全局影响

| 状态 | 判定标准 | 全局影响 |
|------|---------|---------|
| 待审核（0） | 已提交入驻资料，等待审核 | 只能看「审核中」页；不能进入教练端功能首页 |
| 已通过（1） | 入驻审核通过 | 完整使用教练端功能；可提交请假、离职、分享主页 |
| 已驳回（2） | 审核被拒绝 | 显示驳回原因，可修改资料重新提交 |
| 已离职（3） | 离职审批通过 | 功能锁定，仅显示「已离职」状态和「重新入驻」入口 |
| 申请离职中（4） | 已提交离职申请，待管理员审批 | 功能仍可用（继续上课/排班），但购买入口对用户隐藏；仅在离职工单内显示该状态 |

### 1.3 状态 4 隐私强规则

- 教练列表/搜索**不**展示「申请离职中」标签。
- 用户端教练详情页**不**展示任何离职相关提示。
- 离职工单状态**仅**在教练端「我的 → 离职进度」内可见。
- 状态 4 期间，老学员仍可正常约课，未来排班继续生成。

## 2. 实时状态全局规则

### 2.1 实时状态枚举

| 状态 | 颜色 | 触发方式 |
|------|------|----------|
| 空闲中 | `#52C41A` 绿 | 手动 / 自动恢复 |
| 上课中 | `#1890FF` 蓝 | 课程开始前 15 分钟自动切换 |
| 休息中 | `#FAAD14` 橙 | 手动设置 |
| 已下班 | `#8C8C8C` 灰 | 手动 / 自动恢复 |
| 请假中 | `#FF4D4F` 红 | 请假审批通过后系统强制设置，手动入口锁定 |

### 2.2 优先级规则

1. **请假中优先级最高**：审批通过的请假时段内，实时状态强制为「请假中」，手动切换入口锁定。
2. **手动状态次之**：非请假时段，教练手动设置的状态优先级高于系统自动切换。
3. **自动状态兜底**：非请假时段且未手动覆盖时，系统按课程安排自动切换。

### 2.3 页面对应关系

- 教练端首页/我的页：展示当前实时状态，提供切换入口（请假时段锁定）。
- 用户端教练列表/详情：以圆点/标签展示教练实时状态。
- 预约管理页：卡片上展示课程状态（已预约/待上课/上课中/已完成/已取消/候补中/被关注），与实时状态区分。

## 3. 预约管理全局规则

### 3.1 教练端预约卡片状态

| 状态 | 颜色 | 含义 |
|------|------|------|
| 已预约 | `#1890FF` | 学员已预约，未开始 |
| 待上课 | `#FAAD14` | 课程即将开始（课前 15 分钟内） |
| 上课中 | `#1890FF` 蓝底 | 课程进行中 |
| 已完成 | `#52C41A` | 教练已确认上课并扣课时 |
| 已取消 | `#BFBFBF` | 学员/系统取消 |
| 旷课 | `#FF4D4F` | 学员未到课，已自动扣课时 |
| 候补中 | `#722ED1` | 时段已满，学员在候补队列 |
| 被关注 | `#8C8C8C` | 学员关注该时段，等待释放 |

> 注：候补/被关注颜色仅在需要单独展示时使用；默认与「已预约」同区展示但带徽标。

### 3.2 课程确认规则

- 课程结束后 24 小时内，教练可操作「确认上课并扣除课时」或「标记学员未到课」。
- 超过 24 小时未确认，系统自动确认并扣课时。
- 课程未结束前，两个按钮均禁用。
- 已取消/已完成/旷课的预约不可再次确认。

### 3.3 代约/改约规则

- 教练可为已绑定且授权自己的学员代约/改约正价课程。
- ≥24h 的代约/改约：教练直接操作。
- <24h 的代约/改约：需学员在系统内明确确认，未确认则保持原状。
- 代约/改约操作记录 `operator = coach`。

## 4. 学员管理全局规则

### 4.1 关联学员定义

与当前教练存在至少 1 条 `booking` 或 `package` 记录的学员，才出现在「我的学员」列表。

### 4.2 信息切片规则

- 教练维护的是「教练视角信息切片」，写入 `coach_student_profile` 表。
- 不影响学员本人资料（`user` 表）。
- 其他教练看不到本教练填写的切片。

### 4.3 未成年人规则

- 教练可标记学员是否为未成年人并维护监护人信息。
- 未成年人首次上课确认时，由 US-033 触发监护人短信通知。
- 教练端表单中，未成年人开关为 true 时，监护人姓名/手机号必填。

## 5. 排班与请假全局规则

### 5.1 排班规则

- 教练可维护自己的可约时段模板和周实例。
- 时段默认粒度 1 小时，后台可配置。
- 同一教练同一时段不可重复添加。
- 已有时段不可删除（已有 booking 时）。
- 支持「复制上周排班」快速生成。

### 5.2 请假规则

- 请假最小粒度 1 小时。
- 请假开始时间不能早于当前时间。
- 请假时间段不能与已批准的请假重叠。
- 请假审批通过后，系统自动取消受影响预约并释放预占课时。
- 请假期间教练实时状态强制为「请假中」。

## 6. 离职与重新入驻全局规则

### 6.1 离职流程

1. 教练在「我的 → 申请离职」提交申请，`coach.status: 1 → 4`。
2. 系统生成离职工单，列出所有 active 学员套餐。
3. 教练对每份 active 套餐登记处理结果：转新教练 / 全额退款 / 继续上完。
4. 教练提交工单至管理员审批队列。
5. 管理员审批通过后，`coach.status: 4 → 3`，该教练未来 booking 取消、active package 冻结。

### 6.2 重新入驻流程

1. 已离职教练（status=3）在「我的 → 重新入驻」提交申请，`coach.status: 3 → 0`。
2. 走与首次入驻相同的审核流程。
3. 审核通过后 `coach.status: 0 → 1`。
4. 历史评分/评价保留但仅对老学员可见。
5. 已 frozen 的老学员 package 不自动恢复。

## 7. 导航与页面结构全局规则

### 7.1 TabBar（仅 Tab 首页显示）

| Tab | 图标 | 对应页面 |
|-----|------|---------|
| 首页 | home | C-教练端首页 |
| 预约 | calendar | C-预约管理页 |
| 学员 | users | C-学员管理页 |
| 我的 | user | C-教练中心页 |

### 7.2 NavBar 规则

- 所有二级页面显示 NavBar，左侧返回按钮，右侧可选操作（分享/更多）。
- 启动页、审核状态页、特殊流程页等可无 NavBar。
- 标题 17px，白色或深色，根据 NavBar 背景调整；背景默认 `#0050B3` 或白色。

### 7.3 教练端首页结构

| 区域 | 内容 |
|------|------|
| 顶部 | 教练个人形象照、姓名、实时状态切换入口 |
| 数据概览 | 今日课程数、本周待上课数、学员总数 |
| 快捷操作 | 排班管理、代约、请假申请、分享主页 |
| 今日课程 | 按时间轴展示今日预约卡片 |
| 底部 | TabBar |

## 9. 四态设计强制要求

每个页面必须包含：

1. **空状态**：无数据时的引导（如「暂无学员」「暂无预约」）。
2. **加载状态**：骨架屏或 loading 指示器。
3. **错误状态**：网络错误/加载失败的刷新引导。
4. **成功状态**：操作完成后的确认（如提交成功、确认上课成功）。

对于结果页（提交成功/确认成功），成功态就是主状态。

## 10. 跳转动线全局图（教练侧）

```
登录后状态判断
  → status=0（待审核）→ 审核状态页
  → status=2（已驳回）→ 入驻资料填写页（带驳回原因）
  → status=3（已离职）→ 教练中心页（仅重新入驻入口）
  → status=1（已通过）→ 教练端首页

教练端首页
  → 今日课程卡片 → 预约详情页
  → 快捷操作-排班管理 → 排班管理页
  → 快捷操作-代约 → 学员管理页 → 代约时段选择页
  → 快捷操作-请假 → 请假申请页
  → 快捷操作-分享 → 分享海报页

预约管理页
  → 预约卡片 → 预约详情页
  → 预约详情 → 改约页 / 上课记录确认页 / 标记旷课弹窗

学员管理页
  → 学员卡片 → 学员详情/编辑页
  → 代约按钮 → 代约时段选择页

教练中心页
  → 个人主页编辑 → 个人主页编辑页
  → 参考单价 → 参考单价设置页
  → 申请离职 → 申请离职页 → 离职工单处理页
  → 重新入驻 → C-入驻资料页（status=3，重新入驻状态）
```

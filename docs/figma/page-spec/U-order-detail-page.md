## 2. 用户身份与业务状态维度

> **本节是 Page Spec 根基**。先定义"谁可能看到这个页面"以及"以什么业务状态看到"。
> 本页为**学员核心页面**，游客访问时统一拦截到登录流程。

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| 游客 | ❌ 不可见 | 整页拦截，跳转 `U-微信授权页`；登录成功后返回本页刷新 |
| 注册用户 | ✅ 可见 | 可查看自己名下的订单详情；操作权限受订单状态约束 |
| 学员 | ✅ 可见 | 可查看并操作订单详情，是主使用身份 |
| 教练 | ❌ 不可见 | 教练端无此页面 |
| 管理员 | ❌ 不可见 | 管理端使用 Web 后台订单详情页 |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| `order.status = 1` 待支付 | 订单创建后未支付 | 头部显示橙色待支付图标，底部显示「去支付」主按钮 |
| `order.status = 2` 已支付 | 支付成功，套餐 active | 头部显示绿色成功图标，底部显示「申请退款」主按钮 |
| `order.status = 3` 已取消 | 超时未支付或用户主动取消 | 头部显示灰色取消图标，底部仅显示「删除记录」 |
| `order.status = 4` 退款审批中 | 用户提交退款，等待审批 | 头部显示蓝色处理中图标，展示退款进度条（步骤 1/3） |
| `order.status = 5` 争议退款处理中 | 特殊原因申诉 | 头部显示 `color-error` 争议图标，展示申诉材料与预计反馈时间 |
| `order.status = 6` 已退款 | 退款流程完成 | 头部显示深灰已退款图标，展示退款金额、到账方式、到账时间 |
| `order.status = 7` 退款被拒 | 退款/申诉被驳回 | 头部显示红色被拒图标，展示拒绝原因，底部显示「重新申请」 |
| `order.status = 8` 退款处理中 | 管理员批准，渠道处理中 | 头部显示脉冲蓝图标，进度条到步骤 2/3，提示 3-7 工作日 |
| `package.status = expired` | 套餐已过期 | 在「已支付」态基础上顶部增加黄色过期提示条，可申请退款 |
| `package.status = frozen(refund_pending)` | 退款审批期间冻结 | 禁用约课相关入口，显示「退款处理中」提示条 |

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 本页不适用（详情页始终有目标订单；若订单不存在则进入错误状态） | — |
| **加载中** | 首次进入 / 下拉刷新 | 头部显示占位渐变；各卡片区域显示骨架屏（浅灰 #F5F5F5 矩形占位）；底部栏显示默认占位 |
| **错误状态** | 网络断开 / 接口 5xx / 订单不存在 / 越权访问 | 隐藏骨架屏，中央展示错误插画 + 文案 + Primary「重新加载」/「返回订单列表」按钮 |
| **成功状态** | 数据正常返回 | 按 §4 显示规则矩阵完整展示状态头部、信息卡片、退款进度、底部操作栏；倒计时实时更新 |

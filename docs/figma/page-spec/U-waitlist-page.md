## 2. 用户身份与业务状态维度

> **本节是 Page Spec 根基**。先定义"谁可能看到这个页面"以及"以什么业务状态看到"。
> 本页为**学员核心页面**，游客访问时统一拦截到登录流程。

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| 游客 | ❌ 不可见 | 整页拦截，跳转 `U-微信授权页`；登录成功后返回本页刷新 |
| 注册用户 | ✅ 可见 | 可查看并管理「关注」列表；若无 active 套餐，「候补」Tab 为空且提示购买套餐 |
| 学员 | ✅ 可见 | 可查看并管理「候补」与「关注」两个列表，是主使用身份 |
| 教练 | ❌ 不可见 | 教练端使用教练端小程序「我的学员」相关页面 |
| 管理员 | ❌ 不可见 | 管理端使用 Web 后台 |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| `waitlist.status = waiting` | 正在排队候补 | 卡片显示排队位置与预计等待提示，展示「取消候补」按钮 |
| `waitlist.status = converted` | 候补已自动转正为预约 | 卡片显示「已转正」徽标，提供跳转预约详情入口 |
| `waitlist.status = cancelled` | 候补已取消或他处转正被系统取消 | 默认不展示；若展示则置灰并标注「已取消」 |
| `slot_follow.status = active` | 关注有效中 | 卡片显示关注时段信息，展示「取消关注」按钮 |
| `slot_follow.status = invalid` | 时段已删除/过期导致关注失效 | 卡片置灰，标注「该时段已失效」，提供「删除」按钮 |
| 用户持有 active 套餐 | 具备候补资格 | 无 active 套餐时，候补 Tab 空状态提示「购买套餐后可候补」 |
| 候补队列释放 | 他用户取消导致名额释放 | 触发 US-024 自动转正，waiting → converted |

### 3.1 候补卡片字段与状态

| 字段 | 说明 |
|------|------|
| 教练个人形象照 | 展示教练头像 |
| 教练姓名 | 教练姓名 |
| 状态徽标 | 按候补状态显示（排队中 / 已转正 / 已取消 / 已过期） |
| 时段信息 | 如「周三 08:00-09:00」 |
| 场馆/地点 | 如「XX 游泳馆 · 1 号池」 |
| 排队位置 | `waiting` 状态时显示「当前排在第 N 位」 |
| 候补人数 | `waiting` 状态时显示「共 N 人候补」 |
| 预计提示 | `waiting` 状态时显示「有人取消时将按顺序自动预约」 |
| 操作按钮 | `waiting` → 「取消候补」；`converted` → 「查看预约」；`cancelled/expired` → 「删除记录」 |

#### 候补卡片状态变体

| 状态 | 徽标文案 | 卡片表现 |
|------|---------|---------|
| `waiting` | 排队中 | 显示排队位置，「取消候补」可操作 |
| `converted` | 已转正 | 隐藏排队位置，按钮改为「查看预约」 |
| `cancelled` | 已取消 | 整卡置灰，按钮改为「删除记录」 |
| `expired` | 已过期 | 整卡置灰，提示"时段已过期" |

### 3.2 关注卡片字段与状态

| 字段 | 说明 |
|------|------|
| 教练个人形象照 | 展示教练头像 |
| 教练姓名 | 教练姓名 |
| 状态徽标 | 按关注状态显示（关注中 / 已失效） |
| 时段信息 | 如「周四 19:00-20:00」 |
| 提醒说明 | 如「释放前或有人取消时提醒」 |
| 操作按钮 | `active` → 「取消关注」；`invalid` → 「删除」 |
| 失效提示 | `slot_follow.status = invalid` 时，底部显示 "该时段已失效" |

#### 关注卡片状态变体

| 状态 | 徽标文案 | 卡片表现 |
|------|---------|---------|
| `active` | 关注中 | 正常显示，「取消关注」可操作 |
| `invalid` | 已失效 | 整卡置灰，显示失效原因，按钮改为「删除」 |

### 3.3 空状态文案

| Tab | 主文案 | 副文案 | CTA 按钮 |
|------|--------|--------|----------|
| 候补 Tab（有套餐或无套餐空记录） | 暂无候补时段 | 候补 Tab（无 active 套餐）：购买套餐后即可排队候补；其他：去预约页看看可约时段吧 | 无套餐时显示「去购买套餐」；其他情况显示「去预约」 |
| 关注 Tab | 暂无关注时段 | 去预约页看看可约时段吧 | 「去预约」 |

### 3.4 设计约束与注意事项

> **来源**：跨批次全局设计原则 §7 / §8。

| # | 约束 | 说明 |
|---|------|------|
| 1 | 候补/关注为两种并列机制 | 不得将两者混为同一队列，UI 上必须通过 Segment 明确区分 |
| 2 | 排队位置仅对 waiting 状态有效 | converted/cancelled/expired 状态不显示排队位置，避免误导 |
| 3 | 操作按钮状态与后端状态严格对应 | 不允许在 waiting 状态外显示「取消候补」按钮 |
| 4 | 二次确认必须携带业务说明 | 取消候补弹窗文案："取消后将不再排队，是否确认？" |
| 5 | 关注提醒不强制预约 | 关注用户仅收到提醒，不会自动创建 booking |
| 6 | 列表项长按/左滑不触发删除 | MVP 仅通过卡片内按钮操作，避免与滚动冲突 |

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 当前 Tab 下无任何记录 | 隐藏列表，居中展示 Empty 组件：插画 + 主文案 + 副文案 + CTA 按钮 |
| **加载中** | 首次进入 / 下拉刷新 / 切换 Tab | 列表区域显示骨架屏卡片；NavBar 与 Segment 保持可见 |
| **错误状态** | 网络断开 / 接口 5xx / 业务 4xx | 隐藏骨架屏，中央展示错误插画 + "加载失败，点击重试" + Primary「重新加载」按钮 |
| **成功状态** | 数据正常返回 | 按 §4 显示规则矩阵完整展示 Segment、列表卡片、操作按钮；操作后局部刷新 |

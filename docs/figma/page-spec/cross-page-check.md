## 2. 检查维度

| 维度 | 说明 |
|------|------|
| 身份定义一致性 | 游客 / 注册用户 / 学员三种身份在 20 个页面中判定标准与可见操作是否一致 |
| 单教练约束一致性 | 同一用户同时只能绑定一名 active 教练，相关显隐/阻断逻辑是否贯通 |
| 体验课规则一致性 | 每位用户限购 1 份、30 天有效、不可退款、已购隐藏入口等规则是否一致 |
| 取消 / 退款规则一致性 | 24h / 2h 取消时间窗、退款公式、争议退款流程是否一致 |
| 导航一致性 | TabBar/NavBar/返回按钮规则是否符合全局框架；特殊流程页是否正确去除返回 |
| 组件复用一致性 | 教练卡、套餐卡、时段格、状态徽标、空状态等跨页规格是否一致 |
| 设计 Token 一致性 | 颜色、圆角、阴影、字体等视觉 Token 是否引用全局规范 |
| 跳转命名一致性 | 跳转矩阵中的目标页是否统一使用 `U-<页面名>` 格式 |
| 四态覆盖完整性 | 每个页面是否都包含空 / 加载 / 错误 / 成功四态 |
| 命名规范 | Frame 名是否符合 `<端缩写>-<页面名>`；文件命名是否统一 |

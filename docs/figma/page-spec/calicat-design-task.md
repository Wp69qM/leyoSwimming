## 1. 项目概述

### 1.1 产品定位
leyoSwimming 是一个面向游泳场馆的教练与学员约课沟通平台，解决游泳教练与学员之间预约、沟通、记录、评价等环节信息化不足的问题。

### 1.2 核心价值
- **对潜在用户**：透明化教练、套餐、场馆信息，降低决策门槛。
- **对学员**：数字化管理课时、记录成长轨迹、获取教学反馈。
- **对教练**：数字化管理学员与课时，通过数据优化教学策略。
- **对场馆**：提升运营效率，沉淀数据资产，辅助经营决策。

### 1.3 目标平台（MVP）
1. 微信小程序（用户端）——**本批次设计对象**
2. 微信小程序（教练端）
3. Web 后台管理系统
4. 未来扩展：iOS / Android App

## 2. 身份体系（影响页面显隐）

### 2.1 三种用户身份
| 身份 | 定义 | 可访问功能 |
|------|------|-----------|
| **游客** | 未注册访问者 | 浏览公开信息（教练、套餐、公告） |
| **注册用户** | 已注册，0 个 active 套餐 | 注册、购课、浏览 |
| **学员** | 已注册，≥1 个 active 套餐 | 上述 + 预约课程、查看课时、查看记录 |

### 2.2 身份状态机
```
游客 ──注册成功──→ 注册用户
注册用户 ──购买+支付成功──→ 学员
学员 ──所有 active 套餐失效──→ 注册用户
```

- 游客与注册用户互斥；注册用户与学员是同一主体的不同状态。
- 教练、管理员为独立角色，不使用本页面身份体系。

### 2.3 套餐状态（单值枚举）
| 状态 | 含义 |
|------|------|
| `active` | 有效，未过期，可预约 |
| `exhausted` | 课时耗尽 |
| `expired` | 时间过期 |
| `refunded` | 已退款 |
| `frozen` | 冻结（退款处理中 / 教练离职 / 管理员手动） |

### 2.4 课时计数三字段
- `available`：可被预约的课时
- `reserved`：已预约但教练未确认的课时
- `consumed`：教练已确认扣除的课时

**恒等式**：`reserved + consumed + available = total_hours`

## 3. 关键业务规则（必须体现到设计）

### 3.1 套餐模型
- **体验套餐**：1 节 / 30 天，每个用户最多同时持有 1 份 active/exhausted 体验套餐。
- **正式套餐**：一对一，多份/用户，同一教练下可共存多份 active 套餐。
- **扣减顺序**：FIFO 自动扣减；体验套餐优先于正式套餐。

### 3.2 单教练约束
- 同一用户所有 active 套餐必须绑定**同一位教练**。
- 想换教练时必须先退订当前所有 active 套餐，回到"注册用户"，再购买新教练套餐。
- UI 上表现为：学员在教练详情/排班页看到"已绑定其他教练"提示，并禁用购买/预约。

### 3.3 预约释放规则
- 每周三上午 10:00 统一释放下周（周一至周日）可约时段。
- 首页与排班页在释放前 24 小时至释放当天 10:00 前显示倒计时。
- 倒计时文案："距离下周预约开放还有 XX 小时" / "今日 10:00 开放下周预约"。

### 3.4 预约锁单与状态
- 同一时段（coach_id, start_time）仅允许 1 个预约；多人并发仅第一个成功。
- 正价套餐学员提交预约即成功，系统自动预占 1 节课时。
- 课程结束后由教练点击"确认上课并扣除课时"，系统才正式扣减。

### 3.5 取消预约时间窗
- **≥ 24h**：用户可自由取消，预占课时直接释放。
- **< 24h**：需教练审批，24h 内未处理视为拒绝。
- **< 2h（特殊原因）**：可提交"特殊原因申诉"，上传证明材料，管理员 3 工作日内决定。

### 3.6 候补与关注
- 满员时段支持"加入候补"；有人取消时按候补顺序自动转正。
- 用户可同时加入多个时段候补；若其中一个转正，其他候补自动取消。
- 关注时段：释放前/有人取消时收到提醒，不自动预约。

### 3.7 退款规则
- MVP 阶段**不收取任何手续费**。
- 退款金额 = 套餐价 × (available + reserved) / total_hours。
- 原路退回，3-7 工作日到账。

### 3.8 教练实时状态（5 种徽标）
| 状态 | 颜色 | 含义 |
|------|------|------|
| 空闲中 | 成功绿 #52C41A | 可立即预约 |
| 上课中 | 错误红 #FF4D4F | 当前正在上课 |
| 休息中 | 警告橙 #FAAD14 | 临时休息 |
| 已下班 | 中性灰 #8C8C8C | 当日不再接单 |
| 请假中 | 警告橙 #FAAD14 | 短期请假 |

### 3.9 教练入职状态（仅后台/教练端可见，用户端不展示）
- `status = 4`（申请离职中）的教练仍在用户端列表/详情可见，但**禁止显示"申请离职中"标签**。
- 购买按钮置灰/隐藏，hover 提示"暂不可购买"。

### 4.8 核心组件视觉规格
- **Primary 按钮**：渐变背景、白字、44px 高、8px 圆角、主色阴影。
- **Accent 按钮**：橙渐变、白字、44px 高、8px 圆角。
- **Secondary 按钮**：白底、主色边框、主色文字、44px 高。
- **卡片**：白底、12px 圆角、`shadow-card`、内边距 16px、间距 12px。
- **标签**：胶囊圆角 999px、浅色背景 + 对应色文字。
- **头像**：圆形，尺寸 xs/sm/md/lg/xl（24/32/48/64/80px）。
- **NavBar**：总高 88px（状态栏 44 + 内容区 44）。首页/详情用渐变主色；二级页面用白底 + 底部线。
- **TabBar**：总高 83px（内容 49 + 安全区 34），白底、顶部线、阴影。用户端 4 Tab：首页 / 教练 / 预约 / 我的。
- **空状态**：120×120 扁平运动主题插画 + 14px 灰文案 + 可选 CTA。
- **图标**：线性 outline、2px 描边、24×24px；禁止填充图标/emoji/写实插画。

### 4.9 AI 生成强制规则
1. **页面骨架**：Frame 375×812 → 状态栏 → NavBar → 内容区（可滚动）→ TabBar（仅 Tab 首页）。
2. **居中对齐必须使用 Auto Layout**，禁止手动估算 x/y。
3. **阴影 / 渐变 / 圆角 / 留白 / 信息层级 / 色彩点缀**六要素必须齐全。
4. **图标/头像/图片**使用规范占位，禁止 emoji。
5. **状态徽标**必须使用 §3.8 定义的 Tag 样式。
6. **排班页必须使用 7 列 × 15 行二维网格**，禁止做成纵向卡片列表。
7. **列表页**必须包含搜索栏、筛选标签、卡片列表、空状态。
8. **详情页**必须包含头部渐变区、信息卡片组、底部固定 CTA 栏。
9. **四态**：每个页面除 success 外，需在右侧 50px 处创建 empty / loading / error 副本 Frame。
10. **颜色纪律**：背景 #F5F7FA，卡片 #FFFFFF，主色只做操作元素，禁用纯黑 #000000。

## 5. 页面级交付要求

- 公告摘要卡：始终显示最新一条公告入口。
- 含 TabBar，当前选中"首页"。

### 5.3 场馆公告页 `U-场馆公告页`
- 白底 NavBar，标题"场馆公告"，带返回按钮，**无 TabBar**。
- 分类标签栏：全部 / 开放 / 换水 / 释放 / 紧急，选中为蓝色胶囊。
- 公告列表：343×88 白底卡片，左侧 40×40 圆形 type 图标，标题 + 摘要 + 时间。
- 点击列表项手风琴展开详情区（type Tag、完整标题、正文、发布时间）。
- 空状态："暂无公告"。

### 5.4 教练列表页 `U-教练列表页`
- 渐变 NavBar，标题"教练"，**无返回按钮**，含 TabBar（当前"教练"）。
- 搜索栏：胶囊、灰底、placeholder"搜索教练姓名"。
- 排序栏：综合评分 / 价格 / 可约时间，选中下划线 + ▲/▼。
- 教练卡片：343×120 白底卡片，含 48×48 圆形头像、姓名、实时状态徽标、星级评分、教龄、参考单价、标签。
- 状态徽标严格使用 5 种实时状态色，**禁止显示"申请离职中"**。
- 空状态："暂无教练入驻，敬请期待"。

### 5.5 教练详情页 `U-教练详情页`
- 渐变 NavBar，标题"教练详情"，带返回按钮，**无 TabBar**。
- 头部信息区：高 240px `gradient-water`，居中 80×80 头像、姓名、实时状态徽标、评分、教龄、累计课时/学员、证书标签。
- 简介区：白底卡片，最多 4 行，支持展开。
- 参考单价区：白底卡片，显示"参考单价 ¥XXX/节"或未设置状态。
- 联系方式区：电话 / 微信二维码 / 聊天（聊天为 P3，置灰标注）。
- 可约时间预览区：未来 7 天日期条 + 时段标签，点击查看全部跳转排班页。
- 套餐区：体验课橙渐变卡片（有体验套餐时隐藏）、正价套餐白底卡片。
- 评价区：评分汇总 + 标签 + 最多 3 条评价 + 查看全部。
- 底部 CTA 栏：按身份/状态矩阵显示"预约体验课""购买体验课""购买正价套餐""预约正课""购买加课套餐"，学员绑定其他教练时显示顶部冲突提示条。

### 5.6 教练排班页 `U-教练排班页`
- 白底 NavBar，标题"选择时段"，带返回按钮，**无 TabBar**。
- 教练信息卡：展示头像、姓名、实时状态、副信息，点击跳转教练详情。
- 释放倒计时条：窗口期内显示，非窗口期隐藏。
- 周选择器：「本周」「下周」两个胶囊 Tab。
- **二维排班网格**：7 列日期 × 15 行时段（07:00-21:00），单元格 48×48px。
  - 左侧时段列 sticky；顶部日期行 sticky；当天日期高亮。
  - 6 种状态色：可约（白底蓝框蓝字）、我的（蓝底白字）、已满（灰底灰字）、休息（深灰底白字）、候补（橙底橙字）、体验课（绿底绿字）。
- 图例说明：可约 / 我的 / 已满 / 休息 / 候补。
- 底部固定操作栏：选中时段信息 + 对应按钮（确认预约 / 加入候补 / 登录后预约 / 不可预约）。
- 跨教练绑定警告条：仅正价学员绑定其他教练时显示。

## 6. 通用交付规范

### 6.1 四态要求
每个页面必须提供以下 4 个 Frame：
1. `<Frame名>` — success 状态
2. `<Frame名>-empty` — 空状态
3. `<Frame名>-loading` — 骨架屏 / 加载占位
4. `<Frame名>-error` — 错误状态（插画 + 文案 + 重试按钮）

### 6.2 命名与组织
- Frame 命名：`U-启动页`、`U-首页` 等，与页面规格一致。
- 图层可展开、可编辑；禁止使用截图或栅格化图片。
- 颜色、字体、间距必须引用 Figma Variables / Styles，命名与 Token 一致。

### 6.3 适配
- 最小适配：iPhone SE 375×667。
- 大屏参考：iPhone 14 Pro Max 430×932。
- 仅竖屏。

### 6.4 禁止事项
- 禁止 emoji、填充式图标、写实插画、纯黑 #000000。
- 禁止自创组件样式，必须遵循 NutUI / 全局 Token。
- 禁止在 Page Spec 范围外增加功能或页面。

> **项目**：leyoSwimming 游泳约课系统 — 微信小程序用户端  
> **批次**：US001 第一批 · 6 个核心页面  
> **目标平台**：微信 iOS / Android 小程序（竖屏）  
> **交付物**：6 个页面的 Figma Frame（success + empty + loading + error）  
> **版本**：v1.0 | **日期**：2026-08-02

## 1. 项目概述

### 1.1 产品定位
leyoSwimming 是一个面向游泳场馆的教练与学员约课沟通平台，解决游泳教练与学员之间预约、沟通、记录、评价等环节信息化不足的问题。

### 1.2 核心价值
- **对潜在用户**：透明化教练、套餐、场馆信息，降低决策门槛。
- **对学员**：数字化管理课时、记录成长轨迹、获取教学反馈。
- **对教练**：数字化管理学员与课时，通过数据优化教学策略。
- **对场馆**：提升运营效率，沉淀数据资产，辅助经营决策。

### 1.3 目标平台（MVP）
1. 微信小程序（用户端）——**本批次设计对象**
2. 微信小程序（教练端）
3. Web 后台管理系统
4. 未来扩展：iOS / Android App

| 2 | 用户注册登录 | ✅ 启动页跳转 |

## 2. 身份体系（影响页面显隐）

### 2.1 三种用户身份
| 身份 | 定义 | 可访问功能 |
|------|------|-----------|
| **游客** | 未注册访问者 | 浏览公开信息（教练、套餐、公告） |
| **注册用户** | 已注册，0 个 active 套餐 | 注册、购课、浏览 |
| **学员** | 已注册，≥1 个 active 套餐 | 上述 + 预约课程、查看课时、查看记录 |

### 2.2 身份状态机
```
游客 ──注册成功──→ 注册用户
注册用户 ──购买+支付成功──→ 学员
学员 ──所有 active 套餐失效──→ 注册用户
```

- 游客与注册用户互斥；注册用户与学员是同一主体的不同状态。
- 教练、管理员为独立角色，不使用本页面身份体系。

### 2.3 套餐状态（单值枚举）
| 状态 | 含义 |
|------|------|
| `active` | 有效，未过期，可预约 |
| `exhausted` | 课时耗尽 |
| `expired` | 时间过期 |
| `refunded` | 已退款 |
| `frozen` | 冻结（退款处理中 / 教练离职 / 管理员手动） |

### 2.4 课时计数三字段
- `available`：可被预约的课时
- `reserved`：已预约但教练未确认的课时
- `consumed`：教练已确认扣除的课时

**恒等式**：`reserved + consumed + available = total_hours`

## 3. 关键业务规则（必须体现到设计）

### 3.1 套餐模型
- **体验套餐**：1 节 / 30 天，每个用户最多同时持有 1 份 active/exhausted 体验套餐。
- **正式套餐**：一对一，多份/用户，同一教练下可共存多份 active 套餐。
- **扣减顺序**：FIFO 自动扣减；体验套餐优先于正式套餐。

### 3.2 单教练约束
- 同一用户所有 active 套餐必须绑定**同一位教练**。
- 想换教练时必须先退订当前所有 active 套餐，回到"注册用户"，再购买新教练套餐。
- UI 上表现为：学员在教练详情/排班页看到"已绑定其他教练"提示，并禁用购买/预约。

### 3.3 预约释放规则
- 每周三上午 10:00 统一释放下周（周一至周日）可约时段。
- 首页与排班页在释放前 24 小时至释放当天 10:00 前显示倒计时。
- 倒计时文案："距离下周预约开放还有 XX 小时" / "今日 10:00 开放下周预约"。

### 3.4 预约锁单与状态
- 同一时段（coach_id, start_time）仅允许 1 个预约；多人并发仅第一个成功。
- 正价套餐学员提交预约即成功，系统自动预占 1 节课时。
- 课程结束后由教练点击"确认上课并扣除课时"，系统才正式扣减。

### 3.5 取消预约时间窗
- **≥ 24h**：用户可自由取消，预占课时直接释放。
- **< 24h**：需教练审批，24h 内未处理视为拒绝。
- **< 2h（特殊原因）**：可提交"特殊原因申诉"，上传证明材料，管理员 3 工作日内决定。

### 3.6 候补与关注
- 满员时段支持"加入候补"；有人取消时按候补顺序自动转正。
- 用户可同时加入多个时段候补；若其中一个转正，其他候补自动取消。
- 关注时段：释放前/有人取消时收到提醒，不自动预约。

### 3.7 退款规则
- MVP 阶段**不收取任何手续费**。
- 退款金额 = 套餐价 × (available + reserved) / total_hours。
- 原路退回，3-7 工作日到账。

### 3.8 教练实时状态（5 种徽标）
| 状态 | 含义 |
|------|------|
| 空闲中 | 可立即预约 |
| 上课中 | 当前正在上课 |
| 休息中 | 临时休息 |
| 已下班 | 当日不再接单 |
| 请假中 | 短期请假 |

### 3.9 教练入职状态（仅后台/教练端可见，用户端不展示）
- `status = 4`（申请离职中）的教练仍在用户端列表/详情可见，但**禁止显示"申请离职中"标签**。
- 购买按钮置灰/隐藏，hover 提示"暂不可购买"。

### 4.3 字体 Token

### 4.4 间距 / 圆角 / 阴影 Token
间距、圆角、阴影 Token 定义参见 `docs/figma/README.md` 全局设计规范。

### 4.5 渐变 Token
渐变 Token 定义参见 `docs/figma/README.md` 全局设计规范。

### 4.6 栅格
栅格系统遵循全局规范。

### 4.7 组件库
- **小程序端**：NutUI-React-Taro 2.x（React + Taro 3）。
- **Web 管理端**：Element Plus 2.x（本批次不涉及）。
- 设计稿需与 NutUI 默认样式（经主题覆盖后）保持一致。

### 4.8 核心组件视觉规格
按钮、卡片、标签、头像、NavBar、TabBar、空状态、图标等组件视觉规格遵循 `docs/figma/README.md` 全局设计规范。

### 4.9 AI 生成强制规则
1. **页面骨架**：Frame → 状态栏 → NavBar → 内容区（可滚动）→ TabBar（仅 Tab 首页）。
2. **居中布局必须使用 Auto Layout**，禁止手动估算 x/y。
3. **视觉层次、留白、信息层级等**六要素必须齐全。
4. **图标/头像/图片**使用规范占位，禁止 emoji。
5. **状态徽标**必须使用全局规范定义的 Tag 样式。
6. **排班页必须使用二维网格**，禁止做成纵向卡片列表。
7. **列表页**必须包含搜索栏、筛选标签、卡片列表、空状态。
8. **详情页**必须包含头部信息区、信息卡片组、底部固定 CTA 栏。
9. **四态**：每个页面除 success 外，需在右侧创建 empty / loading / error 副本 Frame。
10. **颜色纪律**：所有颜色按全局 Token 使用，禁止偏离规范的自定义颜色。

## 5. 页面级交付要求

### 5.1 启动页 `U-启动页`
- 全屏背景，无 NavBar、无 TabBar。
- 居中展示 Logo、品牌名、Slogan、加载指示器与加载文案。
- 错误态：品牌元素弱化，中央展示错误插画、"网络异常，请重试"文案与"重新加载"按钮。
- 跳转逻辑：无登录态 → 登录页；已登录资料完整 → 首页；已登录资料不完整 → 补充资料页。

### 5.2 首页 `U-首页`
- NavBar 标题 "leyoSwimming"，右侧消息图标。
- 顶部通知栏（按公告 type 区分）与倒计时组件**必须分离**。
- 搜索栏：placeholder 按身份区分。
- 新人体验课 Banner：**仅注册用户且无体验套餐时显示**，游客/学员隐藏。
- 教练区：游客/注册用户显示「热门教练」横向卡片；学员显示「继续上课」当前教练卡片。
- 套餐/场馆入口：游客/注册用户显示「查看全部套餐」「场馆信息」；学员显示「为当前教练加课」「我的套餐」。
- 公告摘要卡：始终显示最新一条公告入口。
- 含 TabBar，当前选中"首页"。

### 5.3 场馆公告页 `U-场馆公告页`
- NavBar 标题"场馆公告"，带返回按钮，**无 TabBar**。
- 分类标签栏：全部 / 开放 / 换水 / 释放 / 紧急。
- 公告列表：卡片展示 type 图标、标题、摘要、时间。
- 点击列表项手风琴展开详情区（type Tag、完整标题、正文、发布时间）。
- 空状态："暂无公告"。

### 5.4 教练列表页 `U-教练列表页`
- NavBar 标题"教练"，**无返回按钮**，含 TabBar（当前"教练"）。
- 搜索栏：placeholder"搜索教练姓名"。
- 排序栏：综合评分 / 价格 / 可约时间，支持下划线+三角标识的选中态。
- 教练卡片：头像、姓名、实时状态徽标、星级评分、教龄、参考单价、标签。
- 状态徽标严格使用 5 种实时状态，**禁止显示"申请离职中"**。
- 空状态："暂无教练入驻，敬请期待"。

### 5.5 教练详情页 `U-教练详情页`
- NavBar 标题"教练详情"，带返回按钮，**无 TabBar**。
- 头部信息区：背景按全局规范处理，居中头像、姓名、实时状态徽标、评分、教龄、累计课时/学员、证书标签。
- 简介区：卡片展示，最多 4 行，支持展开。
- 参考单价区：卡片展示"参考单价 ¥XXX/节"或未设置状态。
- 联系方式区：电话 / 微信二维码 / 聊天（聊天为 P3，置灰标注）。
- 可约时间预览区：未来 7 天日期条 + 时段标签，点击查看全部跳转排班页。
- 套餐区：体验课卡片（有体验套餐时隐藏）、正价套餐卡片。
- 评价区：评分汇总 + 标签 + 最多 3 条评价 + 查看全部。
- 底部 CTA 栏：按身份/状态矩阵显示"预约体验课""购买体验课""购买正价套餐""预约正课""购买加课套餐"，学员绑定其他教练时显示顶部冲突提示条。

### 5.6 教练排班页 `U-教练排班页`
- NavBar 标题"选择时段"，带返回按钮，**无 TabBar**。
- 教练信息卡：展示头像、姓名、实时状态、副信息，点击跳转教练详情。
- 释放倒计时条：窗口期内显示，非窗口期隐藏。
- 周选择器：「本周」「下周」两个 Tab。
- **二维排班网格**：日期列 × 时段行（07:00-21:00）。
  - 左侧时段列 sticky；顶部日期行 sticky；当天日期高亮。
  - 6 种状态：可约、我的、已满、休息、候补、体验课。
- 图例说明：可约 / 我的 / 已满 / 休息 / 候补。
- 底部固定操作栏：选中时段信息 + 对应按钮（确认预约 / 加入候补 / 登录后预约 / 不可预约）。
- 跨教练绑定警告条：仅正价学员绑定其他教练时显示。

## 6. 通用交付规范

### 6.1 四态要求
每个页面必须提供以下 4 个 Frame：
1. `<Frame名>` — success 状态
2. `<Frame名>-empty` — 空状态
3. `<Frame名>-loading` — 骨架屏 / 加载占位
4. `<Frame名>-error` — 错误状态（插画 + 文案 + 重试按钮）

### 6.2 命名与组织
- Frame 命名：`U-启动页`、`U-首页` 等，与页面规格一致。
- 图层可展开、可编辑；禁止使用截图或栅格化图片。
- 颜色、字体、间距必须引用 Figma Variables / Styles，命名与 Token 一致。

### 6.3 适配
- 最小适配、大屏参考、安全区等遵循全局规范。
- 仅竖屏。

### 6.4 禁止事项
- 禁止 emoji、填充式图标、写实插画。
- 禁止自创组件样式，必须遵循 NutUI / 全局 Token。
- 禁止在 Page Spec 范围外增加功能或页面。

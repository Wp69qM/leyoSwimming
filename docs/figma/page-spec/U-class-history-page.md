# 页面规格：U-上课记录页

> **性质**：Figma 设计交付的唯一指令源。AI 生成 Figma 时**必须**按本规格严格执行。
> **核心约束**：本规格的每一条元素显隐规则必须可追溯到 [PRD](../../prd/prd.md) 或具体 US 的某条业务规则。
> **归属 US**：US-032（学员签到课程）/ US-033（教练确认上课记录）/ US-034（管理员查看上课记录）/ US-035（管理员返还课时）
> **对应 PRD**：§5.3.2 预约功能、§5.3.3 课时与上课记录、§5.4.3 上课记录、§6.1 预约状态机、§13.3 MVP 核心页面清单（页面 20）
> **版本**：v1.0 | **创建日期**：2026-08-02
> **特别说明**：本页为二级列表页，聚合学员所有已完成/旷课的上课记录，按月份分组展示，支持查看单条记录详情与课后总结。

## 2. 用户身份与业务状态维度

> **本节是 Page Spec 根基**。先定义"谁可能看到这个页面"以及"以什么业务状态看到"。
> 身份定义来源：[PRD §3.2](../../../docs/prd/prd.md) 与 [CROSS-BATCH-PRINCIPLES.md](../CROSS-BATCH-PRINCIPLES.md) §1。

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| 游客 | 否 | 直接访问时跳转微信授权页；从我的预约/个人中心进入时拦截 |
| 注册用户 | 否 | 无 active 套餐，无上课记录；访问时提示购买套餐 |
| 学员 | 是 | 本人所有已完成/旷课记录的聚合查看入口 |
| 教练 | 否 | 教练端使用教练端页面 |
| 管理员 | 否 | 管理端使用 Web 后台 |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| `booking.status = 已完成` | 教练已确认扣课时 | 显示在列表中，可查看教练记录与学员总结 |
| `booking.status = 旷课` | 学员未到场且教练标记 | 显示在列表中，展示旷课标签与教练备注 |
| `course_record.student_summary_json` 存在 | 学员已填写课后总结 | 记录卡片显示"已总结"标签 |
| `course_record.student_summary_json` 不存在 | 学员未填写课后总结 | 记录卡片显示"待总结"提示 |
| `admin_returned = true` | 管理员返还课时（US-035） | 记录卡片显示"课时已返还"标签 |
| 月份分组 | 按课程结束时间年月分组 | 列表顶部显示月份标题 |

## 3. 元素清单（自上而下）

> **设计原则**：
> 1. **元素清单只描述「有什么元素」以及「元素之间的交互与状态」，不描述具体样式细节。** 颜色、宽度、高度、边距、背景、圆角、字体、字号、阴影等视觉参数**禁止**出现在 page-spec 中。
> 2. 视觉样式以 Calicat 设计稿为唯一最高优先级来源；page-spec 仅对交互逻辑、业务规则、状态流转负责。
> 3. 每个元素必须说明：名称、作用、显示条件、交互行为、关联业务规则。

### 3.5 上课记录卡片（Class Record Card）

> **核心元素**。每个卡片展示一次已完成或旷课的上课记录。
> **来源**：PRD §5.3.3 / US-033 / US-032。

#### A. 卡片整体结构

| 字段 | 值 |
|------|-----|
| 名称 | 上课记录卡片 |
| 作用 | 展示单次上课记录的核心信息 |
| 显示条件 | 列表有记录时显示 |
| 可点击区域 | 整张卡片可点击 → 上课记录详情（本页展开或跳转 `U-预约详情页`） |
| 关联业务规则 | PRD §5.3.3 / US-033 / US-032 |

#### B. 卡片头部行

| 字段 | 值 |
|------|-----|
| 名称 | 卡片头部行 |
| 作用 | 展示日期、星期、课程时间、状态标签 |
| 显示条件 | 每张卡片均显示 |
| 字段内容 | 日期块（如「08/02」）、星期文字、课程时间区间、状态徽标（已完成/旷课）、已总结标签、课时返还标签 |
| 关联业务规则 | PRD §5.3.3 / US-033 |

#### C. 教练与内容区

| 字段 | 值 |
|------|-----|
| 名称 | 教练与内容区 |
| 作用 | 展示教练形象、姓名、课程内容与教练备注 |
| 显示条件 | 所有记录卡片统一显示 |
| 字段内容 | 教练头像、教练姓名、课程内容（无内容时显示"教练未填写内容"）、旷课状态显示教练备注 |
| 关联业务规则 | PRD §5.3.3 / US-033 |

#### D. 课后总结区

| 字段 | 值 |
|------|-----|
| 名称 | 课后总结区 |
| 作用 | 展示或引导填写学员课后总结 |
| 显示条件 | 已完成状态显示；旷课状态隐藏 |
| 字段内容 | 总结标题、总结摘要（未填写时显示"点击填写课后总结"）、编辑按钮 |
| 点击行为 | 点击填写/编辑 → 课后总结表单 |
| 关联业务规则 | US-032 §4.1 / PRD §5.3.3 |

#### E. 卡片状态变体

| 变体 | 触发条件 | 差异说明 |
|------|---------|---------|
| 已完成-有总结 | booking.status = 已完成 且 course_record.student_summary_json 存在 | 显示 "已总结" 标签，课后总结区显示总结摘要 |
| 已完成-无总结 | booking.status = 已完成 且未填写总结 | 不显示 "已总结" 标签，课后总结区显示 "点击填写课后总结" |
| 已完成-课时已返还 | admin_returned = true | 额外显示 "已返还" 标签，课时变动显示 "已返还 1 节" |
| 旷课-有备注 | booking.status = 旷课 且教练填写备注 | 显示 "旷课" 标签，展示教练备注 |
| 旷课-无备注 | booking.status = 旷课 且教练未填写备注 | 显示 "旷课" 标签，备注区显示 "教练未填写备注" |

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 学员无已完成/旷课记录 | 内容区替换为 Empty 组件：游泳主题插画 + "暂无上课记录" + "完成第一节课程后即可查看" + Primary「去预约」按钮 |
| **加载中** | 首次进入 / 切换筛选 / 下拉刷新 | 列表区显示骨架屏（统计摘要占位 + 记录卡片占位） |
| **错误状态** | 网络断开 / 接口 5xx / 业务 4xx | 中央错误插画 + "网络异常，请重试" 或 "服务繁忙，请稍后重试" + Primary「重新加载」按钮 |
| **成功状态** | 数据正常返回 | 按 §4 显示规则矩阵完整展示统计摘要、筛选标签、月份分组、记录卡片；支持展开详情 |

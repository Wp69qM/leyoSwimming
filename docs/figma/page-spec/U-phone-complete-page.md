# 页面规格：U-补充手机号页

> **性质**：Figma 设计交付的唯一指令源。AI 生成 Figma 时**必须**按本规格严格执行。
> **核心约束**：本规格的每一条元素显隐规则必须可追溯到 [PRD](../../prd/prd.md) 或具体 US 的某条业务规则。
> **归属 US**：US-005（用户补充注册资料）/ US-009（用户隐私协议授权与撤回，前置同意校验）
> **对应 PRD**：§3.2 身份状态机、§5.2.1 注册登录、§8.1 注册流程、§11.2 隐私合规、§13.3 MVP 页面 5
> **版本**：v1.0 | **创建日期**：2026-08-02

## 2. 用户身份与业务状态维度

> **本节是 Page Spec 根基**。先定义"谁可能看到这个页面"以及"以什么业务状态看到"。

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| 游客 | ❌ | 未登录用户不应进入此页；若直接进入，先跳转 `U-微信授权页` |
| 注册用户 | ✅ | 当前页面目标用户，需满足 `identity_status='注册用户'` 且 `profile_completed=false` |
| 学员 | ❌ | 学员身份意味着已持有 active 套餐且资料完整，不应进入此页；若通过旧链接进入，自动跳转 `U-首页` |
| 教练 | ❌ | 教练端使用教练端小程序注册流程 |
| 管理员 | ❌ | 管理端使用 Web 后台注册流程 |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| **资料未填写** | 用户刚进入页面，所有表单项为空 | 展示空表单，提交按钮禁用或点击后校验 |
| **填写中** | 用户正在输入手机号/验证码/用户名/密码 | 实时校验手机号格式、密码强度；验证码按钮倒计时中不可点击 |
| **验证码发送中** | 用户点击「获取验证码」，后端正在发送短信 | 验证码按钮进入 60s 倒计时，文案变为「60s 后重新获取」 |
| **提交中** | 用户点击「完成注册」，后端正在保存资料 | 按钮 loading，表单不可编辑 |
| **资料校验失败** | 手机号已注册 / 用户名已存在 / 密码强度不足 / 必填项缺失 | 对应字段下方显示红色错误提示，不跳转 |
| **提交成功** | 后端返回保存成功，`profile_completed=true` | 自动跳转 `U-首页`，顶部显示用户名 |
| **网络错误** | 提交过程中网络断开或后端 5xx | 展示全局错误提示「网络异常，请检查网络后重试」 |

## 5. 跳转动线矩阵

| 触发条件 | 游客 | 注册用户 | 学员 |
|---------|------|---------|------|
| 直接进入本页 | 先跳转 `U-微信授权页` | 若 `profile_completed=false` 停留本页；若 `profile_completed=true` 跳转 `U-首页` | 自动跳转 `U-首页` |
| 点击「完成注册」且成功 | — | → `U-首页` | — |
| 点击《隐私协议》/《用户须知》 | — | → `U-隐私协议页` | — |
| 点击「该手机号已绑定其他账号，请更换或登录」中的「登录」 | — | → `U-登录页` | — |
| iOS 侧滑返回 / 系统返回 | 拦截，不允许返回 | 拦截，不允许返回 | — |

> **强制流程说明**：本页为注册流程终点前的强制步骤，未提交成功前不允许返回上一页或进入首页，避免产生"未完善资料即可使用功能"的状态漏洞。

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 用户首次进入，表单全部为空 | 展示页面标题、微信信息、空表单、未勾选协议；提交按钮可按但点击后触发字段级校验 |
| **加载中** | 获取验证码中 / 提交资料中 | 对应按钮进入 loading；提交时整个表单置灰不可编辑，底部按钮显示「提交中…」 |
| **错误状态** | 字段校验失败 / 手机号或用户名已存在 / 网络或后端错误 | 字段级错误在对应表单项下方显示红色文案；网络/后端错误在底部按钮上方显示全局错误提示区 |
| **成功状态** | 后端返回保存成功，`profile_completed=true` | 页面保持 300ms 后淡出，自动跳转 `U-首页`；首页顶部显示用户名 |

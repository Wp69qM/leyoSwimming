## 2. 用户身份与业务状态维度

> **本节是 Page Spec 根基**。先定义"谁可能看到这个页面"以及"以什么业务状态看到"。

### 2.1 适用身份

| 身份 | 是否可见 | 差异说明 |
|------|:-------:|---------|
| 游客 | ✅ | 当前页面目标用户；展示手机号输入、验证码输入、登录按钮 |
| 注册用户 | ❌ | 已登录用户不应进入此页；若通过旧链接/分享进入，自动跳转 `U-首页` |
| 学员 | ❌ | 已登录用户不应进入此页；若通过旧链接/分享进入，自动跳转 `U-首页` |
| 教练 | ❌ | 教练端使用教练端小程序登录流程 |
| 管理员 | ❌ | 管理端使用 Web 后台登录流程 |

### 2.2 关键业务状态

| 状态 | 含义 | 对本页影响 |
|------|------|-----------|
| **未发起登录** | 用户刚进入页面，尚未输入手机号 | 展示手机号输入框、清空验证码输入框、获取验证码按钮禁用（等待合法手机号输入） |
| **手机号已输入** | 用户已输入合法手机号 | 「获取验证码」按钮高亮可用 |
| **验证码发送中** | 用户点击「获取验证码」，系统请求短信服务 | 按钮进入 loading，显示「发送中…」，防止重复点击 |
| **验证码已发送** | 短信服务返回成功，验证码 5 分钟内有效 | 按钮变为倒计时「60s 后重发」，验证码输入框自动聚焦 |
| **登录中** | 用户点击「登录」，后端校验手机号与验证码 | 登录按钮进入 loading，显示「登录中…」，防止重复提交 |
| **新用户首次登录** | 手机号未注册，验证码正确，系统自动创建账号 | 登录成功后自动跳转 `U-完善个人资料页`（US-005） |
| **已注销手机号重新登录** | user 表中存在该手机号但 `status=1`（已注销），验证码正确 | 按 PRD §5.2.1 第 4 条重新创建新 user 记录，`identity_status='注册用户'`，`profile_completed=false`，登录成功后自动跳转 `U-完善个人资料页`（US-005） |
| **老用户已完善资料** | 手机号已注册且 `profile_completed=true` | 登录成功后自动跳转 `U-首页` |
| **老用户资料不完整** | 手机号已注册但 `profile_completed=false` | 登录成功后自动跳转 `U-完善个人资料页`（US-005） |
| **手机号格式错误** | 用户输入的手机号不符合中国大陆手机号格式 | 输入框标红，提示「请输入正确的手机号」，不发送验证码 |
| **验证码错误/过期** | 用户提交的验证码错误或已过期 | 验证码输入框标红，提示「验证码错误或已过期」 |
| **验证码发送限流** | 用户 60 秒内重复点击获取验证码 | 按钮保持倒计时，提示「请 60 秒后再试」 |
| **短信服务失败** | 短信服务不可用或接口异常 | 提示「验证码发送失败，请稍后重试」 |
| **未勾选协议** | 用户点击登录按钮但未勾选隐私协议 | 提示「请阅读并同意《用户须知》和《隐私协议》」，不执行登录 |

## 5. 跳转动线矩阵

> 本页所有跳转由用户主动点击或登录成功后自动触发。

| 触发条件 | 游客 | 注册用户 | 学员 |
|---------|------|---------|------|
| 点击「登录」且成功 + `is_new_user=true` | → `U-完善个人资料页` | — | — |
| 点击「登录」且成功 + `profile_completed=true` | → `U-首页` | — | — |
| 点击「登录」且成功 + `profile_completed=false` | → `U-完善个人资料页` | — | — |
| 点击「使用微信一键登录」 | → `U-微信授权页` | — | — |
| 点击《隐私协议》/《用户须知》 | → `U-登录页协议浮层` | US-009 |
| 已登录用户通过旧链接进入 | — | 自动 → `U-首页` | 自动 → `U-首页` |

> **登录成功后的回跳逻辑**：若用户从受登录限制的功能（如购买套餐、预约）被引导至本页，登录成功后应返回原页面并刷新身份状态；若直接打开本页，登录成功后按 `profile_completed` 跳转首页或完善资料页。

### 5.1 跳转参数说明

| 参数 | 类型 | 来源 | 用途 |
|------|------|------|------|
| source_page | string | 拦截来源页 | 记录用户从哪个页面被引导至登录页，用于登录成功后回跳 |
| target_action | string | 拦截来源操作 | 如 `purchase_package` / `book_slot`，登录成功后继续该操作 |
| phone | string | 用户输入 | 登录手机号 |
| code | string | 用户输入 | 短信验证码 |
| is_new_user | boolean | 后端返回 | 判断新/老用户 |
| profile_completed | boolean | 后端返回 | 判断资料是否完善 |

## 6. 四态设计

| 状态 | 触发 | 表现 |
|------|------|------|
| **空状态** | 页面首次加载，未输入任何内容 | 表单为空，获取验证码按钮可点击（手机号为空时禁用），登录按钮禁用 |
| **加载中** | 获取验证码中 / 登录提交中 | 对应按钮 loading，其他表单元素不可交互 |
| **错误状态** | 手机号格式错误 / 验证码错误 / 短信服务失败 / 未勾选协议 | 对应输入框标红，错误提示区显示动态文案 |
| **成功状态** | 手机号验证码校验通过 | 登录按钮保持成功态 300ms 后，以淡出动效离开并跳转目标页 |

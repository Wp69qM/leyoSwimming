# 【乐游】游泳约课系统 - 产品需求文档（v6 已确认版）

## 1. 项目概述

### 1.1 产品定位
打造一个面向游泳场馆的约课与运营管理平台，支持多类用户身份，覆盖小程序端与后台管理系统，未来可扩展为移动端 App。

### 1.2 核心价值
- 对潜在用户：透明化教练、套餐、场馆信息，降低决策门槛。
- 对学员：数字化管理课时、记录成长轨迹、获取教学反馈。
- 对自由游泳者：便捷购卡、记录游泳数据、查看场馆状态。
- 对教练：数字化管理学员与课时，通过数据优化教学策略。
- 对场馆：提升运营效率，沉淀数据资产，辅助经营决策。

### 1.3 目标平台
1. 微信小程序（用户端）
2. Web 后台管理系统（管理员、教练复杂操作）
3. 未来可扩展：iOS / Android App（与小程序数据互通）

---

## 2. 版本规划

### 2.1 MVP（第一阶段）：核心约课闭环
目标：让注册用户能变成学员或自由游泳者，教练能上课，管理员能管理。

- 游客浏览公开信息
- 用户注册登录
- 实名认证后方可预约与购课
- 教练信息维护与可约时间配置
- 用户购买体验课后获得体验用户标签，可预约对应教练体验课
- 用户购买正价套餐后成为学员，绑定教练，可约正课
- 每周固定时间释放下周可约时段（默认周三 10:00，后台可配置）
- 满员时段支持排队候补
- 自由游泳者购买次卡 / 月卡、入场签到
- 微信支付 / 支付宝支付
- 上课记录与课时消耗
- 基础消息通知（预约、取消、课前提醒、候补转正）
- 管理员：用户管理、订单管理、基础数据看板

### 2.2 第二阶段：体验优化与运营提效
- 周期性预约 / 固定课程
- 退款 / 退课流程
- 发票 / 收据管理
- 教练绩效与收入结算
- 评价与反馈闭环
- 学员等级与能力评估体系
- AI 数据查询助手

### 2.3 第三阶段：智能化与增长
- AI 视频动作分析（可能使用云端服务，按使用量计费）
- 学员画像与教练推荐
- 营销裂变（老带新、拼团、优惠券）
- 社区 / 打卡 / 内容库
- 物联网硬件联动（闸机、手环、智能柜）
- 多场馆支持

## 3. 用户身份与角色

### 3.1 身份状态定义

系统中用户身份是**动态、可叠加**的，不是互斥角色。

| 身份 / 标签 | 定义 | 获得条件 | 可访问功能 |
|------|------|----------|-----------|
| **游客** | 未登录或未注册的访问者 | 打开小程序但未登录 | 浏览教练列表、套餐、场馆公告、教练详情 |
| **注册用户** | 已完成注册登录，但尚未购买任何服务 | 完成微信授权 + 补充手机号等基本信息 | 预约体验课、购买套餐、购买次卡 / 月卡、查看个人中心 |
| **体验用户** | 已购买体验课的注册用户 | 购买体验课后获得标签 | 预约已购买体验课的教练的体验课时间 |
| **学员** | 已购买正价教练课程套餐 | 购买正价套餐 / 自定义套餐后生效 | 预约绑定教练的正课、查看课时记录、查看上课视频、评价教练 |
| **自由游泳者** | 已购买游泳次卡 / 月卡 | 购买次卡 / 月卡 / 储值卡后生效 | 入场签到、记录游泳数据、查看卡内余额或有效期 |

### 3.2 身份叠加规则

1. 一个用户可以同时拥有多个身份 / 标签。
2. 常见组合示例：
   - 用户 A 买了体验课 → **注册用户 + 体验用户**
   - 用户 A 又买了 10 节私教课 + 20 次游泳卡 → **学员 + 自由游泳者**
   - 用户 B 只买了次卡，没买课 → **自由游泳者**，不是学员
   - 用户 C 注册完什么都没买 → **注册用户**
   - 用户 D 课时用完、月卡过期 → 身份失效，变回**注册用户**
3. 身份过期后，历史数据保留，用户可继续查看历史记录。

### 3.3 身份转换流程

```
游客
  ↓ 微信授权 + 补充信息
注册用户
  ├─ 购买体验课 ───────→ 体验用户
  ├─ 购买正价套餐 ─────→ 学员
  └─ 购买次卡 / 月卡 ──→ 自由游泳者

体验用户 + 学员（可同时具备，但体验课和正课分开管理）
```

### 3.4 角色定义（与身份状态区分）

| 角色 | 定义 | 说明 |
|------|------|------|
| **教练** | 在平台提供教学服务的人员 | 可管理自己的预约、学员、上课记录；教练账号为独立角色，不与学员 / 自由游泳者身份重叠 |
| **系统管理员** | 平台运营管理人员 | 管理用户、订单、套餐、数据、公告、AI 配置 |

说明：教练账号是独立角色，不叠加学员或自由游泳者身份。教练本人若需购课或购卡，需使用另外的注册用户账号。

## 4. 各身份 / 角色功能模块

### 4.1 游客功能

1. 浏览教练列表与教练详情（姓名、证书、任教年限、评分、评价）。
2. 查看系统套餐及价格。
3. 查看场馆公告：开放时间、换水时间、拥挤情况。
4. 查看场馆信息：名称、地址、导航。
5. 查看下周预约释放时间公告与倒计时。
6. 触发注册：预约体验课、购买套餐、购买次卡 / 月卡时需先注册登录。

---

### 4.2 注册用户功能

#### 4.2.1 注册登录
1. 支持微信授权登录，首次登录后补充手机号、用户名、密码、邮箱。
2. 支持手机号验证码登录。
3. 支持账号密码登录。
4. 支持账号注销与数据删除申请。
5. **实名认证**：预约体验课、购买正课套餐、购买次卡 / 月卡前必须完成实名认证。

#### 4.2.2 账号安全
1. 手机号换绑、密码修改、邮箱绑定。
2. 登录设备管理。
3. 隐私协议授权与撤回。

#### 4.2.3 转化入口
1. 购买体验课，获得「体验用户」标签，可预约对应教练的体验课。
2. 购买正课套餐，成为正式学员。
3. 购买次卡 / 月卡成为自由游泳者。

---

### 4.3 体验用户功能

获得条件：购买体验课标准套餐（一般为一对一任意泳姿 1 节课，由管理员在后台配置）。

1. 查看已购买体验课的教练详情与可约时间。
2. 预约该教练的体验课时间，无需再次支付（体验课已提前购买）。
3. **体验课有效期**：自购买之日起 30 天内有效（后台可配置），过期未使用自动失效，用户可申请退款或重新购买。
4. 课前 24 小时外可随时取消体验课预约。
5. **体验课签到**：学员到馆后可在小程序内点击「一键签到」，或经前台扫码 / 闸机刷脸完成入场登记；签到仅用于通知教练和固定搭档已到场，不强制签到，也不扣除课时。体验课结束后由教练点击「确认上课」完成课时消耗。
6. 不想体验时可申请退款。
7. **体验课教练更换规则**：体验课购买后不可更换教练；如需更换教练，需先申请退款，再重新购买目标教练的体验课。
8. 体验课退款成功后，系统自动移除「体验用户」标签，用户恢复为普通注册用户。
9. 体验课结束后可评价教练，并选择是否购买正价套餐。

---

### 4.4 学员功能

获得条件：购买正价教练课程套餐（含自定义套餐）。

#### 4.4.1 教练与套餐浏览
1. 查看所有教练列表与详情（姓名、证书、任教年限、评分、评价、可约时间、实时状态）。
2. 教练实时状态包括：空闲中、上课中、休息中、已下班、请假中；在教练列表卡片和详情页以圆点 / 标签形式展示。
3. 教练详情页展示微信二维码与手机号，学员可直接扫码加微信或拨打电话联系。
4. 教练详情页提供「发起聊天」按钮；若教练处于上课中 / 已下班 / 休息中，系统提示「教练当前较忙，可能延迟回复」。
5. 查看系统套餐：
   - **标准套餐**：由管理员在后台配置，例如一对一任意泳姿 8 节课、一对一任意泳姿 10 节课、一对一任意泳姿 1 节课（即体验课标准套餐）等。
   - **自定义套餐**：学员可自由选择教练、泳姿、课时数量、人数类型（一对一 / 一对二 / 一对三）等。
6. 查看折扣活动与优惠信息。
7. **更换绑定教练规则**：首期不支持直接更换绑定教练。如学员确需更换，可申请退掉剩余未上课时，再重新购买新教练的套餐；退款规则按标准退款流程执行。

#### 4.4.2 预约功能
1. 正价套餐学员进入预约页面时，默认显示已绑定教练的可约时间段，无需再次选择教练。
2. 查看教练可约时间段，可预约未来 7 天内的课程。
3. **预约释放规则**：每周三上午 10:00 统一释放下周（周一至周日）的可约时段；具体释放时间、释放范围由管理员在后台配置。
4. 首页显示释放倒计时：释放前 24 小时显示「距离下周预约开放还有 XX 小时」；释放当天显示「今日 10:00 开放下周预约」。
5. **预约锁单机制**：用户点击「提交预约」后，系统立即锁定该时段，其他用户看到该时段为「已锁定」或「已约满」；同一时段多人并发提交时，仅第一个成功，其余用户收到「已被他人预约」提示。
6. **正价套餐学员**：提交预约即预约成功，系统自动从课时包中预占 1 节课时；课程结束后由教练确认并手动点击「扣除课时」，系统才正式扣减课时；课前 24 小时外取消则释放预占课时。
7. **学员签到方式**：学员到馆后可在小程序内点击「一键签到」，或经前台扫码 / 闸机刷脸完成入场登记；签到仅用于通知教练和固定搭档已到场，不强制签到，也不扣除课时。游泳过程中不带手机，以教练端记录为准。课程结束后由教练点击「确认上课并扣除课时」，系统才正式扣减课时。
8. 预约成功后生成预约卡片，显示时间、教练、状态。
9. 24 小时外可随时取消，释放预占课时；24 小时内取消需教练审批，审批通过后立即释放预占课时，若教练在 24 小时内未处理，默认视为拒绝取消。
10. **学员未到场（旷课）处理**：学员未取消也未签到，教练可在课程结束后标记「学员未到课」，系统释放预占课时，该节课不扣课时；如需扣课时，由教练与学员线下协商后管理员手动处理。
11. 满员时段可排队候补；有人取消时按候补顺序自动转正并通知。
12. **候补规则**：用户可同时加入多个时段的候补队列；若其中一个时段候补成功，其他候补订单自动取消。
13. **关注时段**：用户可关注心仪时段，释放前或有人取消时收到提醒；关注不强制排队，适合不希望被自动预约的用户。
14. 候补与关注为两种可选方式，用户可根据偏好选择。
15. **周期性预约固定时间**：
    - 学员可选择固定教练、固定星期、固定时间段，预约未来 N 周（如 4 周 / 8 周 / 12 周）。
    - 每周排班表发布后，系统自动生成一系列预约记录，并从学员课时包中预占对应课时；这些时段在教练排班表中显示为「周期性预约」卡片，默认置灰不可再开放给其他用户。
    - 教练可在排班表中查看每张周期性预约卡片内的学员信息。
    - 若遇场馆闭馆、换水、教练请假，系统自动跳过该次预约，不扣除学员课时，并同时通知学员与教练。
    - 学员可在通知中一键将该次课程改约到其他可用时段，或保留课时后续使用。
    - **周期性预约取消规则**：开课前 24 小时外，学员可取消单次或整个周期预约，取消后释放对应预占课时；开课前 24 小时内原则上不可取消，特殊情况由教练与学员协商处理。

#### 4.4.3 一对多套餐与搭档
1. 一对多套餐最多支持 3 人（后台可配置，默认上限 3 人）。
2. 一对多套餐学员可维护固定搭档信息：姓名、手机号、游泳等级。
3. **固定搭档绑定规则**：固定搭档必须在平台注册并完成实名认证，由教练或管理员将两名学员绑定为固定搭档关系；双方确认后生效。
4. **固定搭档解除与更换**：任一学员可在个人中心申请解除固定搭档关系，解除后不影响历史订单；如需更换搭档，需先解除原关系，再由教练或管理员重新绑定新搭档。
5. **固定搭档通知**：固定搭档其中一方完成签到或入场后，系统通过微信订阅消息 / 服务通知即时通知另一方；若对方未关注小程序或关闭订阅消息，则通过短信或应用内消息补发提醒。
6. 不固定搭档模式：预约界面显示已预约人数、还差几人拼课成功。
7. 教练可查看所有拼课成功的学员列表；若开课前 24 小时未拼课成功，系统自动取消该预约，释放该时段，并通知关注该时段的用户和候补队列，其他用户可继续预约。
8. **拼课成功后有人退出的处理**（建议采用弹性规则，默认由教练决定）：
    - 一对二套餐最低开课人数为 2 人，一对三套餐最低开课人数为 3 人（后台可配置）。
    - 开课前 24 小时外有人退出，剩余人数满足最低开课人数 → 课程继续。
    - 开课前 24 小时外有人退出，人数不足 → 系统自动取消整节课，通知其他学员，不扣课时；或教练决定是否改为一对一补课（需补差价或协商）。
    - 开课前 24 小时内原则上不可取消；特殊情况由教练与学员协商处理。
9. **预约卡片分享**：
    - 所有预约卡片均支持分享，包括可约时段、一对多拼课中、已预约成功等状态。
    - 学员和教练均可将一对多预约卡片分享到微信聊天或朋友圈，便于快速找到搭档或帮学员拼课。
    - 教练还可分享自己空闲的可约时段到朋友圈，吸引新用户预约。
    - 分享页展示：时间、教练、当前状态（可约 / 已满 / 拼课中）、已预约人数、还差几人、套餐类型。
    - 不同身份查看权限：
      - 游客：可查看基础信息，点击预约时引导注册登录。
      - 注册用户：可预约体验课、加入候补、关注时段。
      - 学员：如套餐类型匹配，可直接预约正课或加入拼课。
      - 卡片分享者本人：可查看完整预约详情。
10. **套餐类型与选项规则**：
    - **人数类型**：一对一、一对二、一对三（后台可配置上限，默认一对一 / 一对二 / 一对三）。
    - **教学泳姿**：蛙泳、自由泳、蝶泳、仰泳；用户购买时选择主要练习泳姿。
    - **搭档模式**（仅一对二 / 一对三可选）：
      - 固定搭档：用户维护固定搭档信息，预约时自动带入选项。
      - 不固定搭档：系统根据条件自动撮合，预约界面显示已预约人数与还差人数。
    - **搭档性别要求**（非强制）：男、女、不限；仅作为撮合参考，不强制限制。
    - 不同套餐类型不可混约，例如买一对二的用户不能加入一对一的预约。
11. 临时沟通群：拼课成功后，系统自动创建一个临时聊天窗口（类似美团订单的临时会话），参与该节课的所有学员与教练可在群内沟通预约时间、到场时间、集合地点、装备准备等事项；课程结束后聊天窗口自动关闭或归档。

#### 4.4.4 课时与上课记录
1. 查看总课时、已上课时、剩余课时。
2. **多套餐课时消耗顺序**：学员同时拥有多个有效套餐时，系统默认按「有效期近的优先、有效期相同按购买时间先后（FIFO）」扣减；管理员可在后台调整扣减优先级。
3. 查看历史上课记录：时间、教练、内容、视频。
4. 每节课后填写自我总结：身体感受、学习效果、问题反馈。
5. 对教练进行评价：教学清晰度、速度、效果。
6. **评价时间窗口与回复**：学员可在课程结束后 7 天内提交评价，逾期不可补评；教练可对评价进行公开回复，回复后学员不可再次修改评价。
7. **评价展示规则**：学员对教练的评分汇总后展示在教练详情页；具体评价内容对其他用户公开或仅管理员可见，后台可配置。

#### 4.4.5 购买与支付
1. 购买套餐生成订单，支持微信支付、支付宝支付。
2. 查看订单列表与支付状态。
3. 申请退款 / 退课（按比例计算）。
4. **退款手续费**：退款时若涉及手续费，系统需明确提示用户，用户确认后再进入退款流程。
5. 申请电子发票。

#### 4.4.6 视频与学习

1. 查看教练上传的本节课视频。
2. 上传自己的游泳视频（可选）。
3. **视频可见范围**：教练上传的教学视频仅学员本人及关联教练可见；学员上传的游泳视频默认仅学员本人及关联教练可见，学员可选择是否对平台其他用户公开（后台可配置默认权限）。
4. AI 分析游泳动作，给出改进建议（第三阶段）。

#### 4.4.7 AI 助理
1. 查询泳池拥挤情况、教练空闲时间。
2. 查询自己的上课记录、剩余课时。
3. 推荐教练、泳姿、训练时间。
4. 根据画像推荐合适的套餐。

### 4.5 自由游泳者功能

#### 4.5.1 游泳记录
1. 查看历史游泳记录统计。
2. 今年游了多少次、总共多长时间。

#### 4.5.2 场馆信息

2. 查看场馆名称、地址、导航。

#### 4.5.3 次卡 / 月卡

2. 查看卡内剩余次数或有效期。

#### 4.5.4 转化入口

2. 通过 AI 助理分析游泳习惯并推荐课程。

### 4.6 教练功能

#### 4.6.1 入驻与资料
1. 首次注册需上传：证书、任教年限、总学员数、总课时数、个人简介。
2. 入驻资质需管理员审核。
3. 个人主页展示任教年限、证书、总课时、带过的学生总量、评分、评价、微信二维码、手机号。
4. 教练可设置一节课的参考单价，作为系统套餐定价和自定义套餐金额计算的基准；实际订单金额可在审批时协商调整。
5. 教练可设置自己的实时状态：空闲中、上课中、休息中、已下班、请假中。
6. 系统根据教练当前课程安排自动切换状态：课程开始前 15 分钟自动变为「上课中」，课程结束后 15 分钟自动恢复为「空闲中」或「已下班」（根据当日排班）。
7. 教练手动设置的状态优先级高于自动状态，但请假状态由请假审批自动同步。

#### 4.6.2 预约管理
1. 以日 / 周 / 月 / 年维度查看预约卡片。
2. 点击卡片查看预约详情：学员姓名、年龄、手机号、游泳等级、学习泳姿、基础情况、已上课时、剩余课时；学员信息页展示学员微信二维码与手机号，教练可直接扫码加微信或拨打电话联系。
3. 学员信息页提供「发起聊天」按钮，教练可直接在小程序内与学员建立一对一临时会话，沟通上课时间、注意事项、到馆安排等。
4. 确认预约、拒绝预约、协商时间。
5. 上课前 10 分钟查看学员入场状态，未入场可一键提醒。
6. 教练可帮学员代约或锁课：
   - **代约**：教练代替学员提交预约，系统按正常预约规则从学员课时包中预占 1 节课时。
   - **锁课**：教练为学员保留某个时段，该时段对其他人不可见，但不预占课时；学员需在 24 小时内确认，超时未确认系统自动释放该时段；学员确认后转为正式预约并预占课时。
7. 教练可将一对多预约卡片分享到微信，帮助学员快速找到搭档拼课。
8. 教练可将自己的空闲可约时段分享到朋友圈，吸引新用户预约体验课或正课。

#### 4.6.3 上课记录
1. 记录每节课时间、内容、学员学习情况。
2. 记录课时消耗：总课时、已用课时、剩余课时；课程结束后教练手动点击「确认上课并扣除课时」，系统才正式从学员课时包中扣减。教练需在课程结束后 24 小时内完成确认，超时未确认系统自动扣减该节课时并通知学员与教练。
3. 支持结构化标签：今日重点、掌握程度、课后作业。
4. 支持语音输入快速记录。
5. 上传照片 / 视频作为本节课记录。

#### 4.6.4 学员信息维护
1. 教练可维护自己关联学员的信息切片。
2. 默认从学员自填信息带入，教练可根据沟通情况更新。
3. 仅影响该教练视角，不影响其他教练或学员本人信息。
4. 可查看学员评价、反馈、历史总结。
5. 可标记学员是否为未成年人；如为未成年人，可维护监护人联系方式。

#### 4.6.5 请假处理
1. 教练提交请假申请，管理员审批。
2. 请假审批通过后，系统根据请假时间自动取消已预约的课程，并自动发送取消通知给相关学员。
3. 教练可填写取消原因或改约建议，一并通知学员。
4. 学员收到通知后可选择改约其他可用时间或保留课时。

#### 4.6.6 AI 助理
1. 查询自己的预约情况、学员信息、上课记录、评价反馈。
2. 生成图表：课时统计、学员增长、收入趋势。
3. 生成经营分析：淡季 / 旺季判断、学员画像、高转化人群特征。
4. 生成学员评价报告：学习进度、动作标准度、对水恐惧程度等。

#### 4.6.7 收入结算
1. 教练收入模式支持按场馆 / 按教练配置：平台抽成、固定课时费、或混合模式。
2. 具体计费规则需在上线前结合市场调研确定。
3. 教练可在个人中心查看收入明细、提现申请。

### 4.7 系统管理员功能

#### 4.7.1 用户与身份管理
1. 查看所有游客、注册用户、体验用户、学员、自由游泳者账号。
2. 重置密码、手机号、邮箱。
3. 配置角色权限。
4. 教练入驻资质审核。
5. 管理实名认证信息。
6. 绑定固定搭档关系。
7. **教练离职 / 取消入驻处理**：管理员取消教练入驻资格或教练主动离职时，系统自动将该教练未上完的学员课时标记为待处理；管理员可为受影响学员安排其他教练承接剩余课时，或按退款流程处理。

#### 4.7.2 教练排班与预约释放管理
1. 查看所有教练排班表。
2. 添加、删除、修改排班时间。
3. 查看请假申请，同意或拒绝。
4. 配置下周可约时间并一键发布到小程序。
5. **预约释放规则配置**：
   - 设置每周固定释放时间（默认周三 10:00）。
   - 设置释放范围（如下周整周或未来 7 天）。
   - 设置是否启用候补队列、候补有效期。
   - 设置关注提醒提前时间。
   - 特殊情况下可手动提前或延迟释放。
   - **节假日处理**：若节假日不营业，管理员可提前释放下一周可约时段，并通过公告通知用户。
6. **预约规则说明**：单个课程预约采用先抢先得机制，无需教练二次确认；教练确认 / 协商环节仅在购买套餐时触发。

#### 4.7.3 套餐与订单
1. **标准套餐配置**：由管理员在后台预设固定套餐，例如：
   - 一对一任意泳姿 1 节课（体验课标准套餐）
   - 一对一任意泳姿 8 节课
   - 一对一任意泳姿 10 节课
   - 一对二任意泳姿 10 节课
   - 每个标准套餐可设置是否需教练审批。
2. **自定义套餐配置**：学员在购买时可自由选择：
   - 教练
   - 教学泳姿：蛙泳 / 自由泳 / 蝶泳 / 仰泳
   - 课时数量（如 1 次、5 次、10 次、20 次等）
   - 人数类型：一对一 / 一对二 / 一对三
   - 搭档模式（一对二 / 一对三可选）：固定 / 不固定
   - 搭档性别要求（非强制）：男 / 女 / 不限
   - 系统根据所选教练的课时单价自动计算参考总价。
   - 自定义套餐可设置是否需教练审批。
3. **教练课时单价参考**：每个教练可设置一节课的参考单价，作为套餐定价的基准；实际成交金额可由教练在订单审批时协商调整。
4. 配置一对多套餐的人数上限（默认 3 人）。
5. 配置折扣活动、优惠券。
6. 查看所有订单，确认或拒绝订单。
7. 处理退款、价格调整、套餐次数调整。
8. **订单生效规则**：
   - 未设置教练审批的套餐，学员支付后订单自动生效，身份相应变更为学员 / 自由游泳者。
   - 设置教练审批的套餐，生成订单后教练需在 24 小时内完成确认 / 拒绝 / 协商；超时未处理，系统自动取消该订单并通知用户，用户可重新下单或选择其他教练。
   - 设置教练审批的套餐，需教练确认 / 协商后由学员确认并支付；若学员拒绝教练修改的方案，订单自动取消。支付后订单自动生效。
   - 管理员可在后台查看订单，处理异常、退款和价格调整，无需对每个正常订单进行人工确认。

#### 4.7.4 场馆与公告
1. 配置场馆名称、地址、导航、开业年限、泳池状态。
2. 场馆闭馆 / 换水设置：管理员设置闭馆日期后，系统自动检测受影响的周期性预约，自动跳过并通知相关学员与教练。
3. 配置免责声明、健康申报模板。

#### 4.7.5 通知栏与首页运营
1. **首页通知栏（Notice Bar）**：
   - 用于展示轻量、时效性强的公告，无需设计卡片。
   - 支持的内容类型：
     - 泳池状态（开放 / 换水 / 闭馆）
     - 开放时间 / 换水时间提醒
     - 下周预约释放倒计时
     - 节假日提前释放通知
     - 临时紧急公告
   - 展示形式：固定置顶条或横向滚动轮播，支持多条公告按优先级排序。
   - 样式类型：普通（蓝色）、提醒（黄色）、紧急（红色）。
   - 可设置可见范围（全部 / 仅学员 / 仅教练等）。

2. **首页 Banner 配置**：上传游泳馆照片、活动海报，支持设置跳转链接（如套餐详情页、活动页、教练详情页）。

3. **首页卡片配置**：用于运营活动和功能入口，如：
   - 折扣活动卡片（如 618 大促、新用户专享）
   - 热门教练推荐卡片
   - 自由游泳者购卡入口卡片
   - 邀请好友得奖励卡片

4. **卡片可见范围配置**：每张卡片可设置对哪些身份 / 角色可见：
   - 全部可见
   - 仅游客 / 注册用户可见（拉新转化）
   - 仅学员可见
   - 仅自由游泳者可见
   - 仅教练可见

5. **排序与有效期**：支持配置通知栏公告顺序、卡片展示顺序、上线时间、下线时间。
6. **预览机制**：配置首页通知栏、Banner、卡片时，支持实时预览效果，无需审核直接生效。

#### 4.7.6 数据看板
1. 游泳高峰期（按小时 / 天 / 周 / 月）。
2. 学习游泳高峰期。
3. 每月总课时、各教练课时。
4. 教练评分、投诉情况。
5. 学员画像：性别、年龄、泳姿分布、消费情况。
6. 每天各时段人数分布。
7. 转化率、续费率、退课率、坪效等经营指标。
8. 预约释放数据：释放时段点击率、候补转化率、热门教练 / 时段分布。
9. 教练实时状态监控：当前空闲、上课中、休息、下班、请假的教练数量分布。

#### 4.7.7 客服与工单
1. 接收学员投诉、建议、换教练申请。
2. 工单流转：提交 → 处理 → 反馈 → 关闭。

#### 4.7.8 AI 配置
1. 选择 AI 模型（OpenAI、DeepSeek、通义千问等）。
2. 配置温度、最大 Tokens、提示词。
3. 配置 AI 可访问的数据范围。
4. AI 视频分析服务可选本地或云端，云端按使用量计费。

## 5. 消息通知体系

### 5.1 通知渠道

1. 小程序内消息中心。
2. 微信订阅消息 / 服务通知。
3. 短信通知（重要事件）：当微信订阅消息未送达或事件优先级较高时启用，例如支付成功、退款到账、课程取消、场馆临时闭馆、次卡 / 月卡到期前 3 天提醒、账号安全相关操作等。

### 5.2 通知场景
1. 预约成功 / 失败 / 取消 / 协商。
2. 排队候补转正通知。
3. 预约释放前提醒（释放前 24 小时、释放前 1 小时）。
4. 节假日提前释放公告通知。
5. 关注时段空出提醒。
6. 课前提醒（学员与教练可自定义提前时间）。
7. 入场通知（学员入场提醒教练）。
8. 教练提醒学员入场。
9. 订单状态变更。
10. 场馆闭馆 / 开放时间变更。
11. 次卡 / 月卡到期提醒。
12. 身份状态变更通知（如购买成功后成为学员）。
13. 应用内即时通讯新消息提醒。
14. 周期性预约因场馆闭馆 / 换水 / 教练请假自动跳过的通知。
15. 一对多拼课失败，时段释放后可继续预约的通知。
16. 教练请假导致课程取消的通知。

### 5.3 应用内即时通讯
1. 支持一对一临时会话：学员与教练可在小程序内直接发起聊天，无需跳转微信或电话。
2. 支持一对多临时群聊：一对多套餐拼课成功后，系统自动创建临时群聊，参与学员与教练可在群内沟通。
3. 聊天场景：预约时间确认、到场时间、集合地点、装备准备、课后反馈、临时请假等。
4. 聊天记录保存至服务端，关联对应订单或预约记录，便于纠纷处理与服务追溯。
5. 课程结束或订单完成后，临时会话可自动归档，不再允许新消息，但历史记录可查看。
6. 支持发送文字、图片、语音消息；未来可扩展发送场馆位置、预约卡片等结构化消息。
7. 消息通知：收到新消息时，通过小程序服务通知 / 订阅消息推送提醒；同时在小程序底部导航或「我的」页面显示未读消息红点 / 数字角标。
8. 未读消息管理：用户可查看所有未读消息列表，支持一键已读；对方已读状态可显示（可选）。

## 6. 核心流程图

### 6.1 用户身份转换流程
```
游客
  ↓ 浏览信息，触发注册
注册用户
  ├─ 购买体验课 ───────→ 体验用户
  ├─ 完成实名认证 + 购买正价套餐 ─────→ 学员
  └─ 完成实名认证 + 购买次卡 / 月卡 ───→ 自由游泳者
```

### 6.2 预约释放与候补流程
```
管理员配置下周排班
    ↓
每周三 10:00 系统自动释放下周可约时段（节假日可提前释放并公告）
    ↓
用户查看可约时间
    ├─ 有库存 → 提交预约 → 系统锁定时段 → 预约成功
    └─ 已满员 → 加入候补队列 / 关注该时段
                    ↓
            有人取消预约
                    ↓
            按候补顺序自动转正 → 发送通知
```

### 6.3 体验课购买与预约流程
```
用户浏览教练
    ↓
购买体验课（选择教练）
    ↓
支付成功 → 获得「体验用户」标签
    ↓
预约该教练的体验课时间（无需再次支付）
    ↓
预约成功 → 发送通知
    ↓
上课前提醒
    ↓
学员到馆签到 → 教练收到通知
    ↓
上课
    ↓
教练记录上课内容 → 点击「确认上课」
    ↓
学员课后评价 → 可选择购买正价套餐
```

注：学员签到为自愿行为，仅用于通知教练已到场，不强制、不扣课时；体验课结束后由教练点击「确认上课」完成课时消耗。

### 6.4 正价套餐学员预约流程
```
选择上课时间（教练已绑定）
    ↓
提交预约 → 系统立即锁定该时段，并预占 1 节课时
    ↓
预约成功 → 发送通知
    ↓
上课前提醒
    ↓
学员到馆签到 → 教练收到通知
    ↓
上课
    ↓
教练记录上课内容 → 点击「确认上课并扣除课时」→ 系统正式扣减课时
    ↓
学员课后总结与评价

注：课前 24 小时外取消，释放预占课时；24 小时内取消需教练审批，审批通过后立即释放预占课时。学员签到为自愿行为，仅用于通知教练已到场，不强制、不扣课时。课程结束后教练需在 24 小时内点击「确认上课并扣除课时」，超时系统自动扣课时。
```

### 6.5 购买正价套餐流程
```
用户浏览套餐
    ↓
选择套餐 / 自定义套餐 → 选择教练
    ↓
生成订单
    ↓
判断套餐是否需审批
    ├─ 是 → 教练确认 / 拒绝 / 协商（可修改价格 / 次数）
    │       ↓
    │       用户确认
    │       ↓
    │       支付
    │       ↓
    └─ 否 → 直接支付
            ↓
      支付成功 → 系统自动确认订单 → 身份变更为学员 → 订单生效
```

注：
- 每个套餐均可配置是否需教练审批。当套餐设置为「需审批」时，生成订单后教练需在 24 小时内完成确认 / 拒绝 / 协商（可修改价格 / 次数）；超时未处理，系统自动取消该订单并通知用户。用户确认教练方案后再支付；若用户拒绝教练修改的方案，订单自动取消。未设置审批时可直接支付。
- 支付成功后订单自动生效，管理员无需对每个正常订单进行人工确认。
- 新学员首次购课或首次预约体验课前，需完成健康承诺书签署和免责协议电子签署，否则无法提交订单。

### 6.6 购买次卡 / 月卡流程
```
用户浏览次卡 / 月卡
    ↓
选择卡种
    ↓
完成实名认证
    ↓
支付
    ↓
身份变更为自由游泳者
    ↓
次卡：闸机刷脸或扫码签到，自动划扣次数
月卡：不强制签到，可自愿记录游泳数据
```

注：首次购买次卡 / 月卡前，用户需完成实名认证、健康承诺书签署和免责协议电子签署。

### 6.7 退款流程
```
用户发起退款（学员课时套餐、体验课可退；次卡 / 月卡暂不可退）
    ↓
系统计算可退金额
    ↓
若涉及手续费，提示用户并需用户确认
    ↓
判断退款类型
    ├─ 标准退款（用户个人原因）→ 教练 24 小时内确认 → 管理员 3 个工作日内审批 → 原路退款
    └─ 争议退款 → 管理员直接介入处理，教练意见作为参考
      - 争议退款场景示例：教练未按约定上课、教学质量严重不符、场馆临时闭馆导致无法履约、双方对课时消耗存在异议、用户因突发伤病无法继续上课并提供有效证明等。
      - 争议退款处理时限：管理员需在 3 个工作日内给出处理结果；需用户补充材料的，以材料提交齐全后起算。
    ↓
通知用户
    ↓
若课时 / 余额清空，身份相应降级
    ↓
体验课退款成功后，系统自动移除「体验用户」标签
    ↓
退款到账：原路退回，预计 3 - 7 个工作日到账
```

### 6.8 教练请假处理流程
```
教练提交请假申请
    ↓
管理员审批通过
    ↓
系统自动检测请假时段的已预约课程
    ↓
系统自动取消课程并发送通知给相关学员
    ↓
教练填写取消原因或改约建议（可选）
    ↓
学员选择改约其他时间或保留课时
```

## 7. 数据与合规

### 7.1 数据安全
1. 用户手机号、邮箱、支付信息加密存储。
2. 敏感操作（支付、退款、修改价格）需二次确认。
3. 操作日志记录，支持审计。
4. 数据库定期备份。

### 7.2 隐私合规
1. 首次注册需用户同意隐私协议。
2. 明确告知数据用途，支持撤回授权。
3. 符合 GDPR、CCPA、国内《个人信息保护法》要求。
4. 未成年人信息需监护人授权。

### 7.3 健康与免责

1. **健康承诺**：首次购课、首次预约体验课、首次购买次卡 / 月卡前需电子签署健康承诺书；后续每次到馆签到或下水前需勾选「当日健康确认」（无心脏病、皮肤病、感冒发热等不适宜下水情况）。健康承诺书只需签署一次，每日健康确认为每次入馆前的例行确认。
2. **免责协议**：新学员首次购课或入场前电子签署免责协议，签署一次后长期有效，用户可在个人中心查看已签署协议。

## 8. 非功能性需求

### 8.1 性能
1. 小程序首页加载时间 < 2 秒。
2. 预约高峰期并发支持 1000 QPS。
3. 视频上传支持断点续传。

### 8.2 可用性
1. 系统可用性 99.9%。
2. 支付链路具备重试与对账机制。
3. 关键操作支持降级方案。

### 8.3 扩展性
1. 预留多场馆、多城市扩展能力。
2. 预留物联网硬件接入接口。
3. AI 模型可配置切换。
4. 首期只做微信小程序，服务端接口预留 App 复用能力。

### 8.4 多端一致性
1. 小程序与 App 数据互通。
2. 教练复杂操作建议在 Web 后台完成。

## 9. 已确认产品决策

以下问题已由产品方确认，作为后续设计与开发的依据。

| 序号 | 问题 | 决策 |
|------|------|------|
| 1 | 教练是否也可以同时具备学员或自由游泳者身份？ | 否。教练为独立角色，不叠加学员 / 自由游泳者身份。 |
| 2 | 一对多套餐最多支持几人？ | 最多 3 人，后台可配置。 |
| 3 | 教练收入是平台抽成还是固定课时费？ | 支持按场馆 / 按教练配置：平台抽成、固定课时费或混合模式；具体规则需结合市场调研确定。 |
| 4 | 退款时是否扣除手续费？ | 若涉及手续费，系统需明确提示用户，用户确认后再退款。 |
| 5 | 是否必须实名认证才能预约？ | 是。预约体验课、购买正课套餐、购买次卡 / 月卡前必须完成实名认证。 |
| 6 | AI 视频分析是否使用云端服务？ | 可能使用云端服务，按使用量计费；具体方案第三阶段确定。 |
| 7 | 是否首期只做微信小程序，还是同步做 App？ | 首期只做微信小程序，服务端预留 App 接口。 |
| 8 | 用户身份过期后，历史数据是否保留？ | 是。身份过期后历史数据保留。 |
| 9 | 预约释放时间周三 10:00 是否需要区分节假日？ | 后台可配置，节假日不营业时可提前释放下一周时段，并通过公告通知用户。 |
| 10 | 候补队列是否允许同时候补多个时段？ | 允许。但若其中一个候补成功，其他候补订单自动取消。 |
| 11 | 体验课购买后是否成为学员？ | 否。购买体验课后为「注册用户 + 体验用户标签」，购买正价套餐后才成为学员。 |
| 12 | 购买正价套餐时是否选择教练？ | 是。购买正价套餐时即选择并绑定教练，不支持通用套餐。 |
| 13 | 一对多拼课成功后有人退出怎么处理？ | 采用弹性规则，默认由教练决定是否继续开课或改为一对一补课；系统提供人数不足自动取消的默认选项。 |
| 14 | 自由游泳者如何签到？ | 次卡通过闸机刷脸或扫码签到自动划扣；月卡不强制签到。 |
| 15 | 固定搭档是否必须注册？ | 是。固定搭档必须注册并实名，由教练或管理员绑定关系。 |
| 16 | 次卡 / 月卡是否支持退款？ | 首期不支持退款，后续考虑支持转让。 |
| 17 | 家长 / 未成年账号如何处理？ | 首期不单独设计家长账号。教练可在自己维护的学员信息中标记未成年及监护人联系方式，由家长使用学员账号预约和评价。 |
| 18 | 首页配置是否需要审核？ | 不需要审核，但支持预览机制，配置后直接生效。 |
| 19 | 订单支付后是否需要管理员确认？ | 否。支付成功后系统自动确认订单，管理员只处理异常和退款。 |
| 20 | 教练请假后是否自动通知学员？ | 是。系统自动取消课程并发送通知给相关学员。 |
| 21 | 24 小时内取消申请教练未处理怎么办？ | 默认视为拒绝取消。 |
| 22 | 满员时段用户可选择候补还是关注？ | 两者都支持，用户根据偏好选择。 |
| 23 | 体验课是否支持退款？ | 支持。 |
| 24 | 健康承诺 / 免责协议何时签署？ | 首次购课、首次预约体验课、首次购买次卡 / 月卡前签署健康承诺书与免责协议；健康承诺书签署一次长期有效，每次入馆前需进行当日健康确认。 |
| 25 | 教练评价内容是否公开？ | 评分公开，具体评价内容后台可配置。 |
| 26 | 体验课是否有有效期？ | 有。自购买之日起 30 天内有效（后台可配置），过期未使用自动失效。 |
| 27 | 正价课学员如何签到？ | 可在小程序内点击「一键签到」，或经前台扫码 / 闸机刷脸登记；签到为自愿行为，仅通知教练已到场，不强制、不扣课时；课程结束后由教练确认上课并扣课时。 |
| 28 | 教练审批订单的超时规则？ | 教练需在 24 小时内处理，超时未处理系统自动取消订单并通知用户。 |
| 29 | 争议退款处理时限？ | 管理员需在 3 个工作日内给出处理结果。 |
| 30 | 学员上传视频的可见范围？ | 默认仅学员本人及关联教练可见，学员可选择是否对其他人公开。 |
| 31 | 固定搭档如何互相通知？ | 一方签到 / 入场后，通过微信订阅消息 / 服务通知通知另一方；未送达时通过短信或应用内消息补发。 |
| 32 | 哪些场景使用短信通知？ | 支付成功、退款到账、课程取消、场馆临时闭馆、卡券到期提醒、账号安全操作等优先级高或微信订阅消息未送达的场景。 |
| 33 | 体验课学员如何签到？ | 可在小程序内点击「一键签到」，或经前台扫码 / 闸机刷脸登记；签到为自愿行为，仅通知教练已到场，不强制、不扣课时；体验课结束后由教练确认上课。 |
| 34 | 学员未到场（旷课）如何处理？ | 教练可标记「学员未到课」，系统释放预占课时，该节课不扣课时；如需扣课时由教练与学员协商后管理员手动处理。 |
| 35 | 教练确认上课的时限？ | 课程结束后 24 小时内，超时未确认系统自动扣减该节课时并通知双方。 |
| 36 | 教练「锁课」保留多久？ | 24 小时，超时未确认自动释放。 |
| 37 | 24 小时内取消审批通过后是否释放课时？ | 是，审批通过后立即释放预占课时。 |
| 38 | 周期性预约能否取消？ | 开课前 24 小时外可取消单次或整个周期；开课前 24 小时内原则上不可取消，特殊情况由教练与学员协商。 |
| 39 | 固定搭档能否解除 / 更换？ | 能。任一学员可在个人中心申请解除，解除后不影响历史订单；更换需先解除原关系，再重新绑定新搭档。 |
| 40 | 多套餐课时消耗顺序？ | 默认按「有效期近的优先、有效期相同按购买时间先后（FIFO）」扣减；管理员可在后台调整优先级。 |
| 41 | 评价时间窗口与教练回复规则？ | 学员课程结束后 7 天内可评价，逾期不可补评；教练可公开回复，回复后学员不可修改评价。 |
| 42 | 体验课能否更换教练？ | 不能。需先退款，再重新购买目标教练的体验课。 |
| 43 | 体验课退款后是否移除标签？ | 是。退款成功后系统自动移除「体验用户」标签，恢复为普通注册用户。 |
| 44 | 学员能否更换绑定教练？ | 首期不支持直接更换。需退掉剩余未上课时，再重新购买新教练套餐。 |
| 45 | 自定义套餐用户拒绝教练修改方案怎么办？ | 订单自动取消。 |
| 46 | 标准退款处理时限？ | 教练需在 24 小时内确认，管理员需在 3 个工作日内审批。 |
| 47 | 退款到账时效？ | 原路退回，预计 3 - 7 个工作日到账。 |
| 48 | 教练离职 / 取消入驻后学员课时怎么处理？ | 系统自动标记为待处理，管理员可安排其他教练承接剩余课时，或按退款流程处理。 |

## Context

本 US 实现管理后台的教练排班查看/修改与请假审批。核心约束：请假通过时必须自动取消请假时段内已预约但未上课的课程，并释放课时预占；排班修改需校验时间冲突。

## Goals / Non-Goals

**Goals:**

- 管理员可查看所有教练排班
- 管理员可新增、修改、删除排班时段
- 管理员可通过或拒绝教练请假申请
- 请假通过后自动取消课程并通知学员

**Non-Goals:**

- 不实现教练端排班功能（由 US-014 实现）
- 不实现教练端请假提交（由 US-036 实现）
- 不实现复杂的排班模板与复制功能

## Decisions

1. **复用 US-014 的 `schedule_slot` 与 US-036 的 `coach_leave_request`**
   - 理由：避免重复建表，统一管理排班与请假数据
   - 补充：增加 `schedule_slot.is_admin_created` 字段区分管理员创建

2. **请假审批同步取消课程**
   - 理由：MVP 数据量可控，同步处理可立即反馈结果并保证数据一致性
   - 替代方案：异步任务队列 —— rejected，增加复杂度，MVP 暂不引入

3. **时间冲突基于同一教练的 `(start_time, end_time)` 区间重叠判断**
   - 理由：同一教练不能在同一时间有多个可约时段
   - 边界：跨天时段按天分别校验

4. **删除有预约的排班时段需二次确认后自动取消课程**
   - 理由：防止误删导致学员课程被取消，同时提供便捷操作

## Risks / Trade-offs

- **[Risk]** 请假时段内课程较多时，同步取消耗时较长 → **Mitigation**: 100 节课以内同步处理，超过则分批并在响应中返回处理进度
- **[Risk]** 管理员修改排班后，学员已预约的时段被调整 → **Mitigation**: 已存在 booking 的时段禁止直接修改时间，只能删除（删除时取消课程）
- **[Risk]** 通知服务失败导致学员未收到取消通知 → **Mitigation**: 通知调用异步化，失败进入重试队列

## Migration Plan

1. 执行 Knex migration 为 `schedule_slot` 增加 `is_admin_created` 字段
2. 部署后端接口与管理端页面
3. 回滚：删除新增字段并回退代码

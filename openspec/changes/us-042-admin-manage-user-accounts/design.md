## Context

本 US 实现管理后台的用户账号管理功能，包括用户列表查询、修改手机号/邮箱、配置角色权限、封禁/解封账号。所有敏感操作需记录审计日志。RBAC 权限细化到操作级：`super_admin` 可操作所有账号，`admin` 仅可操作非管理员账号。

## Goals / Non-Goals

**Goals:**
- 管理员可按身份、注册时间筛选用户
- 管理员可查看用户详情
- 管理员可修改手机号、修改邮箱
- 管理员可配置用户角色权限
- 管理员可封禁/解封用户账号
- `super_admin` 与 `admin` 的 RBAC 权限按操作级细分

**Non-Goals:**

- 不实现用户自助修改资料（由 US-005 实现）
- 不实现账号注销（由 US-007 实现）
- 不实现复杂的组织架构权限

## Decisions

1. **用户表增加 `version` 乐观锁字段**
   - 理由：防止并发修改同一用户资料导致数据覆盖
   - 替代方案：数据库行锁 —— rejected，乐观锁对读多写少场景更友好

2. **角色通过 `user_role` 关联表配置**
   - 理由：支持多对多关系，一个用户可拥有多个角色
   - 替代方案：user 表增加 `role` 字段 —— rejected，无法支持多角色

3. **手机号/邮箱唯一性校验后置写入前加唯一索引兜底**
   - 理由：先查询再写入可能存在并发竞态，唯一索引保证最终一致性

4. **`user.status` 增加封禁状态 2**
   - 理由：支持管理员封禁/解封账号，与注销（1）区分

## RBAC Permission Matrix

| 权限码 | 说明 |
|--------|------|
| `USER:READ` | 查看用户列表/详情 |
| `USER:WRITE` | 修改手机号/邮箱 |
| `USER:ROLE_ASSIGN` | 配置角色权限 |
| `USER:BAN` | 封禁/解封账号 |

| 操作 | `super_admin` | `admin` | 约束 |
|------|---------------|---------|------|
| 查看用户列表/详情 | ✅ | ✅ | 均需 `USER:READ` |
| 修改手机号/邮箱 | ✅ | ✅（仅限非管理员用户） | 均需 `USER:WRITE`；admin 不可改 super_admin |
| 配置角色权限 | ✅ | ✅（不可授予 super_admin） | 均需 `USER:ROLE_ASSIGN` |
| 封禁/解封账号 | ✅ | ✅（仅限非管理员用户） | 均需 `USER:BAN` |
| 删除账号 | ❌ | ❌ | 由 US-007 用户自助注销 |

## Risks / Trade-offs

- **[Risk]** 批量导出大量用户数据造成性能压力 → **Mitigation**: 导出异步化，限制单次 10000 条
- **[Risk]** 修改手机号后原手机号仍被缓存 → **Mitigation**: 更新成功后失效用户详情与登录缓存

## Migration Plan

1. 执行 Knex migration 确保 `user` 表存在 `version` 字段
2. 确认 `user.phone` 与 `user.email` 已设置唯一索引
3. 部署后端接口与管理端页面
4. 回滚：删除新增字段并回退代码

> **OpenSpec Proposal | 映射自 `docs/stories/US-006-用户-手机号验证码登录/user-story.md` §1-§5**

## 背景与目标

提供除微信授权外的手机号验证码登录方式。用户输入手机号并验证短信验证码后即可登录；若手机号未注册，首次验证码登录成功时自动创建账号，并进入 US-005 完善个人资料。登录时必须校验用户已勾选《用户须知》和《隐私协议》。登录成功后复用 US-004 的登录态管理机制：前端存储 token，后续请求携带 token，后端校验登录态。

## 范围

- 手机号验证码发送（登录场景）
- 手机号验证码登录（已注册账号直接登录）
- 未注册手机号首次验证码登录自动注册
- 登录成功后按 `profile_completed` 分流
- 登录时校验《用户须知》和《隐私协议》勾选状态
- 登录态管理：前端存储 `access_token`/`refresh_token`，请求携带 `Authorization: Bearer {access_token}`，后端校验 token 有效性

## 关键决策

- 不设置密码，登录仅用手机号 + 短信验证码
- 未注册手机号首次验证码登录即视为注册
- 与 US-004 并列为注册入口，共享 user 表与 JWT 签发逻辑
- 登录时前后端双重校验《用户须知》和《隐私协议》勾选
- 登录态管理规则与 US-004 完全一致：前端本地存储 token、请求头携带、token 过期自动刷新

## 影响能力

- 2.1 注册登录

- 后续：US-005（完善个人资料）、US-042（管理员管理用户账号）、US-052（用户退出登录）
